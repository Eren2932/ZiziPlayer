## ZiziPlayer 6.80.0 — нижняя карточка текстов

**Полный ZIP исходников, не APK.** `versionCode 165`. Основа — публичный мобильный `ZiziPlayer-v6.79.0.zip` (`versionCode 164`), скачанный 02.10.2026. Android-сборка и отрисовка на устройстве в этой поставке не выполнены.

### Что изменено

Нижняя карточка больше не является одним `Text` из трёх склеенных строк. Новый `LyricsPreviewCard` использует виртуализированный список с текущей строкой на постоянной вертикальной позиции. Активная строка светлая и крупнее, окружающие — непрозрачным оттенком из палитры текстов. Переход соседних строк двигает список за 420 мс, цвет меняется за 240 мс; масштаб меняется пружиной с damping 0.9 / stiffness 260. Большой переход по времени не прокручивает через десятки ненужных строк, а сразу показывает нужный фрагмент.

Фон — **тот же `LyricsSurfaceTheme` / `lyricsPalette` / `LyricsColorMath`, что и у полноэкранных текстов**. Все семь остановок общего `p.background` нормализованы на собственную высоту карточки. Нет второй выборки цвета обложки, одноцветного `p.chip`, нового затемнения или непрерывного декоративного таймера. Код расчёта цветов большого окна не изменён. Маска `DstIn` затухания изолирована в offscreen-слое области текста: фон, заголовок и кнопка не исчезают вместе со строками.

Настройка сверху в полном окне — это сдвиг тайминга, не скорость аудио. Карточка, подпись под обложкой и полный экран используют существующие `LyricsUiState.advanceMs` и `rememberLyricsCursor`. Положительное значение показывает строку раньше, отрицательное — позже; сохранение индивидуально для трека осталось в `LyricsRepository`. Дополнительного таймера или отдельного хранилища нет. Реальные пословные метки enhanced LRC учитываются; для обычного LRC пословная синхронизация не выдумывается.

При повторном входе курсор получает начальное значение из текущего `vm.progress.value`, а список создаётся сразу у активного индекса. Отсутствие позиции, чужой трек, неподходящая длительность и непроверенный текст не выделяются как активное пение. Plain-текст остаётся статическим предпросмотром; при отсутствии текста/инструментале карточки нет. Повторяющиеся фразы различаются по индексу, а не по содержимому.

**Текст под обложкой теперь не кликабелен.** У `InlineLyrics` / `InlineLyricsCaption` нет callback открытия, `clickable`, обработчика указателя или click-semantics. Анимация самой подписи сохранена. Открыть большой текст можно через карточку/кнопку «Показать текст» и прежнее меню трека. Нажатие на кнопку не должно дублироваться родительской карточкой — на это добавлен Android-тест.

### Геометрия и границы точности

Референс — `Screenshot_20261002_054405.jpg`, исходные 1080×2400; второй снимок использован как текущее состояние. Геометрия привязана к ширине, а не к пикселям одного телефона. Основные замеры и коэффициенты:

| Элемент | Опорное значение при ширине 1080 | При доступной ширине 384 dp, fontScale=1 |
|---|---:|---:|
| Внешние поля | 45 px | 16 dp |
| Ширина карточки | 990 px | 352 dp |
| Высота карточки | 1156 px | 411.02 dp |
| Скругление | около 48 px | 17.07 dp |
| Внутреннее поле | около 46 px | 16.36 dp |
| Область строк | 772 px | 274.49 dp |
| Шрифт / строка активного текста | 68 / 84 опорных единиц | 24.18 / 29.87 sp |
| Видимая высота кнопки | 92 px | 32.71 dp |
| Реальная зона нажатия кнопки | не измеряется по картинке | не меньше 48 dp |

Дополнительная зона нажатия компенсирована соседними отступами и не увеличивает обычную видимую высоту карточки. На планшете/в landscape опорная ширина ограничена 480 dp, карточка центрируется. Увеличение системного шрифта не запрещено: область строк растёт по реальному `sp → dp`, в том числе с нелинейным масштабированием Android. Заголовок может переноситься. Одна очень длинная LRC-строка в мини-карточке ограничена четырьмя визуальными строками; весь текст доступен в большом окне.

Вертикальный якорь активной строки — 37.5% области строк; затухание — первые 12% и последние 14%. Эти параметры, межстрочные интервалы и параметры движения — инженерная настройка по одному статичному кадру, **не восстановленная по видео анимация Spotify**. Используется штатный комплект Roboto проекта, не шрифт Spotify. Попиксельное совпадение и поведение Android-рендера ещё требуют проверки на телефоне; синтетический макет не выдаётся за скриншот приложения.

### Проверки

**110 из 110 зарегистрированных локальных наборов прошли** в трёх пакетных прогонах. Отдельно прошли 8 фикстур самопроверки анализаторов, четыре проверки исходников и синтаксис shell-скрипта Android-приёмки. Новый Java-набор выполняет **7131 утверждение** на production-коде геометрии и `LrcTimeline`: пропорции, диапазоны размеров, зона текущей строки, маска, выбор анимации, разные знаки сдвига и границы реальных таймкодов. Семь новых интеграционных проверок проверяют связь компонентов по исходникам; это не компиляция Kotlin.

Старые тесты изменены только там, где поменялся контракт: предупреждение «версия не проверена» перенесено в отдельный компонент и продолжает проверяться; разрешённых точек открытия полного текста стало две вместо трёх. Проверки не отключались.

Последовательный `python tools/check_selftest.py` достиг лимита исполнения the Computer (110 с; код 124). Его частичный лог сохранён и **не помечен успешным**. Все 110 составляющих наборов независимо завершены с кодом 0 пакетным runner; 8 фикстур дополнительно выполнены отдельно. На GitHub CI сценарий продолжает запускаться обычным способом.

Добавлены шесть настоящих Compose-тестов карточки. Вместе с тремя имеющимися тестами общей палитры runner ожидает **ровно 9** успешных Android-тестов; пропуск, неполный XML или падение считаются ошибкой. **Они пока не запускались.** Нет Android SDK, Gradle и эмулятора; APK здесь не собран, JVM/Compose-сборка всего приложения также не подтверждена. Логи и структурированные результаты находятся в `verification/v6.80.0/`.

### Как применить

Загрузить **один** `ZiziPlayer-v6.80.0.zip` в корень репозитория. Существующий корневой `.github/workflows/build.yml` выбирает полный мобильный проект с максимальным `versionCode`, поэтому новый пакет 165 будет выбран вместо 164. Менять корневой workflow, desktop/current.json, серверы, секреты или данные приложения для этой доработки не требуется. Изменённый `check_selftest.py` внутри ZIP подключает новые локальные проверки к существующему CI.

Обычный CI выполняет unit tests и сборку release; выполнение новых Compose-тестов само по себе из этого не следует. Для отдельной приёмки на подготовленном Android-окружении:

````bash
gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest
bash tools/run_lyrics_preview_ui_6800.sh
````

Нужны Gradle 8.11.1, JDK 17+, Android SDK 36 и запущенный эмулятор/телефон. Для проверки промежуточных кадров Android animator duration scale должен быть 1×. Gradle wrapper в исходной базе отсутствует, поэтому команды используют установленный `gradle`.

После зелёной сборки установить APK с прежней подписью поверх приложения, без удаления и очистки данных. Если локальная сборка использует debug-ключ вместо ключа релиза, поверх релизной установки она не встанет — это поведение основы, не изменение этой версии.

### Что проверить на телефоне

Сверить карточку на URANIUM, затем на красной, синей и нейтральной обложках: оттенок и направление градиента должны совпадать с полным окном. Проверить обычный ход, паузу, перемотку назад/вперёд, последние строки, повтор трека и повторяющиеся фразы.

В полном окне поставить +1.5 с, вернуться в карточку, затем −1.5 с и повторить; после другого трека и перезапуска проверить восстановление сохранённого сдвига. Убедиться, что подпись под обложкой не открывает текст ни нажатием, ни через TalkBack. Кнопка карточки и пункт меню должны открывать его ровно один раз.

Проверить большой системный шрифт, длинный перенос, смену ширины, plain-текст, инструментал и отсутствие обложки. Прокрутка по карточке должна двигать внешний плеер, а не перехватываться внутренним списком.

### Область изменений

Только мобильный UI текстов, начальное состояние общего курсора, версия, тесты и документация. Аудиотракт Media3, поиск, серверы, Room, аккаунты, существующие цвета полноэкранного окна и сохранение настроек не менялись. `LYRICS_PREVIEW_v6.80.0.patch` и `CHANGED_FILES_v6.80.0.json` дают точный diff и хеши; исторические документы прошлых релизов сохранены.
