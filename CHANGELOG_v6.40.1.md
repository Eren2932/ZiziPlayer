# ZiziPlayer 6.40.1 — вход в скрытые папки и возврат громкости

Дата: 9 сентября 2026. Основа: **ZiziPlayer-v6.40.0.zip** из публичного
Eren2932/ZiziPlayer (снимок main, полученный в этом диалоге).
`versionName = "6.40.1"`, `versionCode = 83`. Десктоп не менялся.

**Поставляется полный исходный проект, не APK.** Офлайн-проверки пройдены;
Kotlin/Compose, Android-сборка, рендер, биометрия, недавние приложения и поведение
Telegram на телефоне здесь не проверены. В the Computer доступны JVM-проверки,
но нет Gradle, Kotlin compiler, Android SDK и adb. Для установки нужен APK из CI.

## Скрытые папки: вход через шторку

Из верхней панели полностью удалены кнопка замка, её импорты и дополнительная
компоновка. Шторка доступна в общей коллекции и в разделе «Папки», когда есть
скрытые папки. В поиске, внутри папки, в треках и во время выделения она не
перехватывает жесты. Долгое нажатие на локальную папку, множественный выбор,
«Все» и «Скрыть папки» сохранены. Сетевые группы не превращены в файловый сейф.

Шторка использует только остаток прокрутки вниз после достижения начала списка.
Сопротивление 0.55, порог 72 dp, ограниченная высота и один тактильный отклик за
жест сохранены. После порога написано «Отпусти для открытия».

Открытие теперь фиксируется по отпусканию последнего пальца, а не из
`onPreFling`: это убирает зависимость открытия от завершающего события прокрутки.
Пустая коллекция и коллекция с одной карточкой остаются LazyColumn в обоих видах.
Короткий свайп, возврат ниже порога и отмена жеста не открывают раздел; повторный
release не создаёт второе окно. Вход при уже открытой авторизации игнорируется.
Для TalkBack есть действие на поверхности, без видимой кнопки-замка.

Если раздел закрыт, жест открывает окно проверки ключа, а не список папок.
Только успешная проверка открывает список. В уже разблокированной сессии жест
возвращает в список без повторной проверки. Ручное действие «Заблокировать»
внутри списка и автоблокировка при уходе в фон сохранены.

## PIN и биометрия

Вместо текстового поля с системной клавиатурой добавлен собственный компактный
диалог: точки ввода, цифровая клавиатура 0–9, удаление последней цифры, кнопка
подтверждения и отмена. Высота ограничена экраном, длинное содержимое прокручивается.
PIN — **ключ Zizi**, а не PIN телефона; приложение не имитирует проверку чужого
системного кода. Поддерживаются прежние 6–12 цифр. Графический ключ сохранён для
совместимости с уже настроенной защитой и как вариант при первой настройке.

Осталась одна кнопка «Биометрия». На API 30+ запрашивается только сильная
биометрия, без DEVICE_CREDENTIAL fallback; отрицательная кнопка возвращает к
ключу Zizi. Отдельная кнопка «Код блокировки телефона» и её ActivityResult-маршрут
удалены. API 28–29 используют framework BiometricPrompt с его возможностями;
на API 28 наличие сканера предварительно проверяется по аппаратной возможности,
а отсутствие зарегистрированного отпечатка обрабатывается как ошибка. На API
26–27 в этом проекте остаётся PIN/рисунок Zizi, без отдельной биометрической кнопки.
Новые зависимости не добавлялись.

Ошибочный отпечаток, ошибка, отмена и поздний callback не разблокируют папки.
Во время системного запроса параллельная проверка PIN отключена. При уходе в фон
окно закрывается, незавершённый ввод очищается, biometric CancellationSignal
отменяется; callback проверяет активность экрана и поколение запроса. При пяти
ошибках ключа действует прежний lockout, теперь его оставшееся время видно с
обновлением раз в секунду. Проверка PBKDF2 и сохранённые ключи не менялись.

## Скриншоты и недавние приложения

**По прямому уточнению пользователя защита нужна только во время ввода ключа.**
Глобальное включение FLAG_SECURE по факту существования скрытых папок удалено из
MainActivity. SecureOn остался исключительно у окна VaultAuthDialog.

| Экран | Политика приложения |
| --- | --- |
| Плеер, поиск, настройки, эквалайзер | Скриншоты и обычное превью разрешены |
| Обычные папки | Скриншоты и обычное превью разрешены |
| Открытые скрытые папки и их содержимое | Скриншоты и обычное превью разрешены |
| Настройка/ввод PIN или рисунка | Только это окно защищено SecureOn |

Внешний вид системной биометрии и её защита определяются Android. Конкретный
вид карточки в недавних зависит от прошивки; старый закэшированный пустой снимок
может обновиться после нового посещения приложения. Сам Zizi больше не включает
запрет для всего Activity. Разрешение снимков открытых скрытых папок — осознанный
выбор пользователя, не обещание скрыть их во всех системных превью.

## Приглушение и восстановление громкости

6.40.0 возвращала громкость только на AUDIOFOCUS_GAIN. Мессенджер может закончить
воспроизведение, но удерживать этот фокус до закрытия своей панели.

Теперь на время CAN_DUCK-периода подключён публичный AudioPlaybackCallback с
проверкой текущих activePlaybackConfigurations. После наблюдавшегося чужого
воспроизведения, когда остаётся только кандидат собственного MEDIA/MUSIC-плеера,
запускается одна повторная проверка через 240 мс. Если отсутствие конкурирующего
воспроизведения подтверждается, громкость плавно возвращается за 450 мс **без
нового AUDIOFOCUS_GAIN, перезапуска трека или закрытия панели мессенджера**.
Ориентир — около 690 мс плюс задержка системного callback, не жёсткая гарантия
real-time. При возобновлении чужого воспроизведения в том же периоде фокуса музыка
снова приглушается до 8% за 180 мс. Короткие промежутки между сообщениями не дают
немедленного скачка громкости. Восстановление не запускает остановленную музыку.

Наблюдатель остаётся до возврата фокуса/отмены воспроизведения, но постоянного
опроса по таймеру нет: callback и одна отложенная проверка. При паузе пользователя,
stop, release, постоянной потере или TRANSIENT-потере фокуса наблюдение и таймер
снимаются. Системный ползунок громкости, DSP, нормализация и сервер не менялись.
Обычная политика паузы для LOSS/LOSS_TRANSIENT сохранена.

### Важный предел этой доработки

Это наблюдение за **активностью плееров**, не запись чужого звука и не анализ
тишины в аудиодорожке. Публичный API анонимизирует UID/session ID; здесь
используется консервативный подсчёт с учётом одного собственного MUSIC-плеера,
а не достоверная идентификация Telegram. Остановка/пауза, которую Android видит,
может быть обработана без ожидания фокуса. Если Telegram продолжает держать
аудиоплеер активным и выдаёт нулевые отсчёты, либо прошивка не показывает нужную
активность, такой случай **не гарантированно исправлен** этим API.

Нет микрофона, MediaProjection, доступа к уведомлениям, Accessibility Service,
скрытых системных API или попыток принудительно отобрать фокус. Неизвестный
снимок, отсутствие собственного кандидата, буферизация и режим звонка не
трактуются как разрешение поднять громкость. Если чужой плеер вообще не был виден,
нет небезопасного таймаута «через N секунд включить громко»: остаётся fallback
на обычный AUDIOFOCUS_GAIN. Если приложение не запросило фокус вообще, эта
CAN_DUCK-доработка не запускается.

## Проверки и область изменений

Прошли 19 команд офлайн-регрессии, включая существующий preflight. Новые проверки
подключены к tools/check_selftest.py, который уже вызывается корневым Android CI.
14 новых source-contract тестов проверяют связи, а 34 048 исполняемых утверждений
работают с production Java-классами жеста и восстановления громкости. Прежние
проверки, включая 21 028 утверждений правил 6.40.0, также прошли. Большие числа
включают циклы по границам параметров — это не столько независимых сценариев и
не доказательство поведения Android. Семь внесённых в временные копии дефектов
отклонены проверками. Рабочие исходники этими контролями не мутировались.

Сервер, DSP, темы/обложки, схема Room, зависимости, AndroidManifest, конфигурация
подписи и workflow сохранены. Изменения старых контрактов 6.40.0 относятся только
к намеренно удалённой глобальной защите, убранному credential-маршруту и новому
способу завершения жеста. Ключи и база не сбрасываются. Скрытие папок по-прежнему
не шифрует файлы и использует существующую идентичность группы по имени.

Подробности: verification/v6.40.1/, CHANGE_MANIFEST_v6.40.1.json.
Приёмка на устройстве обязательна: жесты, Android UI, биометрия, скриншоты,
обычная и удерживаемая фокусом пауза Telegram, звонки, Bluetooth, фон.

## Как получить APK

Загрузить **ZiziPlayer-v6.40.1.zip в корень GitHub, не распаковывая**. Существующий
Android workflow выбирает полный проект с максимальным versionCode; теперь 83.
Старый 6.40.0.zip можно оставить. Десктопный current.json не трогать. Сервер не
обновлять. Дождаться зелёных Kotlin/JVM и APK/R8 шагов CI, затем проверить APK
на устройстве. Подпись должна быть прежней для обновления поверх установленной
версии. Не очищать данные приложения ради установки и не удалять старую версию.
Репозиторий, GitHub Releases и CI из этого диалога не изменялись и не запускались.
