# ZiziPlayer 6.37.0 + zizi_catalog 1.6

Релиз чинит не «ещё пару мелочей», а причину, по которой 6.36.0 не играл: **сопоставление витрины
со звуком стояло на пути воспроизведения и не успевало за таймаут клиента**. Витрина Deezer в
6.36.0 завелась правильно — это видно и по названиям, и по обложке `Le Grand Bleu` на скриншоте.
Дальше начиналась вторая половина работы, которой не было.

## Что было доказано замерами, а не предположено

| Замер | Ответ | Что из него следует |
|---|---|---|
| `/catalog/health` | `{"ok":true,...,"matches_cached":1}` — без `images_cached` | На сервере лежит **старый** `zizi_catalog.py`. `/img` не существует, обложки идут мимо сервера |
| `/match/deezer?id=3135556` | `vid`, `score:95`, `by:"Daft Punk"` | Сопоставление работает и находит официальное аудио лейбла |
| `/catalog/search?q=phonk` | три записи Deezer с ISRC и обложками | Витрина работает |
| `/stream?id=JhulBGMA7G4` | играет целиком, 5:37, **без VPN** | Тракт звука исправен целиком |
| `matches_cached` после тапа в приложении | **осталось 2** | Приложение до `/match` не доходит **ни разу**. Виноват клиент, не сервер |

## Клиент

### 1. Долгий клиент для `/match/deezer` (`ZiziHttp.slowClient`)

`ZiziHttp.client` живёт с `readTimeout(20)` — правильное значение для запроса метаданных. Но
`/match/deezer` это не запрос метаданных, это **работа**: до трёх поисковых заходов yt-dlp на
одноядерном VPS. Сервер доводил охоту до конца и клал результат в SQLite, телефон к этому моменту
уже отменил запрос → `OFFLINE` → `IOException` в `StreamResolver` → авто-скип. Ровно то, что было
видно глазами: «трек встал на 0:00» и «сам листает дальше».

Теперь этот один запрос идёт через `slowClient` (read 75 с, call 90 с), пул соединений общий.

### 2. Прогрев ожил (`SearchViewModel.warmTop`)

```kotlin
// было, с 6.30.0 и по 6.36.0 включительно
.filter { it.provider == InnertubeCatalog.ID && it.remoteId.isNotBlank() }
```

С 6.30.0 наверху стоит микс: у **всех** результатов `provider == "mix"`, а настоящий источник
уехал в префикс `remoteId` (`dz:3135556`, `yt:JhulB...`). Фильтр не пропускал ни одной строки —
прогрев, написанный в 6.22.0, три релиза молча не делал ничего. Теперь префикс разбирается:
`yt:` уходит в `ZiziResolve.prefetch`, `dz:` — в новый `DeezerCatalog.warm`, то есть сервер
сопоставляет первые три трека, **пока человек читает список**.

### 3. `OFFLINE` больше не обрывает перебор каталогов (`CatalogRegistry.withFallback`)

`OFFLINE` означает «не ответил ЭТОТ источник», а не «сети нет». Пока он считался приговором, один
зависший без VPN запрос к Innertube убивал весь поиск — при живой витрине, отвечающей с того же
телефона за триста миллисекунд. `UNAVAILABLE` и `METERED_BLOCKED` приговором остались.

## Сервер, `zizi_catalog` 1.6

### 4. Три поисковых захода — параллельно

Было последовательно: `"isrc"` → `artist - Topic title` → `artist title`, каждый до 45 секунд.
Стало: одновременно, таймаут захода 25 с. Холодное сопоставление — это теперь самый долгий заход,
а не их сумма.

### 5. Пометки версий («slowed», «sped up», «remix») учитываются симметрично

Главная причина `no confident match` на целом жанре. Старое правило штрафовало кандидата за слово
`slowed` **всегда**, −25. Половина живой выдачи Deezer — записи, у которых пометка стоит в самом
названии: `BACHI BACHI (Slowed + Reverb)`, `Verão Flow (Super Slowed)`. Для них правильный ролик
на YouTube тоже замедленный, то есть сервер штрафовал именно то, что искал, и добивал штрафом за
длительность (замедленная версия длиннее оригинала).

Теперь сравниваются наборы пометок запроса и кандидата: совпали — плюс, разошлись — минус. Для
помеченных записей окно длительности шире (±25 с вместо ±5), потому что у Deezer и YouTube это
физически разные мастер-файлы. Проверено на живых примерах: правильная замедленная версия
получает 102 очка против 75 у оригинала, а «1 HOUR PHONK MIX» — минус тридцать.

### 6. Порог уверенности и отрицательный кэш

Порог опущен с `20` до `−5`: лучший найденный кандидат теперь играет, даже если он не идеален —
человеку нужнее «играет похожее», чем «трек молча скипнулся». Флаг `confident` в ответе честно
говорит, какой это случай.

Промахи запоминаются на 6 часов в таблицу `miss`. До 1.6 «не нашли» не хранилось нигде, и каждый
повторный тап по такому треку заново запускал три процесса yt-dlp.

### 7. `/match/warm?ids=a,b,c`

Отвечает немедленно, работает в фоне (два воркера, дедупликация по пятиминутному окну, не больше
пяти id за раз). Это адрес, который зовёт пункт 2.

### 8. `/catalog/health` теперь называет версию

```json
{"ok":true,"version":"1.6","spotify":false,"deezer":true,
 "matches_cached":N,"misses_cached":M,"images_cached":K}
```

Без поля `version` нельзя отличить «файл залит» от «сервис не перезапущен» — неопределённость,
которая стоила нам целого релиза.

## Порядок выкатки — сервер ПЕРВЫМ

Клиент 6.37.0 без сервера 1.6 будет работать (`/match/warm` вернёт 404, прогрев промолчит), но
смысла в нём половина: обложки останутся серыми, а фонк — несопоставимым.

```bash
scp server/zizi_catalog.py root@147.45.166.244:/opt/zizi/zizi_catalog.py
ssh root@147.45.166.244 'mkdir -p /opt/zizi/img && systemctl restart zizi-resolver'
curl -s 'http://147.45.166.244:8080/catalog/health'   # ждём "version":"1.6"
```

Пока в health нет `"version":"1.6"` — ставить APK бессмысленно.

## Проверка, что всё сошлось

1. Без VPN, поиск `phonk` → тапнуть третий трек. Старт до нескольких секунд, дальше играет.
2. Сразу после — `/catalog/health`: `matches_cached` вырос **больше чем на один** (сработал
   прогрев верхних трёх, а не только тапнутого).
3. Обложки в списке цветные, `images_cached` растёт.
4. `Daft Punk Instant Crush` → чистое название, альбом `Random Access Memories`.
