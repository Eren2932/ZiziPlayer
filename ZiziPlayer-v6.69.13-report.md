# ZiziPlayer 6.69.13 — исправление сужения контура после контакта

27.09.2026. Версия **6.69.13**, Android versionCode **138**. База — сохранённые исходники **6.69.12 / 137**; production-геометрия сверена побайтно с выданным ZIP 6.69.12.

**Полный ZIP исходников, не APK. Java-геометрия скомпилирована и проверена локально. Android/Gradle-сборка, новые instrumentation-тесты и повтор на iQOO Neo 10 Global / Android 16 здесь НЕ выполнялись.**

## Что действительно найдено

Предыдущая правка ограничивала только функцию ширины шейки `waist(u)`. Но на тот же параметр была завязана ещё одна деформация: угол `psi` поворачивал управляющие точки обеих кривых на 90° в пределах первых 0,5 радиуса ширины шейки. Боковые части соединения при этом расширялись, затем втягивались, затем снова расширялись. При микродвижениях получалась многократно повторяемая смена толщины, хотя сама `waist(u)` оставалась монотонной. Это воспроизведено на production Java из ZIP 6.69.12, а не выведено только из описания пользователя.

Двух одновременно рисуемых эффектов или двух экземпляров обложки в проверенном renderer нет. До контакта рисуется отдельная капля, после контакта — объединённый контур. Эти две фазы необходимы для реального разрыва/соединения, переключатель `joined` не удалён. Однако в объединение маски действительно подавались **два почти совпадающих описания тела обложки**: `RoundRect` renderer и круговые дуги в `flesh`. Это лишняя сложность для булевой операции над касающимися кривыми. Связь именно этого механизма с GPU-артефактом справа на iQOO без теста телефона не доказана.

## Изменения

В `CameraMorphGeometry.java` удалён глобальный поворот управляющих точек. Осталось локальное C1-закругление стыка через подразделение кривых де Кастельжо; при первом касании область закругления стремится к нулю. Его раскрытие распределено на ширину одного диаметра камеры вместо четверти диаметра. Устранён дополнительный узкий участок чрезмерной чувствительности.

`flesh` в соединённой фазе теперь закрывается хордой **внутри** тела обложки, как и в раздельной фазе. Renderer объединяет точное тело только с выступающей частью, не решая пересечения двух почти совпадающих внешних окружностей. Полный гладкий контур в `ink` оставлен для геометрических проверок; в соединённой фазе renderer его отдельно не рисует (`!g.joined` остаётся обязательным условием отдельной чёрной капли).

Таймеры, задержки, пружины, накопление направления, подавление событий прокрутки и мёртвая зона не добавлены. Положение по-прежнему определяется текущей прокруткой. Сохранены один источник изображения, общая маска и один проход затемнения из 6.69.12. Затемнение под нижней капсулой остаётся **80%**. Аудио, навигация, база данных и сетевой код не изменены.

## Измерения и регрессии

На центральной контрольной геометрии 1080 px (камера 37 px, путь прокрутки 369,04 px) оценена чувствительность **полного контура**, а не номинальной ширины шейки. Шаг прогресса 0,001, то есть около 0,369 px прокрутки; каждая кубическая кривая разбита на 32 отрезка. Используется симметричное расстояние от точек одного контура до отрезков соседнего, то есть дискретная оценка расстояния Хаусдорфа.

| Метрика в зоне рождения соединения | 6.69.12 | 6.69.13 |
|---|---:|---:|
| Максимум смещения границы / смещение прокрутки на контрольной выборке | 9,1134 | 1,6208 |
| Обратное сужение боковых частей при раскрытии | Воспроизводится | Новый тест проходит |

Это численная оценка на описанных фикстурах, **не точная универсальная верхняя граница, не FPS и не замер телефона**. Предыдущие числа 11,6 → 2,4 относились к другой метрике — ширине шейки, их нельзя напрямую сравнивать с этой таблицей.

Новая Java-регрессия выполняет **427 686 утверждений**: монотонность боковых частей на нескольких размерах камеры/обложки, смещение полного контура, пределы с обеих сторон смены топологии, повторяемость при удержании и возврате, отсутствие задней границы тела в расширении маски. Используются центральные, левые и правые цели. Три mutation-теста по отдельности возвращают старый поворот, быстрое закругление и двойную границу — все три изменения корректно отклоняются новыми проверками.

| Проверка | Результат |
|---|---|
| `python -m unittest discover -s tools -p 'test_*.py'` | **495 тестов, OK**, 51,081 с |
| `python tools/check_selftest.py` | **exit 0** |
| `check_kotlin_syntax.py`, `check_imports.py`, `check_static_refs.py`, `check_call_args.py` | **exit 0**, замечаний нет |
| Новые Android-проверки удержания/микровозврата | Добавлены, **не запускались** |
| APK / Android 16 / iQOO | **Не проверены** |

Новые Android-тесты находят точку контакта на геометрии устройства, принудительно перезаписывают изображение при неподвижной геометрии и сравнивают всю область камеры/обложки, затем возвращаются после движений ±0,25 и ±1 px. Центральная и боковая камера проверяются отдельно. Вместе с прежними проверками инвентарь CI теперь содержит **33 теста на API 28 и 35 тестов на API 35**. Эти эмуляторы не заменяют Android 16 и GPU телефона тестировщика.

Локальные логи находятся в `verification/v6.69.13/`. Логи предыдущих версий внутри архива — история, а не результаты этой версии. Статические Python-проверки не являются Kotlin/Compose-компилятором.

## Ограничения исходных материалов

Команды в the Computer восстановились, сохранились предыдущие исходники и старые записи. Новая запись `lv_0_20260927190151.mp4` **не загружена и не просмотрена**: доступ к `raw.githubusercontent.com` отклонён сетевым allowlist, альтернативный файловый загрузчик отклоняет MP4/ZIP. Свежий снимок GitHub также получить не удалось. Поэтому релиз основан на проверенной сохранённой 6.69.12, а не на заявлении, что текущая ветка репозитория заново синхронизирована.

Детерминированность Java при постоянном входе не доказывает отсутствие нестабильного scroll-входа или ошибки Android-рендера. Этот релиз устраняет воспроизводимый дефект формы и упрощает опасное объединение границ; полное устранение жалобы на телефоне требует повторной проверки.

## Установка и приёмка

Загрузить **ZiziPlayer-v6.69.13.zip** в корень репозитория вместо попытки смешивать файлы двух версий. Сохранённый workflow выбирает полный проект с максимальным versionCode — здесь **138**. Если в актуальном репозитории уже существует сборка с code 138 или выше, сначала согласовать номер, не создавать два разных архива с одинаковым максимальным code.

После загрузки проверить успешную сборку APK. Дополнительно запустить workflow **Build & release ZiziPlayer APK** с `run_camera_tests = true` и проверить именно результаты тестового job, а не только сборки APK. Workflow в этой версии не изменялся.

На **iQOO Neo 10 Global / Android 16** проверить очень медленное первое касание, удержание в точке контакта несколько секунд, малые движения туда-обратно, обе боковые границы, полное поглощение и обратное раскрытие. Сравнивать одинаковые обложку, масштаб экрана и частоту обновления. Если дрожание осталось при действительно неизменной позиции пальца, приложить новую запись напрямую в диалог — потребуется сопоставить входную прокрутку и кадры Android, а не ещё раз вслепую менять ширину шейки.
