# ZiziPlayer 6.69.11 — возврат в подборку и независимая сборка APK

Версия: **6.69.11**, `versionCode = 136`. База: 6.69.10 / 135.

## Исправление зависшей обложки

В `PinnedCollectionScaffold` позиция `LazyListState` восстанавливалась, а измерение
`heroPx` оставалось равным нулю: элемент шапки вне экрана не обязан заново создаваться.
Старая ветка использовала этот ноль как прокрутку, возвращая отдельный слой обложки
в начало анимации при сохранённом глубоко прокрученном списке.

Теперь `CollectionCollapseMath.visualScroll` при `firstVisibleItemIndex > 0`
возвращает максимум высоты шапки и полного пути поглощения обложки. Это насыщенная
визуальная дистанция, не изменение позиции списка. При видимой шапке используется
точный `firstVisibleItemScrollOffset`. Сохранённые пиксельные размеры не вводятся.
Закреплённый заголовок и кнопка Play также не ждут отсутствующего измерения.

Общий компонент используется экранами подборок; аудио, серверы и база медиатеки
этим патчем не изменены. Логика затемнения и единого внешнего контура из 6.69.10 сохранена.

## Два падения из logs_98350590578.zip

`topAttachedReservationRendersConnectedNeckBeforeArtworkDisappears`: тест ожидал
яркость `1 - neckInk`, хотя с 6.69.10 действуют общий и локальный слои затемнения.
Ожидание исправлено на `(1 - bodyInk) * (1 - neckInk)`, допуск не увеличен.

`bodyDarkeningTracksContactAndReverses66910`: вместо белой затемнённой обложки тест
получал цвет фона (0.1882353 вместо ожидаемых 0.58390784 при progress=0.5).
Это не признано нормальным результатом и не замаскировано ослаблением теста.
В соединённой фазе тело теперь рисуется прямым `drawContent()`; зеркальный
девятиплиточный helper используется только для продолжения текстуры перемычки.
Единый внешний clip и один проход затемнения сохранены.

**Статус второго исправления: код изменён, но успешный повтор этого Android-теста
ещё не получен.** Локальные проверки подтверждают структуру патча и геометрию,
а не корректность исполнения Compose/RenderNode на Android.

## Изменение build.yml

Обычный `build` больше не запускает эмуляторы API 28/35, не собирает instrumentation
APK и не компилирует androidTest отдельно. Сохранены локальные проверки, JVM-тесты,
release-компиляция, валидация конфигурации и подписи. Это не отключение всех тестов.

Android-регрессии оставлены в независимом `camera-regression`. Он запускается только
через **Run workflow → run_camera_tests = true**. По умолчанию — false. У `build`
нет `needs` на него, поэтому неуспех Android-регрессий не блокирует выпуск APK.
При ручном включении падение остаётся красным и может сделать общий workflow красным,
хотя независимая задача сборки APK завершится отдельно. `continue-on-error` не добавлен.

Точное ускорение не замерено. Исключены запуск эмуляторов и сборка тестовых APK;
время Gradle/сети/кэша остаётся переменным.

## Как применить

1. Заменить **реальный файл репозитория** `.github/workflows/build.yml` приложенным
   `build.yml`. Не класть его в корень под именем build.yml.
2. Загрузить `ZiziPlayer-v6.69.11.zip` в корень репозитория. По возможности сделать
   оба изменения одним коммитом; если отдельно — сначала workflow, затем ZIP.
3. Убедиться, что выбран ZIP с versionCode 136. При обычном запуске задача
   `camera-regression` должна быть пропущена, а `build` — собирать APK.

**ZIP не заменяет workflow автоматически:** GitHub читает `.github/workflows/build.yml`
из репозитория ещё до распаковки проекта. Обе копии внутри ZIP синхронизированы;
`repo-update/.github/workflows/build.yml` — файл для переноса в репозиторий.
Приложенный `ZiziPlayer-v6.69.11-repository-update.zip` содержит этот путь целиком
для локальной распаковки в checkout; загрузка этого вспомогательного ZIP в GitHub
сама по себе workflow не изменит.

## Проверки

- `python -m unittest discover -s tools -p 'test_*.py'`: **486 tests, OK**, exit 0.
- `python tools/check_selftest.py`: exit 0.
- Проверки Kotlin-синтаксиса, импортов, static refs и аргументов: exit 0.
- Новая исполняемая Java-проверка: **9306 утверждений** восстановления геометрии;
  мутация с возвратом к старому `return hero` отклоняется.
- YAML разобран встроенным парсером Bun; все **29 shell-блоков** прошли `bash -n`.
- В Android-инвентарь добавлены три теста реального удаления/восстановления Compose
  экрана: центральная камера, боковая камера, отсутствие камеры. Они включены
  в ручной прогон API 28/35, **но локально не исполнялись**.

Логи этого прогона: `verification/v6.69.11/`. Android SDK, Gradle-сборка APK,
эмулятор и телефон в этом продолжении недоступны/не запускались.
**Это полный ZIP исходников, не готовый APK и не подтверждение зелёной Android-сборки.**

После установки проверить: прокрутить подборку до исчезновения обложки, уйти на другой
экран, вернуться два раза, проверить закреплённые заголовок/Play, затем прокрутить
к началу. Обложка должна вернуться только с шапкой, без зависшего круга над треками.
