# Обновление Accounts 1.2 → 1.3: общие плейлисты

Общие плейлисты живут только в сервисе аккаунтов. Музыкальный сервер (`server/`, резолвер, yt-dlp) не меняется и не перезапускается. Новых Python-зависимостей нет, venv прежний. nginx для API не трогаем: `/auth/shared/*` идёт через уже существующий `location /auth/`.

Что меняется: `web.py` и `maintenance.py` заменяются, добавляется новый `shared.py`. `core.py`, `library.py`, `profiles.py`, `.env`, SMTP, JWT-ключи, service- и timer-файлы не трогаются. Пять таблиц `shared_*` создаются при первом старте; существующие таблицы и данные не меняются.

## 1. Проверка (ничего не пишет)

Распакуйте `ZiziPlayer-Accounts-1.3.0.zip` в отдельный каталог, перейдите в его `accounts_server/`. Пути ниже — стандартные из service-файла проекта; если у вас другие, подставьте свои.

````sh
python3 install_accounts_13.py --target /opt/zizi-accounts/current --check
````

`Modified live file` означает, что на сервере правленый файл (например, SMTP-фикс в `web.py`). **Не обходите проверку**: сохраните свои правки и объедините их с 1.3 вручную. При отказе ни один файл не меняется.

## 2. Установка

Каждая команда должна завершиться успешно до следующей. Имя резервной базы — новое, не затирайте прошлые копии.

````sh
sudo systemctl stop zizi-accounts
sudo sh -c 'umask 077; sqlite3 /var/lib/zizi-accounts/accounts.sqlite ".backup /var/lib/zizi-accounts/accounts-before-1.3.sqlite"'
sudo python3 install_accounts_13.py --target /opt/zizi-accounts/current --apply
sudo systemctl start zizi-accounts
sudo systemctl status zizi-accounts --no-pager
````

Установщик печатает каталог с резервными исходниками — запомните его для отката.

## 3. Проверка после старта

````sh
curl --fail --show-error https://ziziplayer.duckdns.org/auth/health
curl -s -o /dev/null -w '%{http_code}\n' https://ziziplayer.duckdns.org/auth/shared
````

Ожидается `version: "1.3.0"`, `shared_enabled: true`, остальные флаги как в 1.2. Второй запрос без авторизации — `401`, не данные.

Ежедневный таймер `zizi-accounts-cleanup` уже установлен и теперь заодно чистит удалённые треки и плейлисты старше 30 дней, журнал сверх 2000 событий или старше 30 дней, истёкшие приглашения. Проверить вручную:

````sh
sudo systemctl start zizi-accounts-cleanup.service && sudo journalctl -u zizi-accounts-cleanup -n 3 --no-pager
````

## 4. Страница приглашения `/p/` (музыкальный сервер, один раз)

Ссылка-приглашение — тот же App Link, что у обычных ссылок на плейлист: `https://ziziplayer-audio.duckdns.org/p/#ZS1:<токен>`. Токен во фрагменте после `#`: браузер его на сервер не отправляет, в логи nginx он не попадает. С установленным приложением ссылка откроется сразу. Чтобы и без приложения страница показывала «Вас пригласили в общий плейлист» вместо текста про обычный плейлист, перегенерируйте статику из нового `server/tools/setup_app_links.py`:

````sh
cd /opt/zizi/current && sudo python3 tools/setup_app_links.py --check
sudo python3 tools/setup_app_links.py --apply
````

Отпечаток подписи скрипт берёт из `/opt/zizi/zizi.env`, как и раньше. Резолвер не перезапускается.

## 5. Клиент

APK 6.101.0. Пока сервер на 1.2, пункт «Общие плейлисты» в меню аккаунта есть, но запросы получат 404, и экран честно скажет «Сервер не принял запрос». Поэтому сначала сервер, потом APK.

Проверка двумя аккаунтами на двух телефонах:
1. A: меню аккаунта → «Общие плейлисты» → создать из своего плейлиста. Тост сообщит, сколько локальных треков не попало.
2. A: «Пригласить» → «Отправить» в мессенджер. B открывает ссылку → «Вступить».
3. B добавляет трек через меню трека → «Добавить в плейлист» → «В общий плейлист…». У A он появляется в течение 30 с, если экран плейлиста открыт, или сразу при его открытии.
4. B пытается удалить трек A — пункта нет. A удаляет трек B — получается.
5. B в авиарежиме добавляет два трека, выходит из авиарежима: в течение минуты они уходят сами, на хабе исчезает «Не отправлено изменений».

## Откат

Остановите сервис, верните `web.py` и `maintenance.py` из каталога резервирования, удалите `shared.py`, запустите сервис. Таблицы `shared_*` старому серверу не мешают, их можно оставить. **Не откатывайте базу целиком**: потеряются сессии, регистрации и облачные копии, сделанные после обновления. Клиент 6.101.0 со старым сервером продолжит работать, кроме общих плейлистов.
