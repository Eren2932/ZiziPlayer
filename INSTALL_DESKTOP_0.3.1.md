# Zizi Desktop 0.3.1-preview — установка обновления исходников

Это подготовленное обновление исходников, а не скомпилированный EXE. Kotlin/Compose-сборка и Windows-тесты в этой сессии НЕ запускались. Рабочую 0.3.0 не удалять до успешной сборки и проверки новой версии.

## Как перенести в GitHub

Распаковать `ZiziDesktop-0.3.1-repo-update.zip` и добавить его содержимое в корень Eren2932/ZiziPlayer с сохранением путей. В том числе заменить `.github/workflows/desktop.yml` и `desktop/current.json`, добавить `desktop/releases/ZiziDesktop-0.3.1-preview-source.zip`, обновлённые CI-скрипты и документы. Загрузить один внешний ZIP в корень недостаточно: текущий CI читает `desktop/current.json`, а не выбирает самый новый ZIP по имени.

Android ZIP и Android workflow пакет не меняет. Старый desktop ZIP оставлен доступным для отката. Ничего в GitHub автоматически не опубликовано.

## Параметры подключения задаются один раз при сборке

В Settings → Secrets and variables → Actions используется тот же **secret `RESOLVER_TOKEN`**, что у Android. Не переносить значение в Variables, в workflow, в исходники или в переписку. Если secret отсутствует, сборка специально остановится с безопасным сообщением.

**Variable `RESOLVER_URL`** — тот же сервер, что у Android; допустим адрес с `https://`, `http://` либо без схемы. Для отсутствующей переменной workflow использует адрес по умолчанию из изученного Android 6.39.9. Это совместимость исходников, а не подтверждение актуальности адреса на VPS.

В Actions → Build Zizi Desktop Windows preview (manual) → Run workflow:

1. Для HTTPS оставить `allow_http` выключенным.
2. Если действующий сервер действительно HTTP, включить `allow_http`. Можно вместо этого один раз задать repository variable `DESKTOP_ALLOW_HTTP=true`.
3. Запустить сборку. Preflight не выведет ни адрес, ни токен. Без HTTP opt-in внешний HTTP намеренно не проходит: причина будет явно указана в логе.

HTTP opt-in разрешает незашифрованное соединение **только с origin из сборки** (схема, хост, порт). Прямые произвольные HTTP-ссылки остаются запрещены, перенаправления не включаются. Но это НЕ защита от перехвата на пути к разрешённому серверу: для неё нужен HTTPS на обеих платформах.

После успешного завершения скачать artifact `ZiziDesktop-Windows-x64-0.3.1-preview`, распаковать всю папку и запускать `ZiziDesktop.exe`. FFmpeg и ffprobe по-прежнему внешние: указать FFmpeg в настройках звука. Его настройка теперь не меняет сетевую сессию.

## Что изменилось для слушателя

В приложении больше нет полей сервера и bootstrap-токена. При наличии корректной конфигурации релиза подключение и подготовка ключа запускаются автоматически. До реального запроса UI пишет «Конфигурация загружена · сеть ещё не проверена», а не притворяется подключённым.

Install ID сохраняется как раньше. Новый кэш сохраняет временный device-ключ и срок; он разделён по адресу, install ID и bootstrap. Смена параметров сборки не смешивает старые ключи с новым сервером. Это per-user Java Preferences (HKCU на Windows), **не DPAPI/защищённое хранилище**. Общий bootstrap туда не сохраняется, но остаётся извлекаемым из самого публичного приложения, как у Android.

Вместо большого градиента — чёрный матовый фон и нейтральные поверхности. У поиска мобильные высоты 49.5/52 dp, радиус 3.5 dp, цвета и размеры текста. Enter и иконка поиска заменяют клавиатурную кнопку Android. История запросов сохраняется и очищается. Подсказки пока только из истории и локальной медиатеки, не с провайдера.

## Обязательная проверка после сборки

Проверить холодный старт, поиск, онлайн-воспроизведение, перезапуск, переключение и паузу/seek. Изменить только FFmpeg и убедиться, что авторизацию повторно вводить не требуется. Проверить 401/429/offline без зависания UI и без утечки URL/ключей в сообщениях. На реальном дисплее проверить фон, поиск, диалоги и масштабирование 100/125/150%.

CI запускает 44 JUnit-метода, включая 9 новых тестов bundled connection/cache/policy и существующие аудиотесты с FFmpeg. Их наличие — не утверждение, что они уже прошли: нужен зелёный CI.

## Откат

Сохранить существующую рабочую папку 0.3.0. В GitHub откатить commit с этим обновлением (включая workflow и `desktop/current.json`) и заново собрать предыдущий manifest. Удалять короткоживущие ключи 0.3.1 вручную для отката не требуется. Серверные параметры этот пакет не меняет.
