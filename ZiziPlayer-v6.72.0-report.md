# ZiziPlayer 6.72.0 — отдельная палитра текстов песен

**30 сентября 2026 · versionCode 155 · база 6.71.3 / 154.** Полный ZIP исходников, не APK. Изменение клиентское: сервер обновлять не требуется.

## Результат

Полноэкранный текст больше не наследует затемнение основного плеера. Вместо градиента из `p.top` в почти чёрный `p.bottom` у него собственные семь цветовых точек: низ мягко светлеет, сохраняя оттенок обложки. Прошедшие и будущие строки используют одинаковый непрозрачный светлый оттенок от обложки; активная строка — почти белая. Непрочитанные слова в настоящем enhanced LRC используют тот же цвет, что окружающие строки.

Убрана 24%-ная чёрная подложка системной строки именно на полноэкранном тексте. Основной плеер сохраняет прежнее затемнение и свою подложку. Состояние видимости текстов поднято в его хост: окно и слой status bar используют один флаг, без двух независимых состояний и без эффектов обратной синхронизации.

Размеры шрифта, расположение строк и транспорт не переделывались. Сохранены ручная прокрутка, возврат к текущей строке, переход по таймкоду, импорт, сдвиг LRC, проверка версии/длительности и поведение при смене трека. Основная палитра плеера, включая красные обложки, не перекрашивалась. Аудиотракт, поиск текстов, очередь, медиатека, БД, серверы и зависимости не менялись.

## Что было причиной

В `LyricsScreen.kt` фон строился напрямую из уже обработанного цвета плеера и его чёрного низа. Отдельного цветового режима для чтения не существовало. Цвет неактивных строк был белым с альфой 0,34 для прошедших и 0,52 для будущих: видимый RGB зависел от высоты строки и текущего фона. Отсюда сероватый текст и разная читаемость вверху и внизу.

Теперь `ZiziPalette.artworkPrimary` переносит **исходный кэшированный свотч**, до затемнения плеера. `LyricsSurfaceTheme` один раз на его изменение вычисляет локальную палитру. Ни повторного чтения обложки, ни новой загрузки, ни перерасчёта по часам воспроизведения нет. Формат кэша обложек не менялся: массовая перезагрузка картинок не нужна. При отключённой подкраске или отсутствующей обложке используется нейтральная палитра, без выдуманного цветного оттенка.

## Цветовая математика

`LyricsColorMath.java` не зависит от Android. Преобразование выполняется в OKLCH: меняется перцептивная светлота, а цветовой угол исходного свотча сохраняется. Нет исключения для URANIUM, оливкового цвета или отдельного диапазона красных.

Верхняя светлота определяется выражением `0.335 + 0.030 × Lsource`; нижняя выше на `0.100`. Позиции семи точек совпадают с существующим рендерером: `0, 0.10, 0.28, 0.46, 0.64, 0.82, 1`. Хрома ограничена сверху `0.14` и доступным sRGB-охватом при выбранной светлоте. При выходе за охват уменьшается хрома, а не обрезается один из цветовых каналов. Это предотвращает непреднамеренную смену оттенка.

Околонейтральный цвет проходит плавный порог хромы `0.012…0.035`: слабый цветовой шум JPEG не усиливается. Светлота окружающего текста начинается с `0.845`, его хрома — `min(1.35 × Csource, 0.10)`. Цвет непрозрачный. При необходимости светлота повышается до прохождения контраста 4,5:1. Проверка использует поканальную верхнюю границу всей фоновой рампы, поэтому не ограничивается только её концами.

Форма градиента, отсутствие чёрного низа и принцип устойчивого цветного текста воспроизведены без привязки к одному треку. Проверка точного цвета на текущей обложке и дисплее остаётся частью приёмки.

В `docs/lyrics-6.72.0/` лежат измерения с SHA-256 изображений, значения палитр, полученные исполнением production Java, и `palette-study.png`. Изображение — **расчётная карта цветов, не скриншот собранного приложения**. Шесть примеров охватывают серый, оранжевый, розовый, зелёный, оливковый и красный.

## Проверки и их границы

Прошли **96 из 96 локальных наборов**, включая два новых. Выполнены production Java, существующие Python/SQL-проверки и проверки соединения исходников. В новой численной проверке: 4096 RGB-цветов, 811 008 интерполированных фоновых проб с контрастом обоих типов текста не ниже 4,5:1, контроль угла цвета, 256 нейтральных цветов, отсутствие обложки, шум, детерминированность и допуски относительно референса.

Синтаксический сканер Kotlin, импорты и квалифицированные ссылки не нашли проблем. Проверка аргументов в `app/src/main` чистая. При более широком обходе всех тестов остаются те же три предупреждения сканера, что и в неизменённом 6.71.3; они сверены с базой и не скрыты.

Первый монолитный `check_selftest.py` достиг лимита выполнения команды 120 секунд. После этого **все** 96 указанных в нём наборов запущены заново тремя пакетами с отдельными кодами завершения; каждый завершился с кодом 0. Восемь самотестовых фикстур проверочного инструмента также прошли. Логи и машиночитаемый итог — `verification/v6.72.0/`.

**Не выполнены:** Gradle/Kotlin-сборка всего Android-приложения, создание APK, запуск на эмуляторе и физическом телефоне. В the Computer нет необходимого комплекта Gradle/Android SDK. Проверки текстом и чистая Java не заменяют Android-сборку.

Добавлен JVM/JUnit-тест `LyricsColorMathTest`, который подхватит штатный `:app:testDebugUnitTest`. Добавлены три Android-теста `LyricsPaletteUiTest`: изоляция и обновление темы, реальные пиксели градиента, непрозрачные пословные цвета. Эти три теста **не запускались здесь** и не входят в существующий узкий camera-class filter; для них нужна отдельная команда, указанная ниже.

## Применение

Загрузить **`ZiziPlayer-v6.72.0.zip` целиком в корень репозитория**, как предыдущие мобильные версии. Распаковывать его в корень GitHub не нужно. Проверенный текущий `.github/workflows/build.yml` выбирает полный проект по максимальному `versionCode`; новый код — 155. Не оставлять другой ZIP с тем же максимальным кодом. Для этого выпуска заменять workflow не требуется.

Штатная GitHub Actions выполняет `check_selftest.py`, `:app:testDebugUnitTest` и сборку release APK. Отдельный Android-прогон при наличии SDK, Gradle и устройства:

````bash
gradle :app:testDebugUnitTest
gradle :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=app.ziziplayer.ui.LyricsPaletteUiTest
````

Приёмка на телефоне: открыть URANIUM и несколько красных, синих, зелёных и чёрно-белых обложек; проверить светлый низ и статусную строку, смену трека при открытых текстах, отключение подкраски, ручную прокрутку и возврат. Проверить обычный LRC, enhanced LRC и текст без меток. После закрытия текстов основной плеер должен выглядеть как раньше. Затем проверить горизонтальную ориентацию и увеличенный системный шрифт: геометрия этим выпуском не менялась.
