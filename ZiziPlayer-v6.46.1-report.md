# ZiziPlayer 6.46.1 — исправление сборки экрана текста

## Основание и диагноз

База: публичный Eren2932/ZiziPlayer, снимок main `ba628f461eb11601da08c98f73731f3f827aa440`, архив `ZiziPlayer-v6.46.0.zip`, versionCode 94. В этом снимке это последний мобильный проектный ZIP. Лог взят из `jvm-test-reports (1).zip`, файл `unit-tests.log`.

Лог заканчивается ошибкой `:app:compileDebugKotlin`, до выполнения JVM-тестов. Все пять сообщений относятся к `LyricsScreen.kt`, строки исходной версии 88, 89, 90, 134, 135:

> 'val maxWidth: Dp' cannot be called in this context with an implicit receiver. Use an explicit receiver if necessary.

Это отказ сборки, не стек падения установленного приложения. Причина — правила Kotlin DSL receiver: `BoxWithConstraintsScope` и вложенный `ColumnScope` участвуют в layout DSL. Внутри Column нельзя неявно получить maxWidth скрытого внешнего receiver. Предупреждения об отсутствии release-подписи и о compileSdk 36/AGP 8.7.3 не остановили эту сборку. Они не исправлялись попутным обновлением зависимостей.

## Исправление

В теле внешнего BoxWithConstraints, перед Column, добавлено `val screenWidth = maxWidth`. Пять вызовов LyricsGeometry — headerFont, headerLine, headerHeight, playDiameter, bottomGap — получают `screenWidth.value` вместо `maxWidth.value`.

Значение не хранится в remember, глобальном состоянии или настройках: при перекомпоновке оно считывается из текущих ограничений. Единицы остаются dp (Dp.value); преобразования в px не добавлены. Внешняя ширина с учётом уже существующего safeDrawingPadding не заменена шириной дочернего Row. Compact-порог по высоте остаётся 440 dp. Все формулы LyricsGeometry.java сохранены побайтно, включая ограничения размеров кнопки 48–80 dp. Исходные Java-тесты геометрии/метаданных выполняют 73 проверки и проходят; это не снимки отрендеренного Compose.

Изменён только один runtime-файл: `app/src/main/java/app/ziziplayer/ui/screens/LyricsScreen.kt`. Код воспроизведения, сетевые запросы, база, миграции, схемы, подпись, applicationId, разрешения, ресурсы, зависимости и сервер не изменены.

Версия поднята до 6.46.1 / 95, чтобы существующий workflow однозначно предпочёл исправленный архив старому и APK имел больший versionCode. В семи существующих контрактных тестах обновлены только ожидаемые versionName/versionCode; остальные проверки не ослаблялись.

## Защита от повторения

Новый `tools/test_lyrics_6461_contracts.py` проверяет выбранный способ исправления: захват ширины перед Column и использование её во всех пяти вызовах. Он подключён к уже вызываемому CI `tools/check_selftest.py`, поэтому править корневой workflow не требуется.

Набор содержит пять тестовых методов, включая пять отрицательных подслучаев: каждый из исходных проблемных вызовов по очереди возвращается в копию исходника и должен быть обнаружен. Дополнительно отвергаются перенос захвата внутрь Column и независящий от ширины remember. Проверка отдельно запущена на настоящем исходном файле из 6.46.0: он отвергается (`original-regression.log`). Это узкий текстовый контракт, не компилятор Kotlin и не универсальный анализатор DSL.

## Выполненные проверки и ограничения

В the Computer все 52 команды из `verification/v6.46.1/results.json` завершились с кодом 0. Сохранены свежие полные логи: Kotlin-синтаксис/импорты/ссылки/аргументы (эвристические проверки), существующие UI-контракты, исполняемые production Java-ядра, новая регрессия, офлайн-тесты сервера и CI selector. Наборы внутри check_selftest повторяются отдельными командами; число 52 не означает 52 независимых теста и тем более не означает Android-сборку.

JDK в the Computer: OpenJDK 21.0.12, Java-тесты вызывают компилятор с source/target 17. CI настроен на JDK 17. Gradle, kotlinc, SDK manager и adb здесь отсутствуют; Gradle/Kotlin/Compose-компиляция, assembleRelease, R8 и запуск на телефоне **не выполнялись**. Успех новой сборки и отсутствие других ошибок должен подтвердить Actions. Исправление устраняет именно пять диагностированных обращений, но не является обещанием отсутствия любых следующих ошибок сборки или runtime-сбоев.

Корневой workflow на указанном коммите совпадает с workflow внутри базового ZIP. Он не изменялся. Итоговый архив дополнительно проверяется на CRC, совпадение содержимого с рабочим деревом, уникальность/безопасность путей и выбор новой версии реальным Python-блоком selector из корневого workflow. Результат этой финальной проверки поставляется рядом с ZIP как `ZiziPlayer-v6.46.1-package-check.json`.

## Установка обновления в репозиторий и проверка телефона

Загрузить только итоговый `ZiziPlayer-v6.46.1.zip` в корень репозитория, в main. 6.46.0 можно оставить: 95 больше 94. Не загружать рядом второй проектный архив с versionCode 95. Распаковывать ZIP в репозиторий, менять Desktop/current.json или заменять workflow не требуется. Изменений в удалённом репозитории в ходе этой работы не делалось.

В Actions проверить, что выбран 6.46.1 / 95, выполнены новые source contracts, успешно прошли `:app:testDebugUnitTest` и `:app:assembleRelease`. Скачать APK из `ZiziPlayer-APK-v6.46.1`. Обновление поверх прежнего APK требует того же сертификата подписи. Не удалять приложение и не очищать данные для обхода несовпадения ключей.

На устройстве проверить запуск после обновления без потери медиатеки; открытие и закрытие полного текста; заголовок, прогресс и транспорт; портретную/альбомную ориентацию и изменение окна; compact-режим; экран без найденного текста и с импортированным LRC. Если именно приложение падает на телефоне, нужен отдельный runtime crash log: загруженный unit-tests.log такого падения не содержит.

Исторические отчёты и логи в архиве сохранены без переименования. Актуальные доказательства этой работы находятся только в каталоге verification/v6.46.1 и в сопроводительной финальной проверке упаковки.
