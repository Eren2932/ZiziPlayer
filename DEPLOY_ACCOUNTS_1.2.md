# Обновление установленного Accounts 1.1 → 1.2

Новый сервер нужен для **имени и фото**, а не для включения уже доступной в 1.1 библиотеки. SMTP, nginx, JWT-ключи, музыкальный сервер и пользователей перенастраивать не нужно. В этом диалоге VPS не обновлялся.

Распакуйте `ZiziPlayer-Accounts-1.2.0.zip` в отдельный каталог и перейдите в его `accounts_server/`. Сначала проверьте фактические пути установки. Ниже стандартные пути из service-файла проекта — если у вас другие, замените их, не выполняйте вслепую.

````sh
python3 install_accounts_12.py --target /opt/zizi-accounts/current --check
````

Если установщик сообщает Modified live file, он обнаружил отличие от известных исходников. **Не обходите проверку.** Сохраните рабочие изменения, в частности SMTP, и объедините их с изменениями 1.2 вручную. При отказе preflight ни один установленный файл не меняется.

После успешного preflight остановите только аккаунты, сделайте резерв базы и установите исходники. Каждая команда должна завершиться успешно до следующей. Имя резервной базы должно быть новым, не затирайте предыдущую копию.

````sh
sudo systemctl stop zizi-accounts
sudo sh -c 'umask 077; sqlite3 /var/lib/zizi-accounts/accounts.sqlite ".backup /var/lib/zizi-accounts/accounts-before-1.2.sqlite"'
sudo python3 install_accounts_12.py --target /opt/zizi-accounts/current --apply
sudo systemctl start zizi-accounts
sudo systemctl status zizi-accounts --no-pager
````

Если резервирование или установка не прошли, не продолжайте автоматически. Установщик печатает каталог резервных исходников. Он заменяет только core.py, web.py, library.py и profiles.py, не `.env`, ключи, service-файлы и базу. Таблица account_profiles создаётся при старте; существующая library_snapshots сохраняется. Новых Python-зависимостей нет. Используется прежний venv.

Уже заданный **`client_max_body_size 17m` оставить**. Для этого обновления nginx менять/перезагружать не требуется. Не открывайте внутренний порт Accounts наружу и не меняйте маршруты музыкального сервера.

````sh
curl --fail --show-error https://ziziplayer.duckdns.org/auth/health
````

Ожидается `version: "1.2.0"`, `profile_enabled: true`, `sync_enabled: true`, `library_format: "zizi-library-1"`. `google_enabled: false` нормально. GET `/auth/profile` и `/auth/library` без авторизации должны возвращать 401, а не данные.

После обновления проверить обычный email-вход тестовым аккаунтом, затем имя/фото и облачное сохранение в новом APK. Не публиковать JWT, cookies, коды подтверждения, пароли, env и ключи.

## Откат

Остановите аккаунты, верните исходники 1.1 из каталога резервирования, напечатанного установщиком, запустите службу. Для прежнего 1.1 это core.py, web.py и library.py. Дополнительная таблица профилей и неиспользуемый profiles.py старому серверу не мешают. **Не откатывайте всю базу автоматически:** это потеряет новые сессии/регистрации/копии после обновления. После отката библиотека остаётся доступной, редактор профиля в новом клиенте сообщит о требовании Accounts 1.2.
