# ZiziPlayer 6.62.0-lyrics-hybrid — первый резервный источник текстов

**18 сентября 2026. Исходники экспериментального кандидата, versionCode 117. Не APK.**

## Что готово

Добавлена цепочка `LRCLIB → lyrics.ovh`. Это два реально подключённых сетевых источника, а не переключатель без реализации. LRCLIB сохраняет приоритет, свои проверки названия, исполнителя, версии и длительности, парсер LRC и существующие анимации. Если подходящего результата нет или запросы LRCLIB завершаются ошибкой, приложение пробует публичный API lyrics.ovh. Успешный результат LRCLIB, включая обычный текст и подтверждённую метаданными инструментальную запись, не заменяется резервом.

Общий `LyricsHybridLookup` отделяет последовательность источников от транспорта и их адаптеров. Ошибка, неправильный JSON и таймаут — не «песни нет». HTTP 429 даёт паузу на 60 секунд только соответствующему поставщику. Второй поставщик остаётся доступен. Если все источники вернули настоящий промах, он хранится в RAM 2 минуты; ручное обновление обходит этот кэш, но не ограничение частоты запросов.

**Точность резерва ограничена самим API.** lyrics.ovh возвращает слова, но не возвращает сопоставимые название/артиста/длительность записи и не даёт таймкоды. Мы отправляем точные название и исполнителя, сохраняя `Ultra Slowed`, `Sped Up` и другие версии; сегменты пути кодирует OkHttp. Однако точный запрос не доказывает точность ответа. Поэтому документ явно помечен «версия не проверена», не имеет синхронизации и не получает искусственную длительность. Эта пометка видна и в компактном полноэкранном режиме. Нельзя утверждать, что каждый такой ответ относится к нужному аудио.

Резервный текст хранится только в ограниченной памяти приложения до 10 минут, не пишется в постоянный дисковый кэш. Срок проверяется при следующем обращении к кэшу; он не запускает фоновый таймер обновления открытого экрана. Кэш LRCLIB и импортированные LRC совместимы с прежней версией. Исправлена проверка срока жизни в RAM, чтобы новый короткий срок действительно соблюдался при повторном чтении. Обновление вручную начинает поиск с LRCLIB.

## Ограничения сети и данных

Одна попытка делает не более трёх запросов LRCLIB и одного запроса lyrics.ovh. Координатор дополнительно проверяет лимиты, а не полагается только на циклы адаптера. Лимит одной операции, включая ожидание сетевого слота аудио, — 7 секунд. Бюджеты поставщиков — 26 и 8 секунд соответственно; общий существующий таймаут UI вместе с повторами остаётся 45 секунд. Это верхние программные бюджеты, а не обещание сетевой задержки.

Каждый запрос проходит прежний gate приоритета аудио. Смена трека и выключение автоматической загрузки отменяют корутину и HTTP. Отмена родительской корутины не трактуется как повод обратиться к следующему источнику. Тексты используют отдельный клиент без учётных данных аудиосервера, без cookies, без перенаправлений и без отправки звука. Настройка автоматических текстов теперь раскрывает оба источника и передаваемые им метаданные.

Ответ ограничен 512 КиБ. Резервный plain-текст дополнительно ограничен 100 000 UTF-16 единиц, проверяется на пустоту, HTML-документ и недопустимые управляющие символы. Неправильный тип JSON-поля не превращается в текст. Неизвестные поля с якобы таймкодами игнорируются. Диагностика различает поставщиков, результат, backoff и типы ошибок, не записывает слова песни и полные URL запросов.

## Проверка целевых треков

Повторная публичная проверка выполнена 18 сентября через загрузчик URL, не с телефона и не через собранный APK.

| Запрос | Результат |
|---|---|
| LRCLIB: Raya (Ultra Slowed) — Zericxxn, 130 секунд | Запись 38647172; синхронизированный текст присутствует |
| lyrics.ovh: точные Zericxxn / Raya (Ultra Slowed) | HTTP 404 |
| LRCLIB: поиск Senemene + Dali Dade | HTTP 200, пустой массив |
| lyrics.ovh: точные Dali Dade / Senemene | HTTP 404 |
| lyrics.ovh: Coldplay / Adventure of a Lifetime | HTTP 200, строковое поле lyrics, 1399 символов в исходной строке |

Контрольный ответ подтверждает доступность API и ожидаемую структуру ответа. Production Java-валидатор его принимает. Это **не доказательство прироста покрытия относительно LRCLIB**, не проверка соответствия слов аудио и не исполнение Kotlin-адаптера. Массовый эксперимент по покрытию ещё не проводился.

**Senemene в этой проверке по-прежнему не найден. Отсутствие Raya на телефоне по-прежнему требует телефонной диагностики:** на стороне LRCLIB текст уже есть. ZIP не объявляется исправлением обоих конкретных треков. Никакие тексты для них не придуманы и не взяты от другой записи.

## Исходная база и границы изменения

База — мобильный `ZiziPlayer-v6.61.1-lyrics-exp.zip`, versionCode 116. Его Git blob `98547bdc255d35b20c605e3d0bd5b116c866289e` совпал с деревом публичного репозитория на commit `f5c7e95cfeef6c762b31c5bb13c93aad827665e2`. На этом снимке это последний мобильный ZIP. Desktop не менялся.

Побайтово сохранены `server/` (исходники, без генерируемого pycache), мобильные `playback/` и `data/remote/`, а также `LrcTimeline.java` и `LyricsMatchPolicy.java`. Не изменены сервер сопоставления Deezer/YouTube, Room, DSP и алгоритмы анимаций. В UI текстов добавлены только пометки происхождения/ограничений и обновлена строка диагностики. Репозиторий GitHub и VPS из этой сессии не изменялись.

Новых runtime-зависимостей нет. Для JVM-тестов добавлен только `testImplementation("org.json:json:20240303")`, чтобы тестировать настоящий JSON, а не заглушки Android. Старые активные проверки версии обновлены с 116 на 117; проверки перемещённого backoff/транспорта адаптированы к новой структуре, не удалены.

## Что проверено, а что нет

Общий `tools/check_selftest.py` завершился успешно, включая прежние Java/Python-регрессии. Новый `tools/test_lyrics_hybrid_6620.py` — пять проверок: исполняет **19 assertions production Java-валидатора** и проверяет Kotlin-связи на уровне исходников. Прежние 22 Java-проверки Raya и границ синхронизации также проходят. Четыре эвристические проверки Kotlin-синтаксиса, импортов, статических ссылок и аргументов не выявили замечаний. Дополнительные серверные проверки и шесть тестов выбора ZIP для CI прошли; команды и логи приложены в `verification/v6.62.0-lyrics-hybrid/`.

Добавлены **13 Kotlin/JUnit-тестов** реального координатора и OVH-адаптера с подменённым транспортом: приоритет, промах, outage, 429 по источникам, отмена, родительский и внутренний таймауты, лимит запросов, кодирование пути, неправильный JSON и отсутствие выдуманной синхронизации. Отдельный JUnit-тест подключает Java-проверки к Gradle. **Эти Kotlin/JUnit-тесты здесь НЕ запускались.** Их запускает имеющийся workflow через `:app:testDebugUnitTest`.

**Полная компиляция Kotlin/Compose, Gradle-тесты, сборка APK, эмулятор и телефон здесь не проверены.** Android toolchain не подготовлен. Локальные source guards не заменяют компиляцию и не подтверждают Android-сетевой тракт. Из-за этого архив обозначен экспериментальным кандидатом, а не готовым проверенным релизом.

## Как собрать и принять

Загрузить `ZiziPlayer-v6.62.0-lyrics-hybrid.zip` в корень репозитория. Корневой workflow выбирает максимальный versionCode; 117 больше 116. Второго мобильного архива с таким же максимальным кодом быть не должно. Workflow внутри ZIP побайтово совпадает с текущим корневым (`6f4caf1681e4d1dd5de4801080d90eeb50fe3884`), менять его не нужно. Desktop `current.json` не трогать.

Дождаться зелёных этапов тестов и сборки GitHub Actions. Установить APK с прежней подписью поверх существующей установки, без удаления данных. Если подпись отличается, исправить подпись сборки, а не удалять приложение ради эксперимента.

Для Raya и Senemene: включить автоматические тексты, дать аудио запуститься, открыть текст → настройки текста → «Обновить», дождаться результата, затем «Копировать диагностику». В заголовке журнала должны быть `6.62.0-lyrics-hybrid / LRCLIB + lyrics.ovh`. При попадании LRCLIB резерв намеренно не вызывается. При промахе или ошибке в журнале должна появиться попытка lyrics.ovh. Для подтверждённого 404 Senemene нормален результат «не найден», а не искусственно появившийся текст.

Также проверить старый рабочий LRC, импорт, перемотку, быстрое переключение треков, выключенную автозагрузку, отсутствие сети и читаемость пометки резервного текста. Реальный успех fallback нужно проверять на треке, где LRCLIB не нашёл текст, а lyrics.ovh его вернул; один положительный контроль API этого ещё не доказывает. Если Actions упадёт, нужен лог первой ошибки компилятора или теста, а не установка непроверенной сборки.

## Дальнейшее расширение и условия поставщиков

Публичная документация API: https://github.com/NTag/lyrics.ovh . Доступность endpoint без ключа не равна лицензии на коммерческое использование всех возвращаемых текстов и не гарантирует SLA. Короткий RAM-кэш не решает вопросы авторских прав. Для публичного распространения нужно отдельно проверить применимые условия поставщика и права на отображение материалов.

Musixmatch, LyricFind и YouTube Music в этот ZIP не включены: здесь не было проверенного подходящего доступа к их текстам. Не используются извлечённые аккаунтные токены, обходы доступа и недокументированные обещания синхронизации. Следующий разумный этап — измерить дополнительное покрытие на наборе треков, а затем выбирать более сильного поставщика с подтверждённым доступом, метаданными и условиями использования. Архитектура теперь позволяет добавлять адаптеры, но при третьем источнике необходимо пересмотреть приоритеты и суммарные бюджеты.
