# ZiziPlayer 6.69.15 — слияние по GPU-механизму Telegram

28.09.2026. **versionName 6.69.15 / versionCode 140. Полный ZIP исходников, не APK.**
Основа: выданная в этом диалоге 6.69.14 / code 139. Это изменение механизма формы,
а не очередная настройка старой таблицы ширины перемычки.

## Что реализовано

На Android 12+ с аппаратным ускорением основной путь — `CameraGooeyOverlay.kt`.
Изучен `ProfileGooeyView.java` из DrKLO/Telegram, коммит
`dc780e81ed1261c369c27870e8e0999a1eb0b600`. Старый `ProfileMetaballView` не использован.

Камера и обложка получают встречные треугольные заготовки. Выступ камеры имеет
основание шириной h и кончик на h дальше её передней границы; вершина обложки
поднимается на h/4. h растёт от нуля до максимума при p=0.5, затем возвращается
к нулю при p=1. Максимум = ceil(7*density)*3. Для центральной круглой камеры это
та же конструкция заготовок, что в изученной GPU-ветке Telegram.

Камера и обложка записываются в **разные** GraphicsLayer, уменьшаются в 3 раза,
размываются радиусом 15 **пикселей уменьшенного слоя**, затем совмещаются SrcOver.
**После совмещения** применяется единый порог прозрачности: alpha = clamp(51*A-6375)
для A в диапазоне 0..255. Нельзя применить порог к каждому слою по отдельности:
тогда их слабые пересекающиеся края не образуют соединение.

Поверх формирующего силуэт прохода идёт отдельный проход деталей изображения:
размытие нарастает после p=0.2, ограничивается коэффициентом 0.75;
размер промежуточного слоя и затухание цвета следуют коэффициентам reference GPU profile.
Одна исходная обложка записывается один раз на draw и переиспользуется слоями.
Нет повторного Coil-запроса в отдельной перемычке, screenshots, Bitmap readback,
таймеров формы, другого обработчика жестов или булевого решателя Path.op.

Во второй фазе центральная обложка линейно уменьшается к половине диаметра выреза,
центр движется к центру камеры, как в профиле Telegram. Первая фаза размеров/скролла
не менялась. Прежние WAIST/REACH/SWELL не управляют новым GPU-контуром.

## Что адаптировано, а не скопировано целиком

Это реализация механизма внутри Compose, **не побайтовый перенос Telegram и не
заявление о пиксельном совпадении на любом телефоне**. Выбран high-performance профиль
с factor=1 (gooScale=3); Telegram также имеет иной профиль для средних устройств.
Системная геометрия камеры берётся из существующего безопасного адаптера ZiziPlayer,
не из скрытого Android resource config_mainBuiltInDisplayCutout.

Сохранён ограничитель рисования в status bar: вне локального коридора камеры эффект
не закрашивает часы/значки. Для бокового выреза встречные выступы поворачиваются по
оси камера–обложка, а горизонтальное приближение заканчивается раньше. Это расширение
ZiziPlayer: изученный Telegram отбрасывает боковые вырезы в этом эффекте.
Сохранено групповое исчезновение в последних 10% хода, без остаточной точки на p=1.

Промежуточная область рендера фиксирована на весь жест. Она не округляет движущуюся
границу crop каждый кадр. Дробная потреблённая прокрутка из 6.69.14 сохранена побайтно
в CollectionScrollPrecision и PinnedCollectionScaffold. Появление геометрии выреза после
первых insets не переключает composable с изображением на другой экземпляр.

**Android 8–11 / software rendering:** сохранён рендерер 6.69.14 с NonZero-маской.
CPU bitmap-конвейер Telegram в этот выпуск не перенесён; на старом API нет RenderEffect.
При отсутствии подходящего выреза камера не выдумывается: остаётся безопасное сворачивание.

## Проверки и ограничения

Финальный статус команд зафиксирован в `verification/v6.69.15/results.json` и логах.
Локальная математика проверяет реальные production Java-классы, не копию формул на Python.
Новый набор: 2 520 310 утверждений о параметрах, вершинах, масштабировании, фазах,
дробном входе и точном возврате к тому же состоянию; три ошибочные мутации отклоняются.
Эти числа не являются количеством проверенных кадров на телефоне.

Добавлены **7 Android/Compose GPU-тестов**: тонкое первое соединение и его раскрытие,
сохранность обеих сторон тела, удержание/дробный возврат с одним экземпляром обложки,
исчезновение без остаточной точки, реальное размытие деталей, боковая камера и позднее
появление геометрии выреза без перемонтирования изображения.
Инвентарь обязательных instrumentation-тестов: API 28 — 36, API 35 — 45.

Старые контролируемые тесты материала/контура теперь явно вызывают совместимый
LegacyCollectionCoverMorphOverlay: их прежние таблицы яркости не являются эталоном
нового механизма. Тесты настоящего списка/дробного жеста продолжают вызывать обычный
production entry point, то есть новый GPU-путь на API 35. Новые GPU-тесты дополнительно
проверяют диагностический renderer=gooey-gpu; прохождение через fallback не засчитывается.

**Gradle/Kotlin/Android-сборка, APK, instrumentation и реальный Poco здесь не запускались.**
В the Computer нет готового Android toolchain и подключённого телефона. Локальные проверки
и чтение исходников Compose не заменяют эти этапы. Утверждение «дрожание на Poco устранено»
до повторной проверки на устройстве не делается. Нет замеров FPS/GPU времени/энергопотребления.

## Сборка и приёмка

Загрузить ZiziPlayer-v6.69.15.zip в корень своего репозитория: существующий workflow выбирает
проект с максимальным versionCode, теперь 140. Не держать другой отличный ZIP с тем же code.
Дождаться успешной сборки APK; отдельно запустить workflow с `run_camera_tests=true`.
Приёмка Android-тестов должна показать полный инвентарь, а не просто зелёный assemble.

На Poco и втором исправном телефоне проверить медленное вытягивание, первый тонкий контакт,
удержание 3–5 секунд, микродвижение вперёд/назад, отпускание, полное исчезновение и возврат.
Проверить доступные режимы 60/120 Hz. Если сохраняется дрожание — в существующей служебной
диагностике записать движения; новый trace помечен `renderer=gooey-gpu` и содержит h (`tip`).
Запись выключена по умолчанию, остаётся только в памяти, ограничена 240 событиями.

Аудио, БД, сеть, backend и нижняя подложка не менялись. Исторические документы и логи
предыдущих выпусков оставлены; они не подтверждают проверку нового рендерера.
