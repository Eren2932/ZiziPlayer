# ZiziPlayer 6.51.0 — аккаунты: почта/пароль, Google и изолированный сервер

**Статус: кандидат исходников. НЕ собранный APK и НЕ развёрнутый сервис.**
`versionName = 6.51.0`, `versionCode = 101`, `applicationId = app.ziziplayer` без изменений.
База: опубликованный `ZiziPlayer-v6.50.0.zip`, дерево GitHub
`e4938dff99423f0dc68466137648dcd599fb22b7` (14 сентября 2026).

## Что установлено при изучении репозитория

6.50.0 содержит WelcomeScreen/AccountScreen, AccountGate и AccountStore, но вход был выключен
`SIGN_IN_IMPLEMENTED=false`: регистрации, паролей, сессий и синхронизации там нет. Заметка
RELEASE_v6.50.0.md в ZIP побайтово соответствует файлу текущего дерева GitHub. Корневой
STATUS.md на GitHub устарел: начало про 6.37.3, другой сервер и 890 МБ RAM. Его сведения не
приняты за конфигурацию нового VPS со скрина. За основу мобильного кода взят ZIP 6.50.0,
а не старый STATUS. Проект — Kotlin/Compose/Media3, локальные данные Room, отдельный сервер
каталога/резолва; устройство доступа к каталогу не является аккаунтом пользователя.

Скрин тестировщика прочитан: access/refresh, ротация, PEM private/public cert, 15 минут/7 дней,
HttpOnly-cookie/SameSite=Strict, плоский RBAC. Скрин VPS: Ubuntu 22.04, 1 core, 4 GB RAM,
10 GB NVMe; фактическое состояние ОС/памяти/диска и нагрузка не проверялись. Сервер со скрина
не использовался как SSH-цель и не вшит в APK в виде HTTP IP-адреса.

## Реализация

Добавлен `accounts_server/`: реальное RSA/SQLite/WSGI-ядро, отдельная от музыкального сервера
БД, почтовые коды подтверждения/восстановления, Google ID token verifier, rate limits,
RBAC user/admin, шаблоны nginx/systemd/SMTP, генерация ключей и локальное назначение роли.
Access/refresh — JWT RS256, только фиксированный алгоритм и ожидаемые claims. Access 900 с,
refresh абсолютные 604800 с от входа, без продления общего срока ротацией. Повторное применение
использованного refresh отзывает семью, сброс пароля/выход со всех устройств — все семьи.
Текущая роль и отзыв проверяются по БД при каждом доступе: JWT здесь намеренно не stateless.
Плоские права перечислены явно; role из клиента игнорируется при регистрации.

Android получил отдельный AccountRepository (OkHttp без редиректов/авторетраев), сериализацию
сессии, AES-GCM/Android Keystore/AtomicFile/noBackupFilesDir для refresh и access только в RAM.
Куки Secure/HttpOnly/Strict/host-only; секреты не отправляются музыкальному серверу/Google/CDN.
Пароли и почтовые коды не сохраняются в SavedState/SharedPreferences. Вход/регистрация,
подтверждение/повторное письмо, забытый пароль/сброс, выход здесь/везде подключены к API.
Локальная отметка SIGNED_IN из prefs не считается доказательством: при новом Activity нужна
проверка сервиса; при отсутствии связи музыка остаётся доступной гостю. Автоматического
фонового таймера обновления токенов нет: refresh по необходимости восстановления сессии.

Ниже основной формы — Google Credential Manager. Есть nonce сервера и проверка ID token на
сервере, без WebView. Кнопка доступна только с client ID и подтверждённым google_enabled от
сервера. Это выбор Google-аккаунта: Gmail/Workspace. Внешняя почта — обычная регистрация.
Совпадение email не объединяет два способа входа автоматически. Подробные ограничения и
OAuth-настройка: `accounts_server/README.md`.

Адрес сервиса по умолчанию пустой; разрешён только HTTPS-origin без userinfo/query/fragment/path,
порт 443. Без него вход не предлагается, гостевой режим остаётся. Неудачный выход при
отсутствии сети удаляет локальную сессию и сообщает, что серверный отзыв не подтверждён.
Не обещается, что офлайн-выход немедленно отозвал ранее украденный токен.

## Что сохранено и что сознательно НЕ сделано

Код `app/.../player`, `app/.../data`, `app/schemas`, `server/` сверены с базой: производственные
файлы не изменены. База Room версии 10, миграций и удаления локальных данных нет. Не менялись
аудиотракт, эквалайзер, кэш песен, resolver/device-токены и Desktop. Изменения MainActivity
ограничены навигацией/состоянием аккаунта; прежнее воспроизведение не переписано.

**Синхронизации нет.** Вход удостоверяет личность, но не загружает избранное, плейлисты,
историю или аудиофайлы. Тексты 6.50.0, говорившие о будущем переносе как о свойстве аккаунта,
уточнены. Удаление приложения всё ещё удалит локальную медиатеку. Не реализованы явное
связывание Google с существующим email-аккаунтом, смена email, UI удаления аккаунта,
плавная ротация PEM с несколькими активными ключами и гарантированная очередь почтовой доставки.

## Проверки: что именно доказано

У базового 6.50.0 до правок прошёл `tools/check_selftest.py`. После изменений прошли **27 команд**
из `verification/v6.51.0/results.json` с exit 0. Это вложенные группы, **не 27 независимых тестов**.
Среди них прежние регрессии server 1.12/browse/fallback/guard/device/deploy-tools и сравнение
фикстур с исходным сервером; общий preflight; четыре статические проверки Kotlin без замечаний.

Новые серверные **42 unittest-теста** исполняют настоящий код core.py и web.py, реальные RSA
подписи/проверки cryptography, scrypt, SQLite и WSGI endpoint dispatch. Проверены секунды TTL,
expiry boundary, RS256/тип/audience/issuer, контейнер X.509, несовпадающие ключи, single-use
mail codes, reset, concurrent refresh, фиксация отзыва после reuse, live RBAC, session cap,
cookie flags, CSRF/Origin, размер тела, прокси-доверие, общие ответы, одноразовый Google nonce.
В Google-тестах граница внешней проверки подписи подставлена контролируемым verifier:
**они не проверяют действительность токенов Google, сеть Google или настройку OAuth**.

Java AccountGate — **24 исполняемые проверки** (было 17). Новые Android-контракты — **8 тестов
по исходному тексту**, не исполнение Kotlin. Исторический тест 6.41, запрещавший activity-wide
FLAG_SECURE вообще, изменён только для AccountAuthScreen: добавлена проверка восстановления
исходного флага при закрытии формы. Остальные экраны по-прежнему под прежним запретом.
Старые live-version контракты обновлены с 100/6.50.0 на 101/6.51.0; исторические релизы не
переписаны. Логи и список изменённых файлов включены в ZIP.

**Не выполнены:** Gradle/Kotlin/Compose-компиляция, сборка/подпись APK, Android lint,
instrumentation, установка поверх предыдущей версии, real Keystore/Google Play Services,
Google OAuth/JWT verification по живым ключам, реальная SMTP-доставка, nginx/gunicorn/systemd
старт, HTTPS на VPS, нагрузочный тест и визуальная приёмка. В the Computer нет Android SDK,
Gradle и Kotlin compiler; пакеты не устанавливались. Эти проверки нельзя заменить exit 0
статического анализатора. Python-ядро тестировалось на версии из environment.json; для Ubuntu
22.04 отдельно выполнен разбор нового Python-кода с грамматикой Python 3.10, но не исполнение
на Python 3.10 и не установка серверных зависимостей.

## Как продолжить без поломки текущей установки

Развернуть accounts_server отдельно по его README, проверить HTTPS и письма. Настроить Google
Cloud Android client с package `app.ziziplayer` и SHA-1 реальной подписи, Web client ID с тем же
audience на сервере и Android. Никакого private PEM/SMTP password/client secret в GitHub/APK.

В корень репозитория загрузить мобильный ZIP 6.51.0. Существующий CI выбирает максимальный
versionCode, теперь 101. Старый ZIP 100 можно оставить; двух разных мобильных ZIP с 101 быть
не должно. Отдельно обновить корневой `.github/workflows/build.yml` из repo-update: добавлены
только ACCOUNT_URL и GOOGLE_WEB_CLIENT_ID из GitHub Actions Variables. Одного workflow внутри
ZIP недостаточно. Без этих Variables сборка остаётся гостевой и не изображает подключённый вход.

Дождаться Gradle JVM tests и assembleRelease; установить APK с прежним ключом подписи поверх
6.50.0 **без удаления данных**. При ошибке подписи не удалять приложение ради установки.
Пройти `DEVICE_CHECKLIST_v6.51.0.md`; при ошибке компиляции нужен полный build-log.
GitHub и VPS автоматически не изменялись, готового установленного APK в этой поставке нет.
