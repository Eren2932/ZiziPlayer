# ZiziPlayer 6.59.1 — исправление компиляции библиотеки

**Статус: исправленные исходники; сборка APK не подтверждена.**
Версия 6.59.1, versionCode 111. Дата: 15 сентября 2026.

## Основа и устройство проекта

Взята мобильная версия `ZiziPlayer-v6.59.0.zip` из публичного репозитория
`Eren2932/ZiziPlayer`, commit `41c70f52ca72ee6214944923cd306d4bf4f31400`.
Git blob скачанного ZIP совпал с деревом этого коммита.
SHA-256 исходного ZIP: `8dcdd2f606732e4253666b5ba4b707713c141e84781676f63b8b02a0b2695053`.

Проект — Android-приложение Kotlin/Jetpack Compose с Media3, локальной Room-базой,
сетевыми музыкальными каталогами/резолвером, офлайн-загрузками, DSP и текстами песен.
Аккаунты и облачная библиотека используют отдельный сервер; в мобильном ZIP также
сохранены исходники Python-сервисов и их тесты. Desktop — отдельная поставка.
Это обзор структуры и затронутого участка, не полный аудит всего приложения.

## Причина падения

В приложенном логе падает `:app:compileDebugKotlin`, до запуска JVM-тестов.
В `LibrarySync.kt` и `LibraryStorageScreen.kt` используются `error`, `cloudPreview`
и `cloudHash`, которых нет в конструкторе `LibrarySyncState`.
Ошибки вывода типов около `state.cloudPreview?.let` сопутствуют отсутствующему полю;
не требуется заменять Compose-вёрстку или искусственно приводить типы.

В конец конструктора `LibrarySyncState` добавлены:

````kotlin
val error: String = "",
val cloudPreview: LibraryPreview? = null,
val cloudHash: String? = null
````

`error` соответствует существующим вызовам `copy` и `isNotBlank()` в UI.
Предпросмотр имеет фактический тип `LibraryPreview?`. Хеш — `String?`, и именно `null`,
а не пустая строка: UI разрешает восстановление только при `cloudHash != null`.
Поля добавлены после прежних параметров, их порядок и исходные значения не изменены.
Это состояние в памяти, не Room-сущность: миграция базы не нужна.

Не изменены: алгоритмы синхронизации, защита expectedHash, страховочная копия,
транзакционное восстановление, UI, аудиотракт, схема Room, серверы, зависимости,
подпись и workflow. Это узкий buildfix, а не обещание отсутствия остальных дефектов.

## Защита от повторения

В `tools/test_library_6530_contracts.py` добавлены четыре теста: наличие и значения
трёх полей, а также соответствие читаемых UI-полей объявленной модели.
На исходной модели все четыре падают; после исправления все четыре проходят.
Этот файл уже вызывается действующим корневым GitHub Actions workflow.
Проверка намеренно узкая и текстовая, не заменяет компилятор Kotlin.

Добавлены пять Kotlin/JUnit-тестов `LibrarySyncStateTest.kt`: начальное состояние,
сохранение предпросмотра и хеша при copy, ошибка/повторная попытка, новое состояние
подключения и явное обнуление облачных полей. Они проверяют модель, не живую
синхронизацию. Их запуск не выполнен локально и должен пройти в Gradle CI.

Номер приложения увеличен с 110 до 111, имя — с 6.59.0 до 6.59.1.
В десяти прежних контрактных тестовых файлах изменены только ожидаемые номер и имя
версии; функциональные и защитные проверки не удалены и не ослаблены.

## Как применить

Загрузить **`ZiziPlayer-v6.59.1.zip` в корень существующего репозитория main**,
не распаковывая его поверх Desktop. Действующий корневой workflow реагирует на
`ZiziPlayer-v*.zip` и выбирает ZIP по максимальному versionCode. Новый 111 выше 110,
поэтому старый архив можно оставить. `current.json`, Desktop и сервер не обновлять.
Никаких изменений в GitHub из этого диалога не отправлялось.

Корневой `.github/workflows/build.yml` менять не нужно. Его копия внутри ZIP
побайтово совпадает с текущим корневым workflow. Вложенный workflow сам по себе
GitHub не запускает — используется уже существующий workflow репозитория.

Дождаться успешного завершения обязательного шага:

````bash
gradle --no-daemon :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin --stacktrace
````

И затем `:app:assembleRelease` в штатном CI. Компиляция Android-тестов не означает
их выполнения: для них нужен эмулятор/телефон и `:app:connectedDebugAndroidTest`.
Проверить экран сохранения библиотеки: гостевое состояние, подключение аккаунта,
получение предпросмотра, отображение ошибки сети, ручное сохранение и конфликт
изменившейся копии. Восстановление проверять только на тестовой библиотеке после
отдельного экспорта; диалог предупреждает о замене, а не объединении.

## Предупреждения из лога

AGP 8.7.3 предупреждает о compileSdk 36; именно эта сборка дошла до Kotlin-компиляции,
поэтому предупреждение не объясняет наблюдаемое падение. Toolchain не обновлялся
в рамках точечного исправления, предупреждение не скрывалось.

Сообщение об отсутствии SIGNING_STORE_FILE также не причина этого падения.
APK с DEBUG-подписью не устанавливается поверх приложения с другой подписью.
Для обновления установленного приложения нужен тот же ключ, что у текущего APK.
Не удалять приложение ради обхода несовпадения подписей: можно потерять локальную
библиотеку. Секреты подписи в ZIP не добавлялись.
