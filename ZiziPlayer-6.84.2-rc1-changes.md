# ZiziPlayer 6.84.2-rc1 — экран выбора артистов

## База и статус

Полный исходный проект на базе публичного `ZiziPlayer-v6.84.1-rc2-source.zip` (code 180).
Новая идентичность: `6.84.2-rc1`, `versionCode = 181`.
Перед упаковкой повторно прочитан корень GitHub: базовый ZIP и видео побайтно совпадают
с актуальными Git blob SHA из репозитория. Другого более нового мобильного ZIP в корне нет.
Исходники предыдущей работы восстановлены из сохранённой рабочей копии, затем проверены
и доработаны. Room plugin 2.7.1, схема БД, миграции, сервер, Desktop и аудиотракт не менялись.

Это кандидат на проверку, **не собранный APK и не подтверждённый pixel-perfect релиз**.
В the Computer отсутствуют Gradle, Android SDK и эмулятор. Проверки исходников и исполнение
Java-логики не заменяют Kotlin/Compose-компиляцию, реальные касания и замеры на телефоне.

## Что было неправильно

В исходной версии сочетались `decorFitsSystemWindows=true`, ручной `window.setLayout`
с MATCH_PARENT и Compose-отступы `safeDrawing/ime`. Нижняя кнопка находилась внутри
области под схлопывающимся заголовком. Это смешивало владельцев размера окна и отступов.
Скриншот показывает обрезанную кнопку, но точное OEM-поведение исходного APK локально
не воспроизводилось: причина на уровне окна установлена по коду, а не по device trace.

Теперь Dialog edge-to-edge, ручного изменения Window нет. Insets применяются один раз:
`WindowInsets.safeDrawing.union(WindowInsets.ime)`. «Готово» закреплена в нижнем независимом
слое безопасного viewport. Сетка получает нижний запас по реально измеренной высоте этого
слоя. Рост текста, переход заголовка и высота строк больше не добавляются к координате кнопки.

В старом запросе похожие обрезались `.take(6)` до фильтрации выбранных ID и неизменяемого
начала сетки. Если первые шесть уже выбраны/стоят в защищённой строке, новый ряд получался
пустым, хотя в ответе были другие кандидаты. Новый пул — до 25; лимит шесть применяется
после фильтрации. Общие кандидаты разных нажатий резервируются при детерминированном
проигрывании партий в порядке нажатий, независимо от порядка ответов HTTP.

## Референсы: что действительно измерено

Скриншот `image-1.png`: 576×1280. Белая область поиска приблизительно x=25…550,
y=243…304. Белая область кнопки «Готово»: x=200…375, y=1182…1254.
Это границы ярких пикселей, а не Android layout bounds: антиалиасинг и сжатие дают отличие
от полного прямоугольника компонента. Геометрия переводится из reference px в dp один раз
по ширине: `contentWidthDp * referencePx / 1080`. Размеры шрифта остаются sp, системный
fontScale не отключается; на больших шрифтах приоритет — доступность, а не фиксированный bitmap.

Ролик `Screenrecording_20261003_203402.mp4`: 1080×2400, 60 fps, около 12.275 секунды.
В начальном кадре большой текст — «Выберите хотя бы 3 любимых исполнителей»; это
объясняет три строки, в отличие от двухстрочного текста на пользовательском скриншоте.
Повторно извлечены начальные, переходные и конечные кадры. Поиск движется так:

| Время, с | Верх белого поиска, px | Смещение от начала, px |
|---|---:|---:|
| 0.00 | 693 | 0 |
| 0.70 | 642 | 51 |
| 0.85 | 624 | 69 |
| 1.00 | 592 | 101 |
| 1.10 | 529 | 164 |
| 1.20 | 488 | 205 |
| 1.40 | 405 | 288 |

Большой текст смещается приблизительно вдвое медленнее поиска. Маленький заголовок
не ждёт полного исчезновения большого: его прозрачность растёт примерно пропорционально
прогрессу. Большой остаётся почти непрозрачным до ~53%, затем исчезает около ~70%.
Это измеренная аппроксимация по сжатым кадрам, не восстановленный исходный код референса.

В новой реализации обе текстовые раскладки измеряются отдельно, высота шапки интерполируется,
большой текст движется на половину смещения. Состояние и прокрутка вынесены выше переключения
страниц: обычное возвращение из поиска не разворачивает шапку и не сбрасывает список.
Маленький заголовок однострочный при обычном шрифте; при увеличении шрифта перенос разрешён.
Текст/начальная компоновка взяты со скриншота («Выбери любимых исполнителей», две строки),
а характер движения — из видео. Абсолютные координаты поиска в этих двух образцах различны;
поэтому таблица видео не объявляется ожидаемыми координатами новой двухстрочной версии.

На кадре ~7.6 с «Другие рекомендации» — круглая плитка в последней строке, не широкая
OutlinedButton. Сохранённый черновик ошибочно делал широкую кнопку; он заменён круглой ячейкой.
Подпись помещается в две строки без принудительного разрыва слова «рекомендации».

**Про «Подтвердить»:** в исходном HomeTasteSheet.kt именно так называлась кнопка ZiziPlayer.
Приписывать эту надпись ролику оснований не установлено. Новая кнопка — «Готово», как на
пользовательском скриншоте. Прежнее утверждение о серой «Подтвердить» не используется как факт.

## Подбор, поиск и другие рекомендации

Первая страница: 23 артиста плюс круглая ячейка, то есть восемь полных рядов по три.
«Другие рекомендации» сохраняет все выбранные ID, сначала использует невиденных кандидатов
из локального каталога/успешного кеша похожих, затем циклически возвращает предыдущие страницы.
Это ограниченная ротация доступного пула, **не обещание бесконечного нового серверного каталога**.
Когда отличающейся страницы нет, сообщение/повтор находятся внизу, рядом с местом нажатия.
Действие не подтверждает профиль, не сбрасывает выбор и не помечает onboarding завершённым.

При смене страницы токены старых запросов инвалидируются до отмены jobs. Устаревшие ответы
не могут вставить карточки в новую страницу. Одновременно работают максимум два запроса
похожих. При выборе через поиск артист добавляется в начало browse-сетки, поиск закрывается,
выбор сохраняется и используется тот же путь загрузки соседей.

Пустой/неуспешный ответ больше не скрывается: у выбранного артиста есть отдельное действие
«Похожие · повторить». Ошибка не отменяет сам выбор. Пустые результаты не кешируются как успех.
Если `/reco/onboard?a=ID` отсутствует, пуст или не ответил в выделенный бюджет, клиент пробует
существующий `/catalog/similar?id=ID&limit=25`. У него совместимый набор `id/name/art`.
429 не обходится вторым запросом; CancellationException сохраняется. Бюджеты: 3.5 + 4.0 с
внутри внешнего ограничения 8 с. Никакой мировой чарт не выдаётся за похожих.
Состояние живого сервера и ответы для конкретных артистов здесь не проверялись.

Минимум три уникальных артиста, максимум 30, шифрованное сохранение, проверка реальной
музыкальной выдачи и прежняя логика завершения настройки сохранены.

## Проверки

Финальный `python tools/check_selftest.py` завершился с кодом **0** за 184.04 с.
В логе 1003 запусков unittest-кейсов в 100 блоках; это не число уникальных кейсов.
Новый Java-набор выполнил **81 715 assertions**, включая 5000 seeded-сессий.
Дополнительно прошли Kotlin lexical syntax, imports, static refs, проверка аргументов
`app/src/main`, Room guard и шесть проверок ZIP-selector. Ни одна из них не является APK-сборкой.
В `verification/artist-onboarding-6842/` находятся фактические логи и итоговый JSON.
Новый исполняемый Java-тест покрывает первый пул с шестью неподходящими кандидатами,
первые три нажатия с пересекающимися соседями, обратный порядок ответов, артиста из поиска,
выбранного ребёнка графа, страницы и циклическое исчерпание. Дополнительно 5000 seeded-сессий
в 1/2/3 колонках: уникальность ID, сохранность выбора, ограничения размера, стабильный порядок.
Проверки геометрии/прозрачности исполняют production Java, но не рендерят Compose.

Добавлены пять Android UI-тестов к существующему HomeTasteOnboarding6840UiTest:
неподвижный футер при скролле; доступность круглой плитки над футером без подтверждения;
повтор похожих без снятия выбора; возврат из поиска без разворачивания шапки;
доступная кнопка при fontScale=2. Они внесены в inventory API 28/35, но локально НЕ исполнялись.

Старые source-contract assertions обновлены для намеренно изменённых свойств: edge-to-edge,
новое имя кнопки, replayRelatedRows. Проверки минимума выбора, сохранения, доставки музыки,
Room и остальной код не отключались. Общий тест шрифтов дополнительно потребовал явно
сохранить ZiziFontFamily в обеих новых TextStyle; это исправлено в UI, а не удалением проверки.

## Как получить APK и принять результат

Загрузить **сам `ZiziPlayer-v6.84.2-rc1-source.zip`** в корень `Eren2932/ZiziPlayer`.
Не распаковывать в репозиторий и не загружать patch вместо полного ZIP. Существующий selector
выберет code 181; другие файлы с тем же максимальным versionCode создают неоднозначность.
Workflow внутри ZIP сам по себе не заменяет корневой GitHub Actions workflow.
Запустить существующую сборку APK. Для UI-регрессий включить имеющийся opt-in Android tests.

Проверить на исходном телефоне: открытие с 0/1/2/3 выборами; «Готово» целиком выше системной
навигации; медленный drag/fling вниз и обратный ход; поиск с клавиатурой и возврат;
быстрые нажатия на первых трёх артистов; выбор найденного артиста; offline/повтор;
плитку в конце и смену страницы при незавершённых запросах; поворот, жесты/три кнопки,
fontScale 1 / 1.3 / 2. Сравнение записей проводить при одинаковых density и fontScale.
Без этих замеров обещать «пиксель в пиксель на устройстве» нельзя.
