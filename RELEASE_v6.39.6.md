# ZiziPlayer 6.39.6 — исправление двух падений CI

Полный проект на основе ZiziPlayer-v6.39.5.zip из Eren2932/ZiziPlayer.
Версия: 6.39.6; versionCode: 78 (было 77).
Статус: исправленные исходники, офлайн-проверки пройдены. APK здесь не собран.

## Подтверждённые причины и исправления

1. Последний запуск #367, commit 835e4618ba9ff93eaedaa3f127addd7c042a356b:
   compileDebugKotlin остановился на SearchScreen.kt:1218:33 —
   Unresolved reference 'heightIn'. Добавлен отсутствовавший импорт
   androidx.compose.foundation.layout.heightIn. Лог получен из размещённого
   пользователем jvm-test-reports.zip; это ошибка компиляции, не упавший JUnit-тест.

2. Предыдущий запуск: test_group_descendant_is_killed падал с ProcessLookupError
   при чтении /proc/<pid>/stat. Проверка учитывала FileNotFoundError, но не ESRCH,
   возникающий, когда процесс исчезает после открытия файла. Теперь обе ошибки
   означают завершение процесса. Живые состояния не принимаются за завершение;
   ошибки доступа и прочие I/O-ошибки НЕ подавляются. Разбор поля состояния
   учитывает пробелы и скобки в имени процесса.

Добавлены шесть регрессионных Python-тестов для чтения состояния процесса
(они запускаются существующим шагом test_stage2.py) и одна локальная проверка
импорта heightIn в tools/test_live_ui_contracts.py. Последняя не добавлялась
в корневой workflow: для ручного прогона — python3 tools/test_live_ui_contracts.py.
Исходный интеграционный тест уничтожения потомка не отключён, таймаут не увеличен.
Код server/zizi_process.py и планировщика не изменялся.

## Проверки

На Python 3.12.3 и Python 3.14.6 успешно выполнены все 20 команд из
verification/v6.39.6/*results.json. В каждом полном прогоне:
- 156 unittest-тестов, включая серверные и статические UI-контракты;
- дополнительные самостоятельные проверки guard/device/catalog wiring;
- 8 фикстур инструмента проверки Kotlin и все существующие статические проверки.
Число 156 не включает утверждения самостоятельных проверок и повторы стресс-теста.

Stage 2 (37 тестов) дополнительно запускался 50 раз на каждой версии Python:
100 успешных запусков, 3700 выполнений тестов всего. На старом коде имитацией
ESRCH воспроизведено исходное исключение. Новый тест импорта падает на 6.39.5.
Это проверки исходников/Python, а НЕ Kotlin/JUnit, сборка APK или тест телефона.

В the Computer нет Gradle и Android SDK; установка пакетов недоступна.
Поэтому :app:testDebugUnitTest, :app:assembleRelease, R8, подпись APK и поведение
на устройстве остаются НЕ ПРОВЕРЕНЫ для 6.39.6. Старые verification/ и документы
версий сохранены как история, а не как доказательство проверки этой версии.

## Что сохранено

Все файлы исходного 6.39.5 сохранены. В production-коде Android добавлен только
один импорт; отдельно повышена версия сборки. Все изменения дизайна, настроек,
очистки, поиска и медиатеки из 6.39.5 остаются на месте. Зависимости, SDK,
подпись и оба workflow (репозиторий / вложенный) не изменялись. Предупреждения
Node.js 20 и AGP 8.7.3 с compileSdk 36 не были причиной данных падений;
их обновление не смешивалось с этим минимальным исправлением.

## Загрузка

Загрузить ZiziPlayer-v6.39.6.zip В КОРЕНЬ Eren2932/ZiziPlayer, НЕ распаковывая.
Workflow менять не требуется: он выбирает самый высокий versionCode.
Существующий 6.39.5.zip можно оставить: его код 77 ниже 78. Не класть в корень
две копии проекта с одинаковым максимальным versionCode. jvm-test-reports.zip
не является исходниками проекта и пропускается селектором.

Сначала дождаться зелёной сборки main и проверить APK. Затем при необходимости
создать новый релиз v6.39.6 на коммите с новым ZIP; не переиспользовать старый
тег v6.39.5, который указывает на прежние исходники. Подпись использует прежние
секреты CI. Ни репозиторий, ни релизы в ходе подготовки не изменялись.

Точный список изменений и SHA-256 файлов: CHANGE_MANIFEST_v6.39.6.json.
Подробные результаты: verification/v6.39.6/.
