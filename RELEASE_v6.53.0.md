# ZiziPlayer 6.53.0 — облачная библиотека и email-вход

**Статус: кандидат исходников, versionCode 103. Не APK и не проверенный Android-релиз.**
Основа: публичный `ZiziPlayer-v6.52.0.zip` из `Eren2932/ZiziPlayer`, commit
`75acccbd0db80c83bd132fd472cc1995f1b1fee7`, получен 15 сентября 2026.
Корневой workflow отдельно скачан и побайтово совпал с workflow внутри исходного ZIP.
Desktop и музыкальный сервер `server/` не менялись. Развёртывание на VPS и push в GitHub не выполнялись.

## Что сделано в исходниках

Google-кнопка и ветка запуска Google из форм входа/регистрации удалены. Рабочий email/password,
подтверждение почты, повторное письмо, забытый пароль и сброс пароля сохранены. Неактивный
Google backend/SDK оставлен для совместимости: Яндекс ID не добавлен. Настраивать Google для
этой версии не требуется. Существующий экран приветствия показывается на чистой установке;
используется предоставленный в этом диалоге логотип, чёрный фон, регистрация/вход, оранжевый
`#F97316`. Гостевой доступ сохранён. Нового измеренного попиксельного соответствия фото не заявляется.

После подтверждённого входа приложение проверяет библиотеку аккаунта. Старая гостевая
библиотека не стирается: предлагается её привязать. У чистой установки без пользовательских
данных библиотека из облака восстанавливается автоматически. Если обе стороны содержат
изменения, требуется выбор: телефон или аккаунт. **Это замена, не автоматическое объединение.**
Перед локальным восстановлением создаётся внутренняя страховочная копия.

После первичной привязки приложение проверяет/отправляет изменения примерно раз в 15 секунд,
пока Activity находится в состоянии STARTED. Есть «Сохранить сейчас» и дата серверного
подтверждения. При чистой локальной версии изменения другого устройства получаются автоматически;
если изменились обе стороны, синхронизация останавливается для выбора. При потере сети данные
остаются локально и могут быть отправлены следующим проходом после восстановления связи.
Фоновый WorkManager и гарантия отправки после убийства процесса **не реализованы**.

## Какие данные сохраняются

В облако идут метаданные всех 15 таблиц Room v10: записи треков с provider/remoteId/savedAt,
избранное и его тени, плейлисты и порядок треков, связи с каталогом, закрепления на главной,
история поиска/недавнее/прослушивания, скрытые записи, статистика, настройки эффектов треков и
профили эквалайзера. Это включает также вспомогательные записи ранее прослушанных треков.

Именно идентификаторы каталога, а не загруженные аудиофайлы, позволяют восстановить сохранённое
из поиска и главной. Возможность затем воспроизвести трек всё ещё зависит от музыкального
каталога, резолвера и доступности произведения.

Не переносятся аудиофайлы, кэш, пароли, refresh/access tokens, секреты резолвера, Android grants,
общие настройки DataStore (оформление/сеть/глобальный DSP/папки), состояние очереди плеера и
пользовательские файлы обложек. Локальные метаданные сохраняются, но чужие content:// URI при
восстановлении не считаются действующими правами доступа. Если файла на телефоне ещё нет,
остаётся запись `zizi-missing:...`; сканирование не удаляет её связи. После подключения того же
файла стабильный TrackId позволяет обновить путь. Реальную перепривязку MediaStore/SAF нужно
проверить на устройстве. Чужие локальные обложки плейлистов очищаются, HTTPS-обложки сохраняются.

**Защищённые папки:** если FolderVault содержит защищённые папки, экспорт, облачные операции и
восстановление блокируются с объяснением. Это осознанный безопасный предел этой версии:
защищённые данные не должны незаметно появиться в незашифрованной копии. Их шифрованная
межустройственная синхронизация не реализована. Снять защиту можно только осознанно, если
пользователь согласен включить метаданные в обычную копию; это не обязательный совет.

## Защита данных и ограничения

Облачный снимок принадлежит серверному user.id, определённому из проверенной сессии, не из
поля запроса. API библиотеки использует ту же изолированную HTTPS-сессию, CSRF/origin проверки,
ограничения запросов и проверку текущего аккаунта. Запрос библиотеки не может незаметно
переключить владельца внутри общей очереди AccountRepository.

Сохранение использует compare-and-swap по revision. Устаревший снимок не перезаписывает более
новый: ответ 409. Повтор того же снимка после потери ответа идемпотентен. На сервере остаются
две последние генерации; приложение показывает последнюю. Возврат серверной предыдущей
генерации пока не вынесен в UI. Копия — до 8 МиБ UTF-8 и 100 000 строк суммарно, без скрытого
обрезания: превышение возвращает ошибку, существующая облачная копия остаётся.

Локальное восстановление — одна Room-транзакция, проверка фиксированного набора таблиц,
реальных колонок и типов, параметризованные вставки с CONFLICT_ABORT. Страховочная копия
записывается через AtomicFile до DELETE. При автоматическом восстановлении хеш текущих
данных повторно сверяется внутри транзакции: конкурентное редактирование даёт конфликт, а
не потерю изменений. Хеш восстановленного состояния вычисляется до выхода из транзакции,
чтобы последующее редактирование не было ошибочно признано уже отправленным.

Внутренняя страховка только одна, перезаписывается следующим восстановлением и исчезает
вместе с удалением приложения. Её можно экспортировать отдельной кнопкой. Есть обычный экспорт
и импорт JSON через системный выбор файла; импорт требует подтверждения и приостанавливает
автозагрузку в аккаунт до нового выбора. JSON и серверная SQLite-копия не имеют E2E-шифрования:
TLS защищает передачу, администратор сервера потенциально имеет доступ к метаданным.

Локальная медиатека по-прежнему общая для телефона. Выход не удаляет её. При смене аккаунта
имеющаяся библиотека не загружается в другой аккаунт без выбора пользователя. Изолированные
локальные профили и автоматическое слияние конфликтов не входят в эту поставку.

## Что проверено

`accounts_server/tests`: 60 тестов, без FAIL/ERROR — 42 прежних теста аккаунтов, 14 новых тестов
облачного API и 4 теста безопасного установщика. Проверены реальные WSGI-запросы, SQLite,
подписанные тестовые сессии, изоляция двух аккаунтов, отзыв/истечение сессии, CSRF/origin,
повтор потерянного ответа, гонка двух записей, retention двух поколений и payload больше 32 КиБ.
Это локальные тесты, не вызовы настоящего VPS или SMTP.

Чистая production-Java политика выбора библиотеки выполнена через JVM: 46 assertions,
включая перебор 32 комбинаций состояний. 7 новых статических контрактов проверяют подключение
политики, защиту восстановления, границы API и правдивость интерфейса. Общий `check_selftest.py`
завершается с кодом 0. Четыре эвристические проверки Kotlin завершаются без замечаний.
Подробные результаты и команды: `verification/v6.53.0/`.

Старые контракты обновлены только там, где они фиксировали 6.52.0/102, наличие Google UI или
отсутствие синхронизации. Проверки изоляции сессии, шифрованного vault, гостевого доступа,
подписи и конфигурации не удалялись. Новые проверки добавлены в корневой workflow и его копию.

**Не выполнено:** Gradle/Kotlin compiler, APK/R8, instrumentation/Compose rendering, реальное
удаление/переустановка, работа MediaStore/SAF, тест сети с настоящим VPS, массовая библиотека
на Android и измерение нагрузки/батареи. На the Computer нет Gradle, Kotlin compiler и Android
SDK. Исходники требуют зелёной Android-сборки и приёмки на тестовом устройстве до релиза.

## Установка

Сначала обновить сервер аккаунтов по `DEPLOY_ACCOUNTS_1.1.md`. Только ZIP приложения не
добавляет серверное хранение. Затем загрузить `ZiziPlayer-v6.53.0.zip` в корень GitHub main и
заменить **корневой** `.github/workflows/build.yml` файлом из `repo-update/.github/workflows/`.
Не менять desktop/current.json и не распаковывать вторую копию проекта рядом с архивом.
Workflow выберет versionCode 103. ACCOUNT_URL и секреты подписи оставить действующими.
GOOGLE_WEB_CLIENT_ID можно оставить пустым; SMTP/env/ключи не переносить в GitHub.

Установить полученный APK с прежней подписью поверх 6.52.0 без удаления приложения. Первую
проверку переустановки выполнять на тестовом аккаунте/эмуляторе или втором телефоне, не на
единственном экземпляре основной библиотеки. Перед любым удалением экспортировать JSON и
проверить дату подтверждённой облачной копии. Чек-лист: `DEVICE_CHECKLIST_v6.53.0.md`.
