# ZiziPlayer 6.73.0 — отдельные цветовые роли обложки

Дата: 30.09.2026. `versionCode = 156`. Основа: полный ZIP 6.72.0 из этого диалога; предыдущая работа над текстами песен сохранена. Это **исходники, не APK**.

## Что изменилось

Капсула больше не использует цвет обычной панели `surface`, где присутствовало только 16% уже затемнённого тона обложки. Для неё введены самостоятельные `miniPlayer` и `miniPlayerSubtext`. Бирюзовые обложки теперь дают выраженный бирюзовый фон, красные — глубокий бордовый, нейтральные — графитовый, без искусственного оттенка. Это не общее повышение яркости всех цветов.

Большой плеер получает собственную более тёмную цветовую рампу. Шапки альбомов и подборок получают отдельный, более насыщенный тон своей обложки, а не цвет текущего воспроизведения. Оранжевый брендовый цвет кнопок сохранён. Подложки чипов имеют свою приглушённую роль; обычные панели и нейтральные окна не используют цвет капсулы.

При окончательной проверке устранён ещё один риск: маленькая подпись в верхней части плеера больше не накладывается старым серым с прозрачностью 0.85 на новый цветной фон. Для неё используется проверенный непрозрачный светлый тон. Когда тонирование отключено, прежний вид подписи и нейтральная капсула сохраняются. Цвет автора внутри капсулы также рассчитан на новый фон. Геометрия плеера не менялась.

## Как устроен расчёт

Новый `ArtworkSurfaceMath.java` использует существующие кэшированные dominant/deep swatches. Выделение цвета из картинки, формат кэша и его версия не менялись. Дополнительного скачивания или декодирования обложки в кадре нет.

Совместимая теневая выборка может уточнить оттенок dominant, но её влияние плавно исчезает при расхождении hue от 8 до 20 градусов. Чужой оттенок, чёрная тень и почти нейтральный шум не перекрашивают основной цвет. Для очень тёмных входов дополнительно учитывается абсолютный разброс RGB-каналов: один шумный пиксель не превращается в насыщенный фон.

Яркостной запас распределяется непрерывно по linear-sRGB luminance полностью насыщенного исходного hue. Затем отдельно контролируются saturation/value каждой роли. Поэтому бирюзовый может стать светлее, а красный — темнее, без ветвлений по названиям цветов. Верхняя граница относительной яркости поверхностей — 0.125. У верхнего тона плеера также есть нижняя граница около 0.012, чтобы насыщенный синий не исчезал в чёрном.

Плеер имеет 7 остановок градиента с существующими позициями; остановки смешиваются в линейном свете до `#111111`. Сам Compose рисует промежутки штатным градиентом; именно промежуточные RGB-смеси между остановками тоже проверены. Тексты песен продолжают использовать собственную палитру 6.72.0 из исходного dominant, а не из нового бордового/бирюзового фона плеера.

Это собственная калиброванная модель по предоставленным примерам, **не восстановленный закрытый алгоритм референса и не доказательство совпадения для любой обложки**.

## Проверки

На окончательных исходниках повторно выполнены **98/98 зарегистрированных локальных наборов**, без ошибок. Все 4 статических анализатора завершились без замечаний; все 8 самотестов анализатора аргументов прошли. Подробные результаты находятся в `verification/v6.73.0/SUMMARY.json`, batch JSON и логах.

Production Java-код скомпилирован и выполнен: 4096 RGB-входов, 811008 промежуточных образцов рампы, 256 серых значений, 6 вырезок обложек. Проверены детерминированность, непрозрачность, отсутствие провалов яркости рампы сверх допуска 8-битного округления, подавление чужого hue/шума и локальная непрерывность.

Для проверенных поверхностей контраст с `#F6F7F8` и `#E0E0E0` не ниже 4.5:1. Последний реально подключён к подписи капсулы и подписи в верхней части плеера. Это **не сертификат контраста каждого существующего текста/значка приложения** и не проверка отрисовки на устройстве.

Повторить локально из корня распакованного проекта (Python 3 и JDK 17+):

````sh
python3 tools/verify_surfaces_6730.py
python3 tools/check_imports.py
python3 tools/check_kotlin_syntax.py
python3 tools/check_call_args.py
python3 tools/check_static_refs.py
````

В CI сохранён штатный `tools/check_selftest.py`, включая регистрацию двух новых цветовых наборов. Новый portable runner не заменяет Android-сборку.

**Не выполнено:** полная Kotlin/Android/Gradle-сборка, instrumentation и проверка на телефоне. Локально отсутствуют Gradle и Android SDK. Добавлены Android-проверки ролей цвета и переключения палитры, но они не выдаются за пройденные. Они рисуют тестовые цветовые блоки; это не тест полного экрана MiniPlayer.

## Сборка и применение

Загрузить `ZiziPlayer-v6.73.0.zip` в корень публичного репозитория вместо использования старого архива для сборки. Существующий корневой `.github/workflows/build.yml` выбирает ZIP по максимальному `versionCode`; новый код — 156. Workflow в пакете совпадает с сохранённым GitHub-снимком и не изменялся. Второй архив с тем же `versionCode` создавать не нужно. Замена корневого workflow для этой правки не требуется.

Для ручной сборки нужны JDK 17, Gradle 8.11.1 и Android SDK 36 с зависимостями проекта:

````sh
gradle --no-daemon :app:assembleDebug :app:testDebugUnitTest
# При подключённом устройстве/эмуляторе:
gradle --no-daemon :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.ziziplayer.ui.ArtworkSurfaceUiTest
````

На телефоне проверить PASSO, Raya и FUNK ABNORMAL, затем жёлтые/оливковые, зелёные, фиолетовые, тёмные и многоцветные обложки. Проверить смену трека свайпом и кнопкой, сворачивание в капсулу, отключение тонирования, отсутствие обложки, открытие текстов. После проверки телефона можно судить об окончательном визуальном результате, а не только о модели.

## Сохранность и состав

Аудиотракт, очередь, данные, backend, загрузка/кэш обложек, LRC-тайминги и отдельная палитра текстов 6.72.0 сохранены. При упаковке выполняется побайтовая проверка неизменённых областей относительно 6.72.0. Удалённых исходных файлов нет; временные `__pycache__`, `.pyc` и `.class` не поставляются.

Полный архив содержит исходники, тесты, тестовые вырезки, логи, этот отчёт, `SURFACES_v6.73.0.patch` и `SURFACES_v6.73.0_MANIFEST.json`. Патч включает бинарные тестовые фикстуры и рассчитан на чистые исходники 6.72.0; **к полному ZIP применять патч повторно не надо**. Манифест фиксирует хэши до/после, происхождение основы и отдельный хэш патча; сам манифест исключён из самохэширования. Внешний `.sha256` проверяет целиком готовый ZIP.
