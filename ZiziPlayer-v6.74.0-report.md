# ZiziPlayer 6.74.0 — оттенки по контексту обложки

30.09.2026 · `versionCode = 157` · основа: полный публичный мобильный ZIP 6.73.0, code 156.
Это **полный проект исходников, не APK**. Сохранённая работа из предыдущего этапа продолжена, проверена и упакована; она не заменялась старой версией.

## Что исправлено

Яркий жёлто-салатовый блик на обложке PASSO BEM SOLTO больше не обязан определять весь фон. Помимо прежних primary/secondary/deep из того же ограниченного образца пикселей извлекается четвёртый оттенок — умеренно насыщенный средний тон обложки (`body`). Если светлый dominant действительно связан с этой областью, фон опирается на неё. На предоставленных вырезках получается тёмно-зелёная капсула, а не жёлто-оливковая.

Для умеренно насыщенных обложек исправлено применение формулы, рассчитанной на яркие цвета. FUNK MANDALA получает приглушённый сине-фиолетовый верх плеера и капсулу, а не прежний слишком насыщенный тёмно-синий. Цвет плавно уходит к `#111111`, без цветной полки внизу. Отдельно сглажена чувствительность к светлым бликам и размерам миниатюр: проверены прямые выборки и варианты 160/640 px.

Капсула, большой плеер, чипы и шапки обложек используют собственные цветовые роли. Шапка берёт цвет своей обложки, а не текущего трека. Чужой оттенок, прозрачные пиксели и маленькая цветная деталь не должны перекрашивать фон. В production-коде **нет названий треков, таблицы готовых HEX для этих песен или запросов к Spotify**. Это собственная модель, откалиброванная по присланным примерам, а не восстановленный закрытый алгоритм Spotify.

Оранжевые кнопки, нейтральная медиатека и отдельная палитра текстов песен сохранены. Аудиотракт, очередь, данные и серверная часть не менялись. Верхняя подпись плеера получила непрозрачный `#F6F7F8`, чтобы сохранить контраст на более светлом фоне Mandala; подпись капсулы остаётся `#E0E0E0`.

## Кэш и производительность

Формат сохранённой палитры обновлён с версии 2 до 3: теперь в записи четыре цвета. Старые цветовые записи отклоняются и пересчитываются лениво при обычном декодировании обложки. **Чистить данные приложения и заново скачивать всю медиатеку не нужно.** Ключи файлов миниатюр и сведения «нет обложки» не менялись. Новый расчёт выполняется на том же образце до 64×64 пикселей через существующий `Dispatchers.Default` и семафор; дополнительных сетевых запросов или вычислений на каждом кадре нет.

Прежний primary остаётся источником акцентной/lyrics-палитры. Четвёртый цвет влияет только на поверхности. Результат по-прежнему кэшируется на идентификатор обложки; исправление уменьшает расхождение разных образцов, но не является гарантией одинакового результата для любых изображений с одним идентификатором.

## Проверки и ограничения

**100/100 зарегистрированных локальных наборов прошли**, четыре статических анализатора — без замечаний, восемь фикстур анализатора аргументов — без провалов. В финальном продолжении отдельно повторены 11 команд, включая новую математику, прежние цветовые/lyrics-регрессии и статические проверки. Сохранены логи, batch JSON и `verification/v6.74.0/SUMMARY.json`. Наборы выполнялись отдельными зарегистрированными скриптами через portable runner; это не выдаётся за полный запуск Gradle или самого `check_selftest.py` целиком.

Production Java выполнен на 12 288 сочетаниях цветовых ролей и 2 433 024 промежуточных образцах градиента. Проверены 256 нейтральных входов, 64 случайных пиксельных образца, непрозрачность, детерминированность, ограничения размера, альфа, гладкость переходов и подавление постороннего оттенка. Новые 16 фикстур дополнены шестью прежними регрессиями. Проверенный контраст подписи капсулы/поверхностей и верхней подписи плеера — не ниже 4.5:1; это не проверка всех существующих текстов приложения.

**Не выполнены:** Android/Gradle-сборка, Kotlin/JUnit, instrumentation и проверка на физическом телефоне. В the Computer нет Gradle и Android SDK. Java-код скомпилирован с `-source 17 -target 17` на доступном runtime 21; проверка полного Android classpath остаётся за CI. Добавлены Kotlin-тесты упаковки/миграции цветов, расширен Android-тест цветовых ролей, но они не объявляются пройденными.

Повторить локальные наборы с Python 3 и JDK 17+:

## Как собрать и проверить на телефоне

Загрузить **`ZiziPlayer-v6.74.0.zip` в корень GitHub-репозитория**. Сохранённый корневой workflow выбирает единственный архив с максимальным `versionCode`; здесь это 157. Его содержимое совпадает с `repo-update/.github/workflows/build.yml`, менять workflow ради этого выпуска не требуется. Не добавлять второй мобильный ZIP с тем же code 157. Публикация в GitHub из этого диалога не выполнялась.

Для ручной сборки: JDK 17, Gradle 8.11.1, Android SDK 36 и зависимости проекта.

````sh
gradle --no-daemon :app:assembleDebug :app:testDebugUnitTest
# С подключённым устройством/эмулятором:
gradle --no-daemon :app:connectedDebugAndroidTest -Pandroid.testInstrumentationRunnerArguments.class=app.ziziplayer.ui.ArtworkSurfaceUiTest
````

После успешной сборки установить APK с прежней подписью поверх текущего, без очистки данных. Проверить PASSO BEM SOLTO и MANDALA в капсуле/большом плеере/шапке, сначала после показа поисковой миниатюры, затем после перезапуска и открытия большого плеера. Проверить переключение треков, отключение тонирования, обложку без цвета и отсутствие обложки. Дополнительно открыть Raya, старый бирюзовый PASSO, FUNK ABNORMAL и тексты песен. Только такой прогон подтвердит итоговую отрисовку на устройстве.
