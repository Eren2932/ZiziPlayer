# ZiziPlayer 6.60.0 — обложки, шапки коллекций и плейлисты профиля

**Статус: обновлённые исходники с успешными локальными проверками. Полная сборка Android/APK не подтверждена.**
Версия 6.60.0, versionCode 112. База — ZIP 6.59.1, ранее подготовленный в этом диалоге.
Исправление LibrarySyncState из 6.59.1 сохранено. Репозиторий GitHub не изменялся из диалога.

## Обложка и фон

Убраны постоянные синий/фиолетовый цвета у новых экранов коллекций. `CollectionCover`
связывает показанное изображение и его палитру: фон рассчитывается из `art.swatches.primary`
через существующий `ArtworkColorMath.coverTop`, а изображение рисуется из `art.image` того
же результата декодирования. При отсутствии/ожидании обложки оба используют нейтральную
подложку; цвет активного плеера не подставляется вместо цвета коллекции.

Для локального плейлиста приоритет имеет его coverUri, иначе — тот же трек, что в карточке
плейлиста. Для папок/избранного/всех треков используется самый свежий трек полного состава,
а не первый результат поиска/сортировки. Домашние миксы используют обложку показываемого
первого трека, поэтому при смене этого трека меняются и картинка, и палитра.
Алгоритм не ищет специально последний элемент очереди: ориентир — именно показанная обложка.

«Моя волна» имеет процедурную оранжевую обложку, поэтому фон соответствует ей, а не скрытому
треку. Цветная палитра для такой обложки не требует загрузки изображения трека.
Чёрно-белая обложка может дать нейтральный оттенок: окраска не означает искусственную
насыщенность. Алгоритм выбора доминирующего цвета прежний, ограниченный 64×64 сэмплами;
изменено подключение к экранам, не DSP и не общий алгоритм палитры.

## Общая шапка коллекций

Общий `PinnedCollectionScaffold` используется домашними подборками/миксами, локальными
плейлистами, папками, избранным, всеми треками, сетевыми альбомами и плейлистами.

Первая часть движения вверх уменьшает обложку; после исчерпания этого расстояния движется
список. При уходе заголовка появляется закреплённая верхняя панель. Обратно обложка раскрывается
только после того, как список вернулся к началу и отдал неиспользованное расстояние.
Два независимых таймера не анимируют один и тот же скролл. Доля уменьшения и позиция списка
сохраняются для назначения. Play — один экземпляр, перемещаемый по измеренной высоте шапки.
Размеры ограничены шириной экрана; длинный текст влияет на измеренную высоту, а не рисуется
поверх фиксированного отступа. Учтены status bar, мини-плеер/нижняя навигация и короткие списки.

Размеры: максимум — min(66% ширины, 280dp); минимум — 44% максимума, не менее 64dp и не
больше максимума. Дистанция уменьшения равна разнице размеров в пикселях. Появление панели
использует smoothstep на последних 35% пути до закрепления. Это не пиксельная копия Spotify.

Страницы исполнителей не переведены на новую уменьшающуюся шапку. У сетевого исполнителя
только преобразование цвета приведено к тому же правилу; прежняя разметка сохранена.
Полноэкранный плеер, аватар профиля, поиск и его шапка не переделывались.

Сохранены выбор треков, поиск, сортировка, загрузка полного состава и меню трека. Общая шапка
сообщает ArtworkCache о прокрутке, чтобы декодирование проходящих строк не мешало жесту.
У локальных плейлистов очередь получает идентификатор источника; кнопка паузы не захватывает
случайный трек другой подборки. У сетевого каталога кнопка по-прежнему запускает список
с начала — ложная надпись «Пауза» не добавлялась поверх callback запуска.

## Плейлисты в профиле

Справа от «Плейлисты» добавлена кнопка «Изменить». Экран содержит множественный выбор,
«Выбрать все»/«Отменить выбор», фирменные оранжевые элементы и нижнее действие.
«Удалить из профиля» скрывает только карточки. Плейлисты, их состав и аудиофайлы остаются.
«Вернуть скрытые плейлисты» открывает обратный режим с множественным восстановлением.
Новые плейлисты видны по умолчанию. Удалённые/устаревшие выбранные элементы исключаются
из операции по пересечению с актуальным списком.

Видимость сохраняется атомарно в Preferences DataStore. Ключ включает id и createdAt,
чтобы повторно использованный числовой ID не скрывал другой плейлист.
**Это настройка профиля на текущем устройстве**, не публичная серверная приватность.
Она не переносится текущим форматом облачного снимка и не меняет доступ к облачной копии.
Это ограничение явно показано на экране; социальный профиль/подписки не имитируются.

## Общее меню троеточия

Один `PlaylistActionsHost` используется в медиатеке, профиле, экране множественного выбора
и шапке локального плейлиста. Доступны:

- Слушать с начала и перемешать.
- Открыть плейлист: текущие треки, поиск и сортировка.
- Скачать через существующий механизм загрузок.
- Поделиться через существующий PlaylistShareSheet.
- Переименовать.
- Добавить состав в другой существующий плейлист, без перемещения файлов.
- Удалить из профиля или вернуть в профиль.
- Удалить сам плейлист после отдельного подтверждения.

Состав копируется с отсечением дубликатов существующим транзакционным методом. Проверяются
идентичности источника и получателя; копирование в себя запрещено. Скрытые треки/закрытые
папки не выдаются новыми действиями воспроизведения и копирования. При изменении состава
между выбором и записью дополнительно учитывается текущее членство исходного плейлиста.

Удаление проверяет id+createdAt в той же Room-транзакции, что удаляет связи и сущность.
Переименование использует WHERE id AND createdAt. Новые операции не удаляют треки,
избранное, скачанные аудиофайлы или файлы устройства. Во время записи повторное выполнение
заблокировано; отмена coroutine не маскируется как обычная ошибка.

Не добавлены фиктивные «Premium», «Джем», соавторы, публичные права доступа и редактор обложек.
Новые сетевые службы, разрешения, зависимости и Room-миграции не требуются.

## Применение и обязательная приёмка

Перед обновлением сохранить библиотеку в отдельный файл. Загрузить `ZiziPlayer-v6.60.0.zip`
в корень существующего репозитория main, не распаковывая. Штатный выбор источника должен
предпочесть code 112 перед 111/110. Корневой workflow, Desktop, current.json и серверы не менялись.
Копия workflow внутри ZIP не запускается сама: используется существующий workflow репозитория.

Дождаться успешных обязательных шагов:

````bash
gradle --no-daemon :app:testDebugUnitTest :app:compileDebugAndroidTestKotlin --stacktrace
gradle --no-daemon :app:assembleRelease --stacktrace
````

Для выполнения (не только компиляции) Android-тестов нужен эмулятор/устройство:

````bash
gradle --no-daemon :app:connectedDebugAndroidTest --stacktrace
````

Приёмка: 0/1/2/50 треков, смена обложки микса, медленная сеть/отсутствующая обложка,
длинное название, крупный шрифт, 320/360/411/600dp, поворот, быстрый fling в обе стороны,
возврат после глубокого скролла, единственная кнопка Play, выбор и сортировка. Отдельно
проверить, что исполнители не получили новую уменьшающуюся шапку.

Профиль: скрыть несколько плейлистов, перезапустить приложение, убедиться, что они доступны
в медиатеке, вернуть из скрытых. Удаление и копирование испытывать на тестовых плейлистах:
проверить подтверждение, неизменность аудиофайлов и отсутствие дубликатов при повторной копии.
Проверить отказ доступа к хранилищу/ошибку записи и актуализацию выбранного списка.

Для обновления установленного APK нужен тот же ключ подписи. Не удалять приложение ради
обхода несовпадения подписей: это может уничтожить локальные данные.
