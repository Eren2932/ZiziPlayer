# Обновление каталога 1.10-strict-match

Это патч **только слоя сопоставления каталога** из мобильного исходника 6.47.0. `/resolve`, `/stream`, DSP и сервисные секреты он не меняет. Режим строгий по умолчанию; не считается доказательством доступности аудио.

## Что использовать

Полный новый модуль находится в `server/zizi_catalog.py`, diff — в `patches/zizi_catalog.strict.patch`. В комплекте сохранены совместимые вспомогательные модули для запуска тестов. Не нужно заменять все модули сервера подряд: изменяемый runtime-файл — только `zizi_catalog.py`.

Установщик `server/tools/apply_strict_update.py` принимает только точную известную исходную версию (SHA-256 ниже), делает резервную копию и атомарно меняет файл лишь с явным `--apply`. Если у VPS другая версия, он **останавливается**, а не затирает ваши более новые изменения. В этом случае нужен разбор diff на вашей фактической версии; не обходите проверку принудительной перезаписью.

Исходный модуль:
`efa17f59fbc356d27d8534d1adeafe23605af784740d4eb00f3a8914600dfd03`

Новый модуль:
`793fb998252d135e4bd9e1ea3ba17f69799d52af48abfa49fa72036a2145fe55`

## Последовательность

Распаковать комплект **в отдельную рабочую папку**, не поверх `/opt/zizi`. Из корня распакованного комплекта запустить:

````bash
python3 server/tools/test_strict_match.py
python3 server/tools/test_strict_update.py
python3 server/tools/apply_strict_update.py --target /opt/zizi/zizi_catalog.py
````

Последняя команда — проверка без записи. `/opt/zizi` — путь стандартного установщика проекта; если у вас другой каталог, укажите фактический путь.

Перед изменением сделать согласованную SQLite-backup `catalog.db` через SQLite backup API или штатный инструмент резервирования. Для базы в WAL-режиме простое копирование одного `catalog.db` во время записи недостаточно. Путь к базе может отличаться и задаётся существующей настройкой `ZIZI_CATALOG_DB`.

Если проверка признала исходник известным и резервирование завершено:

````bash
sudo python3 server/tools/apply_strict_update.py --target /opt/zizi/zizi_catalog.py --apply
sudo systemctl restart zizi-resolver
sudo systemctl status zizi-resolver --no-pager
````

`zizi-resolver` — имя стандартного unit из установщика проекта; при собственном имени используйте его. Установщик модуля сам **не перезапускает** службы, не обращается к VPS по сети и не меняет базы/секреты. Перезапуск сервиса может прервать активные сетевые потоки — выбирайте подходящее окно.

Проверьте `/catalog/health` обычным авторизованным запросом вашего сервера. Ожидаются `version: "1.10-strict-match"`, `match_policy: 3`, `strict_default: true`. Не выводите bootstrap/device-токены в публичные команды, логи или скриншоты.

Проверьте `/match` с исходным названием, отдельно с явно указанными Slowed/Remix-версиями, а затем повторите те же запросы: кэш обязан сохранять `strict`, `score`, `picked` и `confident`. Для настоящего strict-режима `strict` можно не передавать. `strict=false` существует только как явная совместимость; не используйте его для будущей Волны. Оригинал без уверенного совпадения теперь может вернуть 404 вместо ремикса — это ожидаемое поведение.

## Данные и откат

Таблица `match_proof` создаётся автоматически при первом доступе с прежними правами к каталожной SQLite. Старые `match`/`miss` записи не удаляются, но пространство ключей меняется на `q3` и разделяется по режимам. ISRC не используется как самостоятельный ключ. База может временно вырасти; массовый принудительный прогрев после обновления не нужен.

При необходимости вернуть предыдущую версию: остановить unit, восстановить сохранённый `.before-strict-*` файл `zizi_catalog.py`, вернуть unit в работу и проверить старую версию health. Аддитивная `match_proof` не мешает старому модулю, удалять её для отката не требуется. Сначала выясните причину, если сервис не поднимается; не удаляйте базу каталога как «универсальное исправление».

Проверки в комплекте используют реальные функции матчера и SQLite, но фикстуры upstream и заглушки импорта FastAPI. Они не подтверждают реальные HTTP-вызовы, доступность YouTube, успешный старт аудио или совместимость произвольной иной версии VPS. Деплой на ваш сервер в этом диалоге не выполнялся.
