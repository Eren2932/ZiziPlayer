# Серверное обновление 1.24-alias-rc1 (исходное название записи по ISRC + запасные кандидаты)

Цель: треки, которые есть на YouTube, но подбор выбирает не ту запись (цензурная/перезалив/«Для никого» вместо оригинала).
Клиент: **менять не обязательно**. Старый клиент работает с этим сервером без изменений, но выигрыш от запасных кандидатов (`alts`) появится только после клиентского патча.

Статус: серверные тесты зелёные в песочнице на фикстурах (24 тестовых файла, каждый отдельным процессом, включая `smoke_stage2.py` на заглушках).
**Живой `/match` на VPS не гонялся. Достижимость MusicBrainz с VPS не проверена. Какая из записей «Для никого» цензурная, определено по названию, каналу и длительности, на слух не проверялось.**

## Что в комплекте

| `zizi_match.py` | RULES 6 → 7 | `pick_aliases` (проверка чужих данных: артист, пометка версии, длина в пределах 8 с или 6%); исходное название идёт первым запросом и получает бонус +6; бонус +3 каналу с именем артиста без лишних слов (фан-каналы не получают) |
| `zizi_catalog.py` | 1.24-alias-rc1 | интеграция алиасов; `alts` (до 2 запасных `videoId` того же ранга версии) в `/match` и `/match/deezer`; мягкий кэш 15 мин, если MusicBrainz недоступен; прогрев поиска добирает ISRC из `track/{id}`; `alias_contract` в `/catalog/health` |

## Установка

```bash
mkdir -p ~/zizi-1.24 && unzip -o ZiziServer-1.24.zip -d ~/zizi-1.24

# 1. Проверка. Ничего не пишет.
/opt/zizi/venv/bin/python ~/zizi-1.24/server/tools/deploy_server.py --check

# 2. Бэкап базы (WAL: копировать .db на ходу нельзя).
sqlite3 "$ZIZI_CATALOG_DB" ".backup '/opt/zizi/catalog.before-1.24.db'"

# 3. Установка (откат автоматический, если health не сошёлся).
sudo /opt/zizi/venv/bin/python ~/zizi-1.24/server/tools/deploy_server.py --apply

# Ручной откат
sudo /opt/zizi/venv/bin/python ~/zizi-1.24/server/tools/deploy_server.py --rollback /opt/zizi/server-backups/<папка>
```

Если `--check` пишет `unknown server edit: <файл> (sha256 …)`: на VPS файл правился руками. Не форсируйте, пришлите sha256 и файл.

## Проверка после установки

```bash
H="Authorization: Bearer $T"; B=https://<ваш-хост>
curl -s -H "$H" $B/catalog/health | jq '{version, alias_contract, prewarm}'   # "1.24-alias-rc1", 1, 1
# исходный MusicBrainz-доступ с VPS (если здесь тишина или 503 — алиасы не работают, подбор идёт как в 1.23):
curl -s -A "ZiziPlayer/7.0" "https://musicbrainz.org/ws/2/isrc/RUA1R2100001?fmt=json" | head -c 200
# «Для никого» по Deezer id (подставьте реальный id трека):
curl -s -H "$H" "$B/match/deezer?id=<DEEZER_ID>" | jq '{vid, picked, by, alts}'
journalctl -u <служба> -n 80 | grep -iE 'alias|match'
```

Отключить всё целиком без отката: `ZIZI_ALIAS=0` в окружении службы и рестарт (подбор как в 1.23).
Своя строка User-Agent для MusicBrainz: `ZIZI_ALIAS_UA`. Путь к кэшу алиасов: `ZIZI_ALIAS_DB`.

## Что изменится на проде

- `RULES` 6 → 7: **все старые кэши подбора сбросятся**. Первый тап по ранее прогретым трекам будет холодным.
- Холодный трек получает один запрос к MusicBrainz, около 0,5–1 с. Разово на каждый ISRC (дальше из кэша 30 / 3 суток).
- Если MusicBrainz недоступен, трек играет как раньше, но результат живёт в кэше 15 минут вместо недели.
- Фоновый прогрев при занятом замке отвечает 503 и ничего не кэширует.

## Риски и ограничения

- `alts` сейчас **только лежат в ответе**. Перебор запасных при 404/451 делает клиент, его патч не написан.
- MusicBrainz знает не все ISRC (особенно новые и локальные релизы). Для них поведение ровно как в 1.23.
- Один запрос в секунду к MusicBrainz: при массовом холодном старте очередь прогрева растянется. Автопрогрев главной ограничен 4 треками.
- `smoke_stage2.py` в песочнице шёл на заглушке fastapi/uvicorn. На VPS он идёт в предустановочных тестах на настоящем стеке.
- Ступень 3 (расширение базы потока: `ZIZI_EXTRA`, id вида `yt:<vid>`, строгий фильтр, дедуп с Deezer) в комплект **не входит**.
