## «Моя волна»: что вычищено
`HomeCollectionKind.WAVE` и его ветка в `openCollection`, `WaveArtwork` и оранжевый тон страницы подборки, кнопка запуска
в плитке, поле `HomeFeedState.wave`, константы `WAVE_PLAY` и `TILE_ICON` (иконки служебных плиток тоже ушли).
Ранжированный офлайн-список остался только как полка ленты «Всегда с тобой» (`offlineRanked`), ровно с прежними 12 треками.
Идентификатор источника очереди `home:wave-local-v1` нигде не читается: старая сохранённая очередь с этим id просто играет как обычная.

## Закрепления 6 -> 8
`HomePins.LIMIT = 8` используют DAO (`setPinned`), лист «Закрепления» («Закреплено N из 8»), сообщение о лимите и сетка Главной (`.take(HomePins.LIMIT)`).
Тест держит равенство с `HomeHeaderGeometry.TILES`. Старые данные (до 6 закреплений) укладываются в новый лимит; таблица `home_pins` и миграции не менялись.

## Добор свободных плиток исполнителями
Порядок сетки: закреплённые плейлисты -> остальные плейлисты -> исполнители. Правила в чистой Java `HomeTileFillPolicy`:
- сначала исполнители по давности последнего прослушивания (`play_stats.lastPlayedAt`), затем по давности добавления трека; сортировка устойчива, результат детерминирован;
- один исполнитель - одна плитка, сколько бы треков и «feat.»-записей у него ни было (ключ - главный артист после нормализации);
- заглушки («unknown», «Various Artists», каналы-перезаливщики) плиткой не становятся;
- имя, совпавшее с плейлистом на сетке, пропускается, место добирается следующим исполнителем;
- тап открывает страницу исполнителя тем же путём, что «К исполнителю» в меню трека (`openArtistPage`): каталожный исполнитель - во вкладке Поиска с возвратом на Главную, локальный - в медиатеке с возвратом на Главную.
**Приватность.** Кандидаты берутся из уже отфильтрованного на экране `state.tracks` (скрытое и закрытые папки отрезаны синхронно), в ViewModel добавлена только карта `trackId -> lastPlayedAt` (числа, без названий). Граница не расширена. Если плейлистов 8 и больше, пул не считается вовсе.
Пользователь без плейлистов и без библиотеки по-прежнему видит пустой блок (показывать нечего).

## Навигация: причина и починка
**Причина.** Плитка делала `vm.openPlaylist(id); tab = LIBRARY`. Человек оказывался во вкладке «Медиатека» с открытым плейлистом.
«Назад» закрывала плейлист (`vm.handleBack()`), вкладка оставалась прежней - отсюда «окно медиатеки вместо Главной».
**Починка.** При входе «вглубь» медиатеки с чужой вкладки запоминается вкладка-источник (`libraryOrigin`, переживает поворот и убийство процесса).
Как только медиатека вернулась на корень (любым способом, включая удаление открытого плейлиста), происходит возврат на источник.
Если человек сам перешёл на другую вкладку, запись сбрасывается: медиатека ведёт себя как обычно.
- Решение вынесено в чистую Java `LibraryReturnPolicy.decide(hasOrigin, onLibraryTab, drilledIn)`, чтобы проверять её на JVM.
- «Открыто вглубь» читается из `selection` синхронно (`MainViewModel.isDrilledInNow()`), а не из `library`, который считается в фоне и отстаёт на кадр: иначе при входе был бы ложный мгновенный отскок.
- Охвачены четыре входа: плитка Главной, плейлист из профиля, локальный исполнитель (`ArtistRoute.Local`) и переход из плеера в «Папки».
- Запоминаются вкладка-источник и **глубина** медиатеки при входе: 2 - открыт плейлист/папка/исполнитель, 1 - срез списка («Папки»), 0 - корень.
  Вход вглубь возвращает по состоянию (любым способом). Вход в срез - **только по системной «назад»**: на срезе есть чипы фильтров,
  и тап по чипу «Коллекция» - выбор человека, а не «назад», уводить его с экрана нельзя.
- Стек Поиска (`artistOrigin`), стек Главной (`homeVm.back()`), стек Медиатеки (`vm.handleBack()`) не менялись.
- Позиция прокрутки Главной сохраняется (`SaveableStateProvider` по вкладке).

## Что стоит проверить руками
1. Главная -> плитка плейлиста -> «назад» (кнопка, жест, стрелка) -> Главная, прокрутка на месте.
2. Главная -> плитка -> нижняя вкладка «Медиатека» -> «назад»: остаёмся в Медиатеке (источник сброшен намеренно).
3. Профиль -> «мои плейлисты» -> плейлист -> «назад»: вернётся на вкладку, с которой открывали профиль, а не в сам профиль.
4. Закрепить 8 плейлистов, на девятом - сообщение о лимите; открепить - сетка добирается плейлистами, затем исполнителями.
5. Удалить/скрыть плейлисты так, чтобы их стало меньше 8: свободные места заняты исполнителями, обложки круглые, тап открывает страницу исполнителя, «назад» возвращает на Главную.
6. Скрыть трек или закрыть папку-хранилище: его исполнитель пропадает из плиток сразу, без кадра задержки.
7. Плеер -> меню -> «Папки» -> «назад»: на вкладку под плеером. В «Папках» тап по чипу «Коллекция» остаётся в медиатеке.
