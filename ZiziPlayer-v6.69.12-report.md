# ZiziPlayer 6.69.12 — стабильность контакта обложки с камерой

Дата: 27.09.2026. База: последний мобильный ZIP в полученном снимке публичного репозитория — **6.69.11 / 136**. Новая версия: **6.69.12 / 137**.

**Это полный ZIP исходников, не APK. Android/Gradle-компиляция, instrumentation-тесты и повтор на телефоне здесь не выполнены. Исправление среза справа требует подтверждения на устройстве тестировщика.**

## Что изучено

Мобильный клиент написан на Kotlin/Jetpack Compose; геометрия общей шапки вынесена в Java, воспроизведение и серверные компоненты отделены от UI. Правки ограничены общей анимацией обложек и затемнением под нижним плеером. Аудиотракт, Room, сервер, авторизация и восстановление списка из 6.69.11 не изменены.

Рассмотрены `VID_20260927_180239_929.mp4` (588×1280, 15 с, около 24 кадров/с) и `Screenrecording_20260927_125830.mp4` (1080×2400, 24,7 с, переменная частота кадров). В записи бага виден неполный боковой контур маленькой обложки. Запись сама по себе не позволяет измерить реальное время кадра приложения или доказать конкретный GPU-дефект. Увеличенные кадры сохранены в `verification/v6.69.12/bug-closeup.jpg`.

## Изменения

### 1. Контакт больше не усиливает малое движение так резко

Прежняя таблица раскрывала перемычку от 0 до 1,30 радиуса камеры на интервале расстояния всего 0,06 радиуса. На центральной эталонной геометрии численная проверка production Java дала пик около **11,6 пикселя ширины перемычки на пиксель прокрутки**. Это объясняет чувствительность контакта к целочисленному смещению LazyList и небольшим обратным движениям пальца.

Промежуточные узлы кривой перераспределены; начало контакта, полная ширина 2,62 радиуса, монотонность, непрерывность первой производной и нулевой наклон на концах сохранены. На той же центральной геометрии пик составляет **около 2,4**. Это не замер FPS и не универсальная скорость для всех камер: боковая траектория дополнительно включает горизонтальное движение. В отдельной матрице центральных/левых/правых целей проверяется её ограниченная чувствительность; максимальное значение по этой матрице — 7,20.

Таймеров, пружины, задержки за пальцем, гистерезиса и «мёртвой зоны» нет. Прямой и обратный ход при одинаковой геометрии дают одинаковый результат. Референс сохранён как форма и последовательность эффекта, но чрезмерно резкое начало его старой аппроксимации намеренно изменено.

### 2. Единая отрисовка вместо независимого масштабирования слоя

Убран внешний `graphicsLayer`, отдельно задававший положение и масштаб относительно кэшируемого контура. Трансформация, контур, затемнение и blur теперь вычисляются из одного `Frame` и применяются внутри одного прохода рисования.

Добавлен принадлежащий composable `rememberGraphicsLayer`: содержимое обложки записывается **один раз за проход**, тело и отражённая текстура перемычки рисуют этот явный слой через `drawLayer`. Внутри девятиплиточного отражения больше нет многократного вызова `drawContent()` дочернего Compose-дерева. Это убирает зависимость от повторного размещения дочерних слоёв и разделённой трансформации, подозрительных при наблюдаемом срезе. Без Android-прогона не утверждается, что установлен единственный источник артефакта.

Сохранены один внешний объединённый контур, единичное затемнение, расширенные границы финального fade и защита системных значков. Blur применяется только к записанной текстуре, не к контуру/чернилам. API 26–30 остаются без RenderEffect. Использованные API сверены с исходниками Compose UI Graphics 1.7.6 (BOM 2024.12.01); это проверка API, не замена компиляции.

### 3. Затемнение под нижней капсулой: 65% → 80%

Изменён максимум чёрной подложки `CollectionGeometry.scrimAlpha`, то есть +15 **процентных пунктов**. Светопропускание в максимуме теперь 20% вместо 35%. Плавный градиент, прозрачное начало, непрозрачность текста/кнопок, поверхность и размеры самой капсулы сохранены. Это нижняя подложка интерфейса, не затемнение обложки у камеры.

## Как применить и закрыть проверку

Загрузить **`ZiziPlayer-v6.69.12.zip` в корень репозитория**. Текущий корневой workflow уже совпадает с вложенным и выбирает полный проект по максимальному `versionCode`; менять workflow для этой версии не требуется. Не создавать второй архив с тем же code 137. Обычный push запускает независимую сборку APK.

Для Android-регрессий дополнительно запустить **Actions → Build & release ZiziPlayer APK → Run workflow → `run_camera_tests = true`**. Они остаются отдельной задачей и не блокируют job сборки APK — успешная сборка сама по себе НЕ означает успешные пиксельные тесты.

На исходном телефоне тестировщика проверить медленное касание, микродвижения вверх/вниз в точке контакта, полное поглощение и обратное раскрытие, быстрый fling, а также уход со страницы и возврат при свёрнутой шапке. Проверить правый край маленькой обложки и подложку нижнего плеера. До этого повторного теста обещать отсутствие артефактов на всех OEM/GPU было бы некорректно.
