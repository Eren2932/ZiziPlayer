# ZiziPlayer Reco 2 — сохранённое состояние 6.83.0-rc1

## Статус
RC/WIP исходники, НЕ проверенный Android-релиз. APK не собран. Не заменять ими production без CI и проверки на устройстве.
Мобильный ZIP содержит полный проект без временных копий. Серверный ZIP содержит тот же server/ из мобильного ZIP.

## Что есть в коде
- Профиль: избранное, слушания/ранние пропуски, сохранённая медиатека, плейлисты, открытые артисты/треки поиска, выбор артистов при знакомстве; логарифмический вес; до 30 сидов.
- Очистка заглушек и хвостов каналов; исправлена нормализация русских заглушек (й → и при NFD).
- Кэш соответствий имя → ID Deezer, чтение seeds[] ответа сервера; дополнительные поля s2 и h с лимитами старого сервера.
- RecoVault: AES-GCM, AndroidKeyStore, noBackupFilesDir, AtomicFile; снимок главной до 48 часов, проверка скрытых треков и закрытых папок.
- Интеграция сохранённого снимка главной, фильтр уже сохранённых треков и «не нравится» для полок/ленты.
- Обложки Deezer нужного размера, очередь 4 загрузки для небольших картинок (включая 480px карточки), склейка URL-запросов, ограниченная предзагрузка карточек.
- Ожидание аудио только при подключённом контроллере, с ограничением времени.
- Экран настройки вкуса: минимум 3 артиста, поиск, похожие артисты, «Позже», повторное открытие с главной.
- Меню: «Не нравится трек» и «Не рекомендовать исполнителя».
- Названия треков для уточнения исполнителя отправляются ТОЛЬКО после отдельного согласия в настройке вкуса; по умолчанию выключено.
- Заголовок «Быстрый доступ / Закрепления» перенесён перед сеткой.
- Сервер: два шага related-графа, поправка на популярность сцены, агрегатная CoStats, ID по подсказке, SWR ответа, GET /reco/onboard, до 40 отрицательных артистов.
- tools/reco_eval.py: офлайн artist Recall@K/NDCG@K/coverage с запретом пересечения train и heldout. Он принимает уже полученные ранжирования; не снимает автоматически события с телефона и не доказывает попадание во вкус.

5. Собрать реальные holdout-данные и обратную связь тестеров, затем настраивать веса. Введённые коэффициенты — стартовая эвристика, а не доказанный оптимум.

## Что НЕ реализовано из расширенного плана
- Раздельные кластеры вкуса/станции по Jaccard или иной кластеризации.
- Совместные появления в РЕАЛЬНЫХ плейлистах Deezer. CoStats сейчас опирается на наборы артистов профиля/графа, это НЕ готовая playlist collaborative filtering.
- Серверный /img?w=... с ресайзом, пул соединений и проверка редиректов прокси. Размеры Deezer меняются на клиенте; сам img-прокси ещё прежний.
- Произвольные введённые текстовые поисковые запросы не превращаются в подтверждённый вкус: учитываются открытия артистов/треков. Не угадываем артиста из любого запроса.
- Точные ID для всех YouTube/локальных артистов не гарантированы; разрешение по имени/подсказке по-прежнему может ошибаться на тёзках.
