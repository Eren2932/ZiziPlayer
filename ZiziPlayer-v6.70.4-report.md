# ZiziPlayer 6.70.4 — адаптивные углы панели плеера

Дата: 29.09.2026. `versionCode = 150`. Полный ZIP исходников, **не APK**.
База: последний мобильный архив `ZiziPlayer-v6.70.3.zip` из публичного репозитория
`Eren2932/ZiziPlayer`, снимок `179d2745f21a8ce2919c17c266f503d4c88d2513`.
SHA-256 исходного архива: `853890b266d87b1fc28569b07656c7d2d0b270aa50c3cc996653f1dfebed91ce`.

## Контекст и исправление

Мобильный клиент — Kotlin/Jetpack Compose, Media3, Room, DataStore; в комплекте
также находятся Python-сервисы музыки и аккаунтов. Полноэкранный плеер живёт отдельным
слоем MainActivity поверх текущего экрана. Его закрытие уже обслуживают общий slide,
вертикальный dragOffset и существующая политика «Назад». До этой правки внешний слой
имел только translationY: ни фон, ни содержимое не обрезались по округлому контуру.

Теперь один graphicsLayer одновременно получает прежнее смещение и общий округлый
контур. В маску попадают и ZiziBackdrop, и весь PlayerScreen. Радиус напрямую зависит
от текущей позиции; отдельного таймера или догоняющей анимации нет. Поэтому свайп,
отмена свайпа, стрелка закрытия, системное «Назад» и повторное открытие используют
одну и ту же геометрию. Полностью раскрытый плеер не получает новых программных вырезов.

Логика жестов, длительности анимаций, профиль/его прокрутка, аудиотракт, экран плеера,
базы данных, коллекции, эффект камеры и серверы не изменены. Это не общий аудит проекта:
изучены структура и связанные с исправлением участки.

## Откуда берутся углы

На API 31+ читаются четыре независимых `WindowInsets.getRoundedCorner(position).radius`:
верхний левый, верхний правый, нижний правый, нижний левый. Значения уже выражены в
пикселях; повторного умножения на плотность нет. Левый и правый углы не зеркалятся в RTL.
Изменение Insets, размеров/поворота окна и Compose Configuration обновляет данные.
Наблюдатель не заменяет Insets-listener Compose и удаляется при размонтировании панели.

Нулевой или отсутствующий угол на API 31+ сохраняется квадратным. Если прошивка не
предоставляет данные, отличить это от настоящего квадратного дисплея достоверно нельзя:
в этой версии такой случай не заменяется придуманным радиусом. До API 31 применяется
явный резервный дизайн 28 dp с ограничением по фактическому размеру слоя. Это не
измерение устройства и не обещание точного соответствия корпусу.

Вырез камеры/чёлка — другая геометрия; он не используется вместо внешних углов дисплея.
Полное совпадение с произвольной неокружной формой угла, неточными OEM-данными либо
устройством без публичных данных гарантировать невозможно. Даже корректный RoundedCorner
описывает радиус, а не полный физический контур панели.

## Математика

Сначала четыре исходных радиуса пропорционально уменьшаются, только если сумма двух
соседних радиусов превышает соответствующую ширину/высоту слоя. Асимметрия сохраняется;
неправильного независимого ограничения каждого угла половиной ширины нет.

Для полученных целевых радиусов R и текущего смещения y:

- t = clamp(y / max(1 px, max(R)), 0, 1);
- s = 3t² − 2t³;
- rᵢ(y) = Rᵢ × s.

При y = 0 программный радиус равен нулю; после смещения на максимальный целевой
радиус все углы достигают своих целевых значений. Производная по y равна нулю
на обоих концах перехода. Контур непрерывен, монотонен и не зависит от направления
движения. NaN, бесконечные и отрицательные входные радиусы не попадают в отрисовку.

## Что действительно проверено

Полный `python tools/check_selftest.py` завершился с кодом **0** за 126.93 секунды:
70 unittest-прогонов, суммарно **639 тестов**, а также исполняемые Java-проверки
и фикстуры существующего набора. Количество Java-утверждений не выдаётся за отдельные
Android/JUnit-тесты.

Новый Java-набор выполняет реальный production-код геометрии: **130 141 утверждение**,
включая 20 000 воспроизводимых случайных случаев. Проверены крайние размеры, асимметрия,
нулевые углы, плотности, обратный ход, концы интерполяции и некорректные входы.
Три намеренно внесённые поломки (линейная интерполяция, подмена левого угла правым,
отключение нормализации размеров) отвергаются тестами после успешной компиляции.

Проверки Kotlin-скобок/строк, импортов, аргументов вызовов и статических ссылок прошли.
Они **не заменяют компиляцию Kotlin**. Логи и машинные результаты находятся в
`verification/v6.70.4/`; исходный diff — `PATCH_v6.70.4.diff`.

Добавлено **6 Android-тестов**, включённых в существующий opt-in CI:
три теста production-слоя/Compose-контура (пиксели всей панели, обновление состояния,
RTL/плотность) и три теста публичного Android-адаптера Insets. Тестовый Builder
создаёт независимый контейнер углов, чтобы не изменять общий объект AOSP.
Эти Android-тесты здесь **не запускались**. Итоговый инвентарь CI: 72 метода на API 28,
96 на API 35; прежние методы сохранены.

В the Computer отсутствуют Gradle, Kotlin compiler и Android SDK. Поэтому APK,
полная Android-сборка, GPU-анимация, реальные события поворота/resize и физический
телефон не проверены. Проверки пикселей и точности на устройстве ещё обязательны;
заявления «без багов на любом смартфоне» эта поставка не делает.

## Применение

Загрузить `ZiziPlayer-v6.70.4.zip` целиком в корень репозитория. Существующий корневой
workflow побайтно совпадает с вложенным и выбирает максимальный versionCode — 150.
Заменять workflow или распаковывать отдельные файлы в корень не требуется. В репозиторий
ничего автоматически не отправлялось; сервер обновлять не нужно.

После обычной сборки запустить opt-in Android-проверки (`run_camera_tests=true`) и
ручную приёмку из `DEVICE_CHECKLIST_v6.70.4.md`. Для обновления установленного приложения
APK должен быть подписан тем же ключом, что и предыдущая версия.
