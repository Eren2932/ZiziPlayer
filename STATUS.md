## 3. Текущая архитектура

```
поиск/рекомендации:  APP ──Innertube──> music.youtube.com          (работает всегда)

воспроизведение:     APP ──/resolve|/stream──> VPS 147.45.166.244:8080
                                                 │
                                    ┌────────────┴─────────────┐
                              прямой путь                 прокси-путь
                          (IP сервера, RU-паспорт)     (xray → VLESS, US/NL/EE/FR)
                          бот-чек ПРОХОДИТ             гео ЧИСТОЕ
                          часть треков → 451           часть узлов → бот-чек
```

Правило маршрутизации (ZiziResolve 1.2, `ZIZI_PROXY_MODE=fallback`):

1. резолв напрямую;
2. отказ `451 / 404 / 402 / 502` → повтор того же трека через прокси;
3. отказ `403` (бот-чек) → на прокси **не** идём, прямой IP тут сильнее;
4. трек, добытый через прокси, помечается `via=proxy`, и `/stream` для него тоже
   идёт через прокси (googlevideo привязывает ссылку к IP запросившего → иначе 403);
5. приговор пользователю берётся с **прямого** пути (он честнее по формулировке).

## 4. Ключевые технические факты (грабли, на которые не надо наступать снова)

1. **IP сервера геолоцируется Google как RU.** Нода в Амстердаме, но диапазон Timeweb
   российский: в ссылках `&gcr=ru`. Отсюда `The uploader has not made this video
   available in your country` на части треков.
2. **`--xff US` / `geo_bypass` не работает.** Google закрыл трюк с `X-Forwarded-For`;
   в ответе он сам пишет `You might want to use a VPN or a proxy server (with --proxy)`.
   В 1.2 `geo_bypass` отключён — только тратил время.
3. **yt-dlp требует JS-движок И скрипты решателя.** Одного Deno недостаточно:
   без пакета **`yt-dlp-ejs`** валится `n challenge solving failed`, часть клиентов
   отдаёт плеер без форматов, и это выглядит как «This video is not available» /
   «Error code: 152 - 18», хотя трек доступен.
   **Установка `yt-dlp-ejs` починила 4 из 5 «мёртвых» треков.**
4. **IPv6 нельзя использовать.** YouTube душит IPv6-диапазоны ЦОДов. Нужны
   `source_address 0.0.0.0` (yt-dlp) и `local_address="0.0.0.0"` (httpx).
   Симптом утечки в IPv6: `mip=2a03:...`, `ipbypass=yes`, цепочка из 3 редиректов, задержка.
5. **Кэши yt-dlp для прямого и прокси-пути должны быть разными** (`ytdlp-cache/direct`,
   `ytdlp-cache/proxy`), иначе visitor-данные с RU-паспортом утекают в прокси-запрос.
6. **Коммерческие VPN-узлы часто в бан-листе Google.** Проверено на подписке из 38 узлов:
   `NL / EE / US / FR — чистые`, `DE (50.7.157.246) и LV — бот-чек`.
   Узлы с пометкой `| RU` в названии выдают российский IP — брать нельзя.
7. **`--workers 2` у uvicorn = два независимых процесса**, у каждого свой кэш, свои
   приговоры и своя статистика. `/stats` показывает один из двух, кэш работает вполсилы.
   Нужен `--workers 1`.
8. **Deno падает по OOM.** `Out of memory: Killed process (deno) total-vm:18145620kB`
   при 4 ГБ RAM и нулевом свопе. Симптом: «то играет, то не играет».
   Лечится свопом 2 ГБ + `DENO_V8_FLAGS=--max-old-space-size=256`.

## 7. Незакоммиченные правки (применены на сервере, нет в ЗИПе)

1. `classify()`: шаблон гео расширен до `"in your country" in m` — прежний
   `"not available in your country"` не ловил реальный текст YouTube
   `not **made this video** available in your country`; плюс `"error code: 152"`.
2. `RETRY_VIA_PROXY = (451, 404, 402, 502)` — 502 добавлен, иначе неопознанные
   отказы не уходили на прокси-путь.
3. `pip install -U "yt-dlp[default]" yt-dlp-ejs` — решатель JS-челленджа.
4. Своп 2 ГБ + `DENO_V8_FLAGS=--max-old-space-size=256`.
5. `--workers 1` в systemd-юните.

**Всё это нужно перенести в `zizi_resolver.py` и в `install-zizi-resolver.sh`.**

## 8. Следующие шаги, по приоритету

1. **Замер покрытия.** 15–20 случайных id из живой очереди → `/resolve` → посчитать
   доли `via=direct` / `via=proxy` / отказ. Это единственный честный критерий
   «выпускать релиз или нет».
2. **Проверить, что прокси-фолбэк реально срабатывает:**
   `journalctl -u zizi-resolver | grep 'via proxy'` после запроса гео-блокнутого трека.
   Если строки нет — разбираться с `.env` / `_routes()`.
3. **Сбрасывать негативный кэш после любых изменений** (`/flush?neg_only=0`), иначе
   приложение получает приговоры, вынесенные до починки. Уже наступали.
4. Если покрытие низкое — **куки левого Google-аккаунта** (`ZIZI_COOKIES`):
   снимает бот-чек в том числе на прокси-узлах. Минус: аккаунт со временем забанят.
   Альтернатива без аккаунта — `bgutil-ytdlp-pot-provider` (`ZIZI_POT_URL`).
5. Мониторинг: `/stats` + алерт на рост `share_failed_pct`.
6. Долгосрочно: держать Audius как второй источник воспроизведения — он не зависит
   ни от Google, ни от гео.

## 9. Честные ограничения, которые не лечатся кодом

- Часть треков закрыта правообладателем для RU (и иногда почти везде). Это лицензии,
  а не техника: ни прокси, ни куки, ни архитектура тут не помогут.
- Схема нарушает ToS YouTube. Репозиторий теоретически может получить жалобу.
- yt-dlp — гонка с Google. Именно поэтому резолв вынесен на сервер: там экстрактор
  обновляется ночным кроном силами сообщества, а не пересборкой APK.
