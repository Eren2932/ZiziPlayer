# Приёмка 6.54.0 / Accounts 1.2 на устройстве

**До этой приёмки сборка — кандидат. Не удаляйте основную установку ради теста.** Сначала экспортируйте текущую библиотеку в отдельный JSON и сохраните файл вне данных приложения.

## Сборка и внешний вид

Дождитесь зелёного GitHub Actions (версия 6.54.0, код 104), установите APK с прежней подписью поверх текущего. Проверьте главную гостя и вошедшего пользователя, аватар, меню, переходы в историю, профиль, плейлист и настройки. Настройки из медиатеки и меню должны открываться одинаково. Мини-плеер и нижняя навигация работают под профилем/настройками; редактор фото закрывает их.

Проверьте поиск настроек по «имя», «аватар», «экспорт», «офлайн», «качество». Системное «назад» из раздела/поиска возвращает к разделам, затем закрывает настройки. Переключатели Wi-Fi/кэша отражают фактическую настройку и сохраняются после перезапуска. Нет несуществующих Premium и социальных функций.

Снимите скриншоты на ширине 360/393 dp и при увеличенном системном шрифте. Сравните пропорции аватара и отступы с таблицей RELEASE_v6.54.0.md. Исходные измерения не заменяют проверку реального рендера.

## Профиль

Убедитесь, что health объявляет 1.2.0/profile_enabled. Измените имя на кириллице и выберите фотографию с EXIF-ориентацией. Сохраните, закройте/откройте профиль, перезапустите приложение и войдите на втором тестовом устройстве. Фото/имя должны совпасть. Удалите фото — должна вернуться буква и прежний цвет. Несохранённые изменения при закрытии требуют подтверждения; черновик при пересоздании Activity может потеряться.

Откройте редактор на двух устройствах: после сохранения разных правок первое обновление второго должно получить конфликт, не затереть новое имя. При потере сети не должно появляться ложного успеха. На Accounts 1.1 библиотека должна работать, но изменение профиля должно требовать обновления сервера. Не менять основной аккаунт ради этого теста.

## Реальная запись библиотеки — ключевая проверка

На тестовом аккаунте добавьте три сохранённых трека каталога, два избранных и плейлист с порядком треков. Откройте «Облачная библиотека» → «Проверить облако» → «Использовать библиотеку телефона», подтвердите замену. Дождитесь даты **«Подтверждено сервером»**, проверьте сводки.

Добавьте ещё один трек/измените порядок. Нажмите «Сохранить сейчас». На втором устройстве с пустой тестовой библиотекой войдите в тот же аккаунт и проверьте восстановление, порядок, избранное и возможность воспроизвести доступные записи каталога. Именно второй независимый клиент подтверждает полный цикл — health и дата сами по себе недостаточны для проверки всей Android-цепочки.

Отключите сеть перед первым подключением облака, затем верните её и подержите приложение открытым больше минуты. Подключение должно повториться. После ошибки ручное «Сохранить сейчас» должно выполнять попытку сразу. При 413 сообщение различает ограничение самой копии и nginx. При конфликте двух устройств автосохранение приостанавливается и требует выбора.

Выход не стирает локальную медиатеку. При входе в другой тестовый аккаунт данные первого не должны автоматически отправляться без выбора. На телефоне нет изолированных локальных библиотек по пользователям — это текущее ограничение, не обещание приватных профилей.

Локальные аудиофайлы не скачиваются из аккаунта: подключите их отдельно. При защищённых папках экспорт блокируется с объяснением. Проверку удаления/переустановки выполняйте только на тестовом устройстве после успешного восстановления и резервного JSON, не на единственном экземпляре своей коллекции.

Если реальный экспорт всё ещё не проходит, сообщите версию APK, точный текст ошибки на экране, примерное количество треков/плейлистов и время попытки. Пароли, коды, токены и библиотеку целиком присылать не нужно.
