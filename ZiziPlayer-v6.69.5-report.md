# ZiziPlayer 6.69.5 — исправление компиляции Android-теста камеры

Исходники для CI, **не APK и не подтверждённая Android-сборка**. VersionCode: **130**.
Основа: `ZiziPlayer-v6.69.4.zip` (code 129) из публичного репозитория
`Eren2932/ZiziPlayer`, commit `0314b49c866bfdae6b30407f50d6946c18c77142`.
SHA256 исходного ZIP: `adcf8c56a9edbd56d0ceb0c9dcf26dfd8eda882192c287ce6c76c1918afbb531`.

## Причина падения

Архив `jvm-test-reports (3).zip` содержит только `unit-tests.log`, а не XML-результаты
завершённых JVM-тестов. В нём основная Kotlin-компиляция и Java-компиляция проходят,
после чего падает `:app:compileDebugAndroidTestKotlin`:

````text
CameraMorph6692UiTest.kt:218:82 Unresolved reference 'testTag'.
````

Новый тест `topAttachedReservationRendersConnectedNeckBeforeArtworkDisappears`
вызывает `Modifier.testTag`, но импортирует только `androidx.compose.ui.test.*`.
Расширение находится в **другом пакете** — `androidx.compose.ui.platform.testTag`.
Добавлен явный импорт. Тест не удалён, его assertions не ослаблены, CI не обойдён.
Предупреждения про deprecated API, debug-подпись и AGP/compileSdk не являются
причиной этого падения. Из исходного лога нельзя заключить, что JVM-тесты прошли.

## Защита от повторения

`tools/check_imports.py` теперь учитывает переданный корень исходников: раньше он
молча использовал `app/src/main/java` независимо от аргумента. В небольшой список
проверяемых библиотечных имён добавлен `testTag`. При проверке полного имени импорт
с alias больше не принимается за употребление полного имени в исполняемом коде.
Проверка по-прежнему эвристическая и **не заменяет Kotlin-компилятор**.

Добавлены 9 регрессионных тестов `tools/test_imports_6695.py`: все три source set,
правильный/неправильный wildcard, явный импорт, alias, строки и комментарии, аргументы
CLI, исходный Android-тест и его мутация без исправляющего импорта, сканирование
реального `app/src`. Удаление импорта из копии настоящего теста даёт ненулевой код
завершения и нужную диагностику.

Набор подключён в начало `tools/check_selftest.py`, который уже вызывает корневой
workflow. Поэтому достаточно загрузить **только новый ZIP**. Workflow внутри ZIP,
его копия в `repo-update/` и корневой workflow репозитория не изменены.

## Сохранённая функциональность

Все файлы `app/src/main/` побайтово совпадают с 6.69.4. Не менялись геометрия,
отрисовка шейки, фильтры DisplayCutout, фон статус-бара, воспроизведение, Room,
аккаунты, серверы и зависимости. В Gradle изменены только versionCode/versionName.
Это отдельное исправление сборки, а не новый визуальный эксперимент.

По структуре проекта: Android-клиент на Compose, ViewModel/Flow; Media3-сервис и
контроллер воспроизведения; Room/DataStore для локальных данных; отдельные подсистемы
каталогов/резолвера, аккаунтов/синхронизации и текстов. Слияние общей шапки разделено
на чистую Java-геометрию, Android-адаптер выреза и Compose-overlay. Такое разделение
позволяет тестировать математику отдельно, но не доказывает правильность пикселей
на конкретной прошивке. Это обзор затронутых слоёв, не полный аудит всего проекта.

## Проверки и ограничения

**28/28 проверочных команд завершились с кодом 0** (включая полный preflight и
офлайн-набор серверных проверок из CI). Это число команд, не число Android-тестов.
Актуальные результаты и коды завершения: `verification/v6.69.5/results.json`;
регрессия импортов отдельно: `imports-regression.log`.
Полный preflight прошёл, включая 7 тестов камеры, **463009 численных утверждений
над production Java-геометрией** и отклонение всех **8 контрольных мутаций**.
Статические проверки Kotlin, импортов и вызовов также прошли.

В the Computer доступны Java и Python, но нет Gradle, Kotlin CLI, Android SDK и
эмулятора. Поэтому здесь **не выполнены** `testDebugUnitTest`,
`compileDebugAndroidTestKotlin`, `connectedDebugAndroidTest`, `assembleRelease`/R8
и установка APK. Успешный локальный preflight не означает успешную Android-сборку.
Попиксельное совпадение с физическим отверстием камеры vivo не подтверждено.

## Применение

Загрузить `ZiziPlayer-v6.69.5.zip` в **корень main**, не распаковывая.
CI выбирает максимальный versionCode: 130 выше прежнего 129, поэтому старый ZIP
не мешает. Не держать два мобильных ZIP с одинаковым максимальным code 130.
**Корневой `.github/workflows/build.yml` менять не нужно.** Репозиторий автоматически
не обновлялся; коммиты и релизы из этой работы не публиковались.

Дождаться компиляции Kotlin/Android-тестов, JVM-тестов, затем instrumentation на
API 28 и API 35 и сборки release. После зелёного CI установить APK с прежней
подписью поверх текущего приложения, без очистки данных. Проверить медленное
сворачивание/раскрытие подборки, промежуточную шейку, отсутствие верхней полосы,
кнопки Back/Play. Если падение уже на эмуляторе — нужен соответствующий
`camera-collection-api-*` артефакт: это следующая стадия, не прежняя ошибка импорта.

Предупреждение AGP 8.7.3 / compileSdk 36 стоит устранить отдельным обновлением
совместимой пары AGP/Gradle, не смешивая миграцию сборочной системы с этим hotfix.
На будущее полезно хранить Android-исходники непосредственно в Git, а ZIP выпускать
как артефакт: это даст нормальный diff и review тестов до загрузки релизного архива.
