## Проверка твоего сервера

15.09.2026 прямой GET `https://ziziplayer.duckdns.org/auth/health` вернул:

````json
{"version":"1.1.0","google_enabled":false,"sync_enabled":true,"library_format":"zizi-library-1"}
````

Это подтверждает доступность API и объявленную поддержку синхронизации. `client_max_body_size 17m` — сведения владельца, конфигурация nginx удалённо не прочитана. Авторизованные запросы к настоящему аккаунту и запись его библиотеки не выполнялись: нет сессии пользователя. Поэтому причина именно наблюдавшегося на телефоне сбоя пока не доказана, и утверждение «все твои данные уже сохранены» было бы неверным.

## Изменения интерфейса

На главной вошедший пользователь видит круглый аватар слева от фильтров. Заголовок «Главная» для него убран, история доступна через меню; гостевой заголовок сохранён. Без фотографии показываются начальная буква имени и один из шести цветов, стабильно вычисленный из server user ID. Цвет не меняется при смене имени; у разных пользователей он может совпадать.

Меню шириной 90% экрана ведёт в профиль, недавние, облачную библиотеку и настройки. Профиль имеет градиентную шапку, имя, аватар, кнопку изменения, настройки, меню выхода и реальные локальные плейлисты с количеством треков. Это не список публичных плейлистов: подписчиков и публикации плейлистов в продукте нет.

Редактор имени и фотографии — отдельный экран с крестиком, «Сохранить», большим аватаром и строкой имени. Системный выбор файла, удаление фото, подтверждение отказа от несохранённых правок. Фото обрабатывается локально: нормализация ориентации, центральная квадратная обрезка, 256×256 PNG, без EXIF и исходного URI. Ручное позиционирование обрезки и камера не реализованы. Черновик только в RAM: при пересоздании Activity/процесса несохранённые правки могут потеряться; большая картинка намеренно не помещается в Bundle.

Все используемые приложением входы в настройки ведут в один полноэкранный интерфейс с оставшимся снизу мини-плеером и навигацией. Разделы представлены строками, поиск открывается лупой, ищет по ключевым словам разделов. Быстрые действия реально меняют «Только Wi-Fi» и «Кэшировать потоки». Существующие настройки звука, загрузок, библиотеки, оформления, диагностики и сети сохранены. Выход требует подтверждения. Нет декоративных Premium, рекламы, Spotify Connect, родительского контроля и социальных счётчиков.

## Геометрия референсов

Оригиналы имеют размер **1080×2400**, а не размер уменьшенных изображений в чате. Для сравнения используется нормализованная ширина 360 dp: исходный размер в пикселях делится на 3. Это выбранная система координат, а не утверждение о фактической плотности телефона. Размеры масштабируются с шириной текущего экрана, максимум ×1,6 для широких экранов.

| Элемент | Референс, приблизительно px | Реализация при ширине 360 dp |
|---|---:|---:|
| Аватар главной | 92 | 30,7 |
| Аватар меню | 138 | 46 |
| Аватар профиля | 324 | 108 |
| Аватар редактора | 382 | 127 |
| Боковой отступ профиля | 46 | 15,3 |
| Ширина бокового меню | 972 | 90% |
| Видимая плитка карандаша | 92 | 30,7 |

Цветовая сегментация внутренних непрозрачных областей дала 89×89, 135×136, 321×322 и 378×378 px соответственно. Внешние контуры включают сглаженные края, поэтому практическая погрешность измерений около 2–4 px. Источник этих измерений — приложенные PNG, не рендер нового APK.

Кнопка аватара имеет область касания 48 dp. Из-за этого первый фильтр при ширине 360 dp начинается примерно на 5–6 dp правее, чем при буквальном копировании референса; это осознанное отличие ради доступности. Системные отступы, масштаб шрифта и ширина экрана тоже меняют итог. Иконки используют общую векторную сетку 24 и контурный стиль проекта, добавлена шестерёнка. **Побитовое совпадение контуров Spotify и попиксельная идентичность всех экранов не заявляются:** оригинальных SVG нет, Android-рендер здесь не получен.

## Что исправлено в облачной библиотеке

В 6.53.0 JSON разбирался до проверки HTTP-статуса. HTML-ответ nginx 413/502 превращался в общую «Invalid account response», скрывая реальную причину. Теперь статус обрабатывается первым; ограниченный фрагмент ответа разбирается только для кода ошибки и не показывается пользователю. Отдельно различаются превышение лимита самой библиотеки 8 МиБ и лимита тела HTTP-запроса.

После временной ошибки первого подключения синхронизация теперь повторяет попытку через минуту при открытом приложении. Ошибки конфликта не запускают автоматическую перезапись. Для передачи библиотеки увеличены тайм-ауты: запись 60 с, чтение 45 с, общий запрос 90 с вместо общего ограничения 20 с для всех операций. Остальные операции входа сохраняют короткие тайм-ауты. Ручное «Сохранить сейчас» обходит паузу после ошибки; автоматический цикл сохраняет паузу.

Добавлена проверка объявленного протокола сервера перед подключением. После привязки обновляются сводки данных телефона/облака и подтверждённая сервером дата. Автосохранение по-прежнему работает примерно каждые 15 секунд, только пока Activity STARTED. При одновременных изменениях двух устройств выбор делается пользователем. Это замена, не слияние.

Сохраняются метаданные 15 таблиц Room v10: сохранённые записи каталога, избранное, плейлисты и их порядок, история, закрепления, статистика и настройки отдельных треков. Аудиофайлы, общие DataStore-настройки, очередь плеера, кэш, права доступа Android и локальные пользовательские обложки плейлистов не переносятся. Локальные файлы на новом устройстве нужно подключить отдельно. При наличии защищённых папок экспорт и облачные операции остаются заблокированы. Медиатека телефона остаётся общей, не отдельной для каждого аккаунта.

## Accounts 1.2

Для синхронизации библиотеки достаточно установленного **1.1**. **Для серверного хранения имени/фото нужен 1.2**: новый `/auth/profile` и отдельная таблица `account_profiles`. Формат библиотеки не меняется, почта и музыкальный сервер не изменены. С 1.1 новый клиент может сохранять библиотеку, но редактор профиля сообщит о необходимости обновления.

Профиль приватный, доступен только владельцу проверенной сессии. Запись использует revision/CAS; конфликт не перетирает более новый профиль. Фото проверяется на сервере: ограниченный PNG, размеры до 256×256, CRC, ограниченная распаковка, запрет EXIF/text/анимации/URL. Имя — 1–80 Unicode code points после NFC/trim, без управляющих категорий. Нет E2E-шифрования профиля и библиотеки: TLS защищает передачу, администратор сервера потенциально имеет доступ к SQLite.

Установщик 1.2 принимает известные исходники 1.0/1.1/текущего комплекта, отказывается затирать изменённые файлы и симлинки, резервирует исходники. `.env`, SMTP, ключи, nginx, systemd и база им не заменяются. Старый `install_library_11.py` в новом комплекте перенаправлен на установку полного 1.2, чтобы не забыть profiles.py. Не применять историческую инструкцию 1.1 к новому комплекту.

## Проверки и пределы доказательств

**84 серверных теста прошли.** Включены прежние 60 и 24 новых: WSGI/SQLite, перезапуск хранения профиля и медиатеки, миграция при уже существующей библиотеке, многомегабайтный снимок с кириллицей, изоляция аккаунтов, CAS/гонки, отозванные/истёкшие сессии, CSRF/origin, PNG и установщик. Дополнительно фактические исходники Accounts 1.1 из базового ZIP успешно прошли установку в тестовый каталог с неизменностью фиктивных env/DB.

Полный `tools/check_selftest.py` прошёл с кодом 0, включая новые 7 проверок 6.54.0 и выполнение 207 утверждений production Java по обработке ошибок. `test_account_6520_contracts.py` — код 0. Четыре эвристические проверки Kotlin — 0 замечаний. Python compileall — код 0. Изменены только устаревшие ожидания номера релиза и контракт подписи кнопки «назад»; защитные проверки не отключались.

**Не выполнены:** Gradle/Kotlin/Compose compilation, R8/APK, Android instrumentation, настоящий SMTP/login/upload/download с VPS, проверка на устройстве и pixel-diff скриншотов. На the Computer отсутствует установленный Android toolchain; статические проверки не заменяют сборку. Логи в `verification/v6.54.0/`. Push в GitHub и обновление твоего VPS не выполнялись.

## Установка клиента

Загрузить `ZiziPlayer-v6.54.0.zip` в корень GitHub. Корневой `.github/workflows/build.yml` уже побайтово совпадает с комплектом, менять его для этого ZIP не требуется. Сборщик выбирает проект по versionCode 104. ACCOUNT_URL оставить `https://ziziplayer.duckdns.org`, действующие секреты подписи и SMTP не менять и не присылать. Новый тест подключён через существующий selftest, поэтому подхватится из ZIP.

После зелёной Android-сборки установить APK с прежней подписью поверх приложения, без очистки данных. Accounts обновить отдельно по `DEPLOY_ACCOUNTS_1.2.md`. На тестовом аккаунте выполнить `DEVICE_CHECKLIST_v6.54.0.md`. До проверки восстановления не удалять единственную копию приложения/медиатеки.
