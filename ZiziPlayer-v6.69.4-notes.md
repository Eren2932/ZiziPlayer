# ZiziPlayer 6.69.4 — кандидат исправления слияния с камерой

Основа: ZiziPlayer-v6.69.3.zip, versionCode 128, из публичного main на коммите
8b38289773b84ac978419a5faadf56fbf353ed05. Новый versionCode 129.
Это исходники для CI, **не собранный и не проверенный на устройстве APK**.

## Подтверждённая причина и граница знания

Скриншот диагностики с vivo I2405 / Android 16 / API 36 показывает окно 1080×2400,
status 110 px и отказ проверки геометрии: «Широкий/неопределённый вырез».
По коду это означает target=null: вместо слияния запускается уменьшение до нуля с
исчезновением. Затемнение не является причиной отключения геометрии.

Прежний отчёт не сохранял отвергнутые bounding rect / path bounds / density.
Поэтому нельзя утверждать, какое именно условие проверки нарушено на этом телефоне.
**Узкая область, начинающаяся от y=0, — проверяемая гипотеза, а не полученный с vivo замер.**
Размеры физических камеры/отверстия из скриншота не извлекались и не зашивались.

## Изменения

### Распознавание

Точный допустимый системный Path имеет прежний приоритет. Для ранее отвергнутой
узкой верхней системной области добавлена явно приближённая ветка:

- один вырез, полноэкранный портрет, неизменённая система координат;
- начало области 0–1 px от верхнего края;
- ширина 8–32 dp и не больше 12% ширины окна;
- высота больше ширины, но не больше трёх ширин;
- нижний край не ниже status + 8 dp;
- диаметр оценки равен ширине области; центр X берётся из области;
- низ оценки совпадает с низом области, верх = bottom − width.

Оценка дополнительно проходит прежний фильтр компактного круглого выреза.
Отсутствующие данные, широкие чёлки, несколько вырезов, landscape и сдвинутые окна
не превращаются в выдуманную камеру. Это консервативное приближение по резервируемой
области Android, **не гарантия попиксельного совпадения с физическим отверстием**.
Если конкретный vivo сообщает иной вид геометрии, безопасное исчезновение сохранится;
понадобятся raw-поля нового служебного отчёта, а не дальнейшее расширение фильтра вслепую.

### Перетекание

Существующая шейка из кубических кривых и две фазы прокрутки сохранены.
Для боковой камеры движение по X теперь заканчивается до входа в статус-бар
(при 75% второй фазы), вместо диагонального движения через узкую маску.
Добавлены проверки видимой перемычки при ещё непрозрачной обложке, нижней привязки
оценки, бокового положения, запрета широких областей и обратимости геометрии.
Android-тест отдельно проходит настоящий адаптер DisplayCutout и проверяет пиксели
перемычки и ещё видимой обложки в середине перехода, а не только чёрную точку в конце.

### Верхний фон

Глобальный StatusBarTint (24% чёрного) удалён из корневого окна. Он принадлежит
только открытому полному плееру, остаётся неподвижным относительно окна и исчезает
по мере ухода верхнего края плеера. Эквалайзер и другие полноэкранные слои выше плеера
не получают этот глобальный слой.

В подборках отдельный неподвижный цвет статус-бара и градиент внутри прокручиваемой
шапки заменены одним градиентом в координатах окна. Начало = status − scroll,
конец = начало + измеренная высота hero. Под системными значками закреплённая шапка
продолжает свой цвет с той же прозрачностью, без чёрного стекла.
Новый Android-тест проверяет отсутствие цветового скачка на границе статус-бара.

### Диагностика

Строка «Слияние обложки с камерой» отсутствует в обычных настройках release.
Оставлена только в DEBUG или после существующего служебного разблокирования.
Кнопка обводки недоступна при отсутствии цели. В служебном отчёте теперь сохраняются
raw rect, path bounds, density и координаты окна даже при отказе фильтра.
Обводка по-прежнему временная, не включает сам морфинг и не сохраняется после
перезапуска процесса — это диагностический инструмент, не пользовательская настройка.

## Применение

Загрузить ZiziPlayer-v6.69.4.zip в корень main. Корневой workflow уже совпадает
с .github/workflows/build.yml исходной 6.69.3 (Git blob
4e23f8149d7f79be452e966610c5d3ffb0d32b20), в этой версии он не меняется.
Выбор источника идёт по максимальному versionCode; оставить только один ZIP с code 129.
Старый code 128 не мешает. CI уже запускает изменённые Android-классы на API 28/35.
Серверы, база и воспроизведение не менялись. Репозиторий автоматически не обновлялся.

После зелёного CI установить подписанный APK поверх прежней версии, без очистки данных.
Проверить «Все треки», короткий плейлист и удалённый альбом: медленная прокрутка туда
и обратно, шейка до исчезновения картинки, отсутствие полосы сверху и нормальное
нажатие «Назад»/Play. Проверить стекло только в полном плеере, его закрытие жестом,
эквалайзер и настройки поверх него. Убедиться, что обычные настройки не показывают
техническую строку. Реальное совпадение с отверстием проверять глазами на устройстве:
физическая камера не является нарисованным пикселем скриншота.

Если слияние всё ещё выключено или оценка не совпадает с отверстием, не объявлять
кандидат исправлением устройства: нужны raw-данные из служебной/отладочной сборки.
