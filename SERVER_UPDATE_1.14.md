# Серверное обновление 1.14-smart-match

Заменяет «строгий поиск» 1.11–1.13 подбором по баллам. Цель: всё, что показал поиск, играет, а мусор
(новостные ролики, игровые клипы, чужие суры, «видео вместо трека») не проходит.

## Что меняется

| Было (1.13) | Стало (1.14) |
|---|---|
| Набор жёстких ворот: любое несовпадение = 404 | Баллы за название, артиста, длительность, версию, источник; 404 только если нет ни одного годного |
| H2HELL на Deezer, «FORGET777 - Topic» на YouTube = 404 | Чистый Topic с точной длительностью и названием проходит и без имени артиста |
| «Ultra Slowed» нет на YouTube = 404 | Играется соседняя степень или оригинал, с пометкой `substituted: true` (отключается, см. ниже) |
| Промах жил 30 минут (`ZIZI_MISS_TTL`, а в `zizi.env` мог стоять и больше) | Промах живёт 2 минуты, потолок зашит в код: 600 с, любое значение из env обрезается |
| Промах прогрева без соисполнителей блокировал тап | Ключ промаха учитывает соисполнителей |
| Отмена устаревших задач прогрева не работала (`gen` не доезжал) | Работает |
| Нельзя понять, почему 404 | `explain=1`: таблица кандидатов с причиной отказа по каждому |
| Обложки с YouTube — 4:3 с чёрными полями | `/img` режет центральный квадрат (нужен Pillow) |
| `/catalog/health` падал на удалённом `FALLBACK` | Починен |
| Подбор: сура любая подходит, лишь бы совпало слово «surah» | Слова «сура», «часть» и т. п. весят 0,3, имя суры обязано совпасть |

Что **не** пропускается, по-прежнему и намеренно:
- замедленная запись вместо ускоренной и наоборот (противоположное направление скорости);
- ролики с лишними словами при неподтверждённом артисте («Bodycam footage … 7NEWS»);
- игровые клипы и хроника (`cs2`, `montage`, `bodycam`, `footage`, `news` и т. п.), если этих слов нет в запросе;
- однословное название, у которого артист нигде не подтверждён (иначе подставится любая песня с таким названием).

## Файлы комплекта

| Файл | Роль |
|---|---|
| `zizi_match.py` | **новый** модуль подбора |
| `zizi_catalog.py` | заменяется (импортирует `zizi_match`) |
| `zizi_versions.py` | ставится, только если развёрнутый файл не знает `speed_compatible`/`SPEED_TAGS` |
| `tools/apply_smart_update.py` | установщик: проверка хеша базы, бэкапы, откат |

Базы, которые установщик признаёт: 1.11, 1.12, 1.13. Любой другой `zizi_catalog.py` (правленный руками)
= отказ без записи.

## Установка

Сначала положите `server/` из комплекта на VPS (например, в `~/zizi-1.14/server`).

```bash
# 1. Проверка. Ничего не пишет.
python3 ~/zizi-1.14/server/tools/apply_smart_update.py --target-dir /opt/zizi

# 2. Резервная копия каталожной базы (WAL: копировать .db на ходу нельзя).
sqlite3 "$ZIZI_CATALOG_DB" ".backup '/opt/zizi/catalog.before-1.14.db'"

# 3. Установка. Службу скрипт не перезапускает.
sudo python3 ~/zizi-1.14/server/tools/apply_smart_update.py --target-dir /opt/zizi --apply

# 4. Обложки без чёрных полей (необязательно; без Pillow всё работает, как раньше).
sudo /opt/zizi/venv/bin/pip install pillow

# 5. Перезапуск.
sudo systemctl restart zizi-resolver
sudo systemctl status zizi-resolver --no-pager
```

Если на шаге 3 что-то не так, скрипт сам откатывает всё, что успел записать за этот запуск. Бэкапы
лежат рядом: `*.before-1.14-<время>`.

### Ручной откат после установки

```bash
cd /opt/zizi
sudo cp zizi_catalog.py.before-1.14-<время> zizi_catalog.py
sudo systemctl restart zizi-resolver
```

`zizi_match.py` при откате можно оставить: старый каталог его не импортирует.

## Проверка после перезапуска

`$T` — тот же токен, что шлёт приложение (`Authorization: Bearer …`).

```bash
H="Authorization: Bearer $T"
B=https://<ваш-хост>

# Версия и режим
curl -s -H "$H" "$B/catalog/health" | python3 -m json.tool
# ждём: "version": "1.14-smart-match", "match_engine": "smart", "substitute": "all"
```

Разбор любого 404 (кэши не читаются и не пишутся):

```bash
# по названию и артисту
curl -s -H "$H" --get "$B/match" \
  --data-urlencode "title=SEM DEMORA (Ultra Slowed)" \
  --data-urlencode "artist=DJ Samir" --data-urlencode "dur=130" \
  --data-urlencode "explain=1" | python3 -m json.tool

# по id Deezer (то же, что делает приложение на тап)
curl -s -H "$H" "$B/match/deezer?id=<ID>&explain=1" | python3 -m json.tool
```

В ответе: `vid` (что выбрано), `tier` (`exact` / `good` / `loose` / `variant`), `queries` (какие запросы
шли), `candidates` (каждый кандидат: балл, причина отказа `veto`, заметки `notes`).

**Если 404 остался — пришлите вывод `explain=1` по этому треку.** По нему видно, в каком правиле дело,
и поправка занимает одну итерацию.

## Настройки (`/opt/zizi/zizi.env`, все необязательные)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ZIZI_SUBSTITUTE` | `all` | `all` — играть соседнюю степень или оригинал с пометкой; `degree` — только соседнюю степень; `off` — только точную версию (больше 404) |
| `ZIZI_MISS_TTL` | `120` | Срок кэша промахов, секунды; выше 600 не поднимается. Старое `21600` в env безопасно: оно обрезается |
| `ZIZI_HUNT_BUDGET` | `14` | Потолок охоты на тап, секунды |
| `ZIZI_HUNT_BUDGET_BG` | `25` | То же для фонового прогрева |
| `ZIZI_AUTOWARM` | `1` | Прогрев треков по выдаче поиска, альбома, плейлиста |
| `ZIZI_AUTOWARM_N` | `8` | Сколько первых треков выдачи греть (0–12) |
| `ZIZI_IMG_SQUARE` | `1` | Квадратная обрезка миниатюр YouTube в `/img` (нужен Pillow) |

## Что известно и чего нет

- Скорость: обычный трек = один вызов yt-dlp; трудный — два-три. Первый тап по свежему треку может
  занять дольше 2–3 с, повторный и прогретый — как раньше. Замеров на вашем VPS нет.
- Подбор проверен на сохранённых страницах выдачи YouTube и синтетических случаях. С живым YouTube и
  Deezer не проверялся: у тестовой среды нет доступа в сеть.
- Квадратная обрезка касается только треков, у которых обложка — миниатюра YouTube. У треков, найденных
  через Deezer, обложка Deezer, как и раньше.
- Пометку `substituted` приложение пока не показывает (клиент не менялся).
- Падение `ForegroundServiceStartNotAllowedException` — клиентское, этим обновлением не затрагивается.
