## Панели и управление

Подтверждённая ошибка 0.3.3: внутри AnimatedVisibility при закрытии очереди queueOpen становился false и ветка else показывала EffectsPanel на время exit-анимации. Слева sideTarget сразу переключал структуру библиотеки, а animateDpAsState продолжал сжимать её ширину. На узком окне открытие правой панели одновременно запускало автосворачивание левой.

Теперь один DesktopDock: NONE/QUEUE/EFFECTS/DEVICES. Изменения геометрии атомарные, без анимации ограничений ширины; это сознательное решение, а не обещание «улучшенной анимации». Нечему показывать DSP при закрытии очереди. SaveableStateProvider сохраняет табы/прокрутку; скрытие левой панели возвращает её предыдущий режим. Удалён недостижимый старый полноэкранный путь очереди. Реальный рендер быстрых переключений пока не проверен.

ThinSlider не использует Material Slider. Дорожка белая в покое, фирменная оранжевая при взаимодействии; Play и активные режимы оранжевые. Есть мышь, клавиатура, Home/End, семантика accessibility, отмена незавершённого жеста. Seek проверяет trackId и generation и в прогрессе, и непосредственно перед командой. Таймер вынесен в SeekBar: позиция не является подпиской всей нижней панели. Громкость имеет mute с восстановлением уровня. Stop остаётся в раскрытом плеере.

## Цвет и страницы

Один кистевой градиент принадлежит прокручиваемой странице, не играющему треку. В него входят hero, действия, прозрачная незакреплённая шапка таблицы и первые строки. Конец: heroHeight + 244 dp. При закреплении таблица получает непрозрачную поверхность. Чтение scroll offset происходит в draw phase. Оригинальный mobile ArtworkColorMath, кэш, семафор и URL-проверки сохранены; новых запросов ради окраски нет.

Chroma увеличена в 1.18 раза с потолком 0.22 вместо 0.15; светлота всё ещё 0.36…0.50. Нижние оттенки непрозрачные, затеняются в поверхность #101010. Контраст белого текста проверен независимой численной моделью; banding, FPS и скриншотный паритет не измерялись. Оттенок отсутствующей обложки нейтральный.

Исполнитель: крупный круглый портрет, первые пять треков каталога, «Показать ещё», широкая правая колонка с реальными сохранёнными треками из загруженного набора. Нет вымышленных слушателей, прослушиваний или «Выбора исполнителя». Текущий API не предоставляет эти данные. Нет выдуманных альбомов или рекомендаций под видом ответа сервера.

## Поиск

Добавлены «Все», первый результат, треки и горизонтальные полки исполнителей/альбомов/плейлистов. Смешанный поиск использует четыре существующих запроса только после явной отправки; подсказки по-прежнему имеют debounce 320 мс и максимум шесть треков. Отмена распространяется через searchPart, а ошибка одной категории не уничтожает остальные. Поздние ответы защищены поколением. Пустой каталог показывает локальные совпадения.

Стартовый экран содержит жанровые поисковые плитки, исполнителей из своей медиатеки, запросы и избранное. Это локально обоснованные точки входа, НЕ новый персональный рекомендательный алгоритм и не перенос всей mobile Discover API. История popup теперь имеет собственный заголовок и очистку. Прослушивание не сохраняет трек автоматически.

Длительность из существующего поля каталога dur (секунды) теперь заполняет durationMs. Нулевые, отрицательные, слишком большие значения остаются неизвестными; они не подменяются придуманной длительностью.

## Вывод звука

Иконка Headphones взята из мобильной 6.39.9 без изменения её общего файла: при открытой панели — оранжевый цвет и точка снизу. Панель использует реальные Java Sound playback mixers, а не имитацию Spotify Connect. Список читается на IO, обновляется раз в пять секунд только при открытой панели. ActiveOutput публикуется лишь после успешного открытия Sink, закрытие старого Sink не сбрасывает новый.

Для seekable проигрывания/паузы выбор выхода использует существующий сериализованный seek/handover с сохранением позиции/паузы. Возможен краткий разрыв звука; бесшовность не обещана. Для потока без перемотки/загрузки выбор действует со следующего открытия. Выбор хранится только в сеансе, формат библиотеки не менялся. При отключении выбранного устройства нужна явная смена; автоматического fallback нет.

ВАЖНО: Java Sound может показывать только Primary Sound Driver/системный выход, не физическое имя Bluetooth-гарнитуры. При default-выходе честно написано «Системное устройство по умолчанию». Точное определение физического endpoint и события Windows Core Audio не реализованы. Wi-Fi Connect, трансляция на телефон и автоматическое Bluetooth-подключение не реализованы. Есть кнопка системных настроек звука Windows. В этой среде устройства и переключение на Windows не проверялись.

## Неизменяемые части

Байтово сохранены DesktopPlayer, Sink/JavaSoundSink, Engine, Decoder, DSP, LibraryStore, OfflineFiles, все семь upstream файлов, мобильный ZIP и workflows. DesktopUi теперь передаёт новый провайдер выхода; это реальное изменение wiring аудиовыхода, хотя сам движок не переписан. В сетевом клиенте изменён только разбор dur, endpoints/авторизация/транспорт неизменны. Зависимости не добавлены.

## Приёмка в Windows

Сначала обязателен успешный существующий Actions workflow с Kotlin/Compose compilation, JUnit/audio tests и упаковкой. После этого проверить 960×680, 1280×800, 1440×900 и полноэкранное окно; DPI 100/125/150%. Переключить каждую пару dock-состояний и скрывать/сворачивать библиотеку, в том числе при скролле и длинных заголовках. Проверить паузу/следующий трек во время seek, отпускание мыши вне дорожки, Tab/стрелки/Home/End, mute/restart, быстрое закрытие приложения.

Для выхода: default, проводные/USB/Bluetooth, смена в паузе и на ходу, отключение выбранного устройства, отсутствующий драйвер, ошибка открытия. Для поиска: быстрый ввод и смена запроса, очистка/отмена, offline, частичный отказ одной категории, загрузка следующих страниц. Для оформления: красная/синяя/монохромная/отсутствующая обложка и смена играющего трека при открытой чужой коллекции.

Сравнивать новые скриншоты 0.3.4 с референсом при одинаковом масштабе. Полный Windows render и отсутствие визуальных регрессий пока НЕ подтверждены.
