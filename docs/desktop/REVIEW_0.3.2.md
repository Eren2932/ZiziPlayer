# ZiziPlayer Desktop 0.3.2 preview — адаптация 6.39.9

## Статус и происхождение

Это обновление **исходников**, не проверенный Windows EXE. База десктопа — исходный пакет 0.3.1 из этой беседы. Мобильная база — сохранённый `ZiziPlayer-v6.39.9.zip`, SHA-256 `cd9f3608b68e8ade4d1e148cd5ee3753324f5ac478691523f260a0b9d50a3ef0`. ZIP и распакованные файлы повторно изучены.

Свежий GitHub ZIP получить не удалось: URL-загрузчик вернул `Unsupported content type: application/zip`. Поэтому изменения удалённой ветки после сохранённой копии не проверены. Репозиторий и работающий сервер не изменялись.

## Повторно изученные мобильные компоненты

`SettingsStore.kt`, хаб/разделы `SettingsSheet` в `Sheets.kt`, `CollectionPageScreen.kt`, модели коллекций и серверный `zizi_browse.py`, выборка обложек `Artwork.kt`, `ArtworkColorMath.java`, преобразования Oklch и переходы `ZiziTheme.kt`, DSP-конфигурация и кодек. Полного паритета всего мобильного приложения этот этап не достигает.

### Переход к исполнителю

В текущем `dz_track()` сервер возвращает имя исполнителя, но **не его ID**. Десктоп использует `artist_id`, если поле появится, а при его отсутствии открывает поиск **исполнителей** с явным выбором. Первый результат не принимается за нужного исполнителя автоматически. После выбора запрос страницы выполняется строго по паре `kind + id` и проверенному источнику `deezer`. Это сознательно безопаснее неверного «прямого» перехода по совпадению имени. Для настоящего однокликового перехода от каждого сетевого трека нужен совместимый серверный контракт с `artist_id`; в данном пакете сервер не меняется.

### Матовый цвет и полосы

Доминирующий цвет и фильтрация прозрачных/монохромных областей совпадают с мобильным математическим ядром. Переходы используют короткую дугу оттенка в Oklch. Нижний плеер, активные элементы и развёрнутый плеер получают согласованные цвета. Фон медиатеки остаётся чёрным; яркие широкие градиенты и размытие не добавлены. Таким образом убран именно источник полос старого градиентного фона. Отображение на мониторе пользователя ещё не проверялось; общую гарантию отсутствия артефактов дисплея дать нельзя.

### Хранение и защита данных

На Windows данные находятся в `%LOCALAPPDATA%/ZiziPlayer`, с резервным путём в профиле пользователя. На Linux — `$XDG_DATA_HOME/ZiziPlayer` либо `~/.local/share/ZiziPlayer`.

`library-v1.json` хранит библиотеку и сеанс. Запись проходит через одного фонового владельца, временный файл, `fsync` и атомарную замену там, где она поддерживается. Предыдущая корректная версия хранится в `library-v1.backup.json`. Повреждённая библиотека восстанавливается из backup; неизвестная схема не заменяется старой. Если восстановить нечего, включается режим без записи с явным предупреждением. При ошибке финального сохранения закрытие окна отменяется, чтобы можно было освободить место и повторить.

Токены подключения и байты обложек не записываются в JSON библиотеки. Введённая пользователем прямая ссылка сохраняется как источник трека: если сам пользователь вставил секрет в query такой ссылки, это свойство самой ссылки, не защищённое хранилище секретов. Сетевые треки Zizi сохраняются через стабильные `zizi://` источники, не через временные адреса стримов.

Удаление из медиатеки или плейлиста **не удаляет пользовательский аудиофайл**. Отдельная операция удаления загрузки удаляет только принадлежащий приложению файл. Скачанные аудио находятся в `downloads`, изображения — в `artwork`. Закачка ограничена 2 ГБ на файл, редиректы не разрешаются, HTTP остаётся ограничен origin из сборки. До завершения и проверки FFprobe `.part` не используется для проигрывания.

### Что не перенесено

Не реализованы: мобильный discover-хаб с жанрами/подборками во всём объёме, импорт/экспорт мобильного формата плейлистов, общая облачная библиотека, адаптивное качество/потоковый аудиокэш, metered-network policy Windows, пропуск тишины с корректной шкалой времени, speed/pitch, спектр, горячие медиаклавиши ОС/трей, жестовая карусель и полный набор мобильных переходов. Нет мониторинга папок, экранного переименования папок и всех мобильных сортировок коллекций. Это отдельная работа, а не спрятанные готовые функции.

Настройки Wi-Fi/мобильной сети и Android-разрешений не копируются на ПК механически. Отсутствующие возможности не представлены пустыми переключателями. В основных настройках нет формы подключения, адреса и токена; транспортное предупреждение и выбор FFmpeg доступны отдельно: **О приложении → Диагностика и аудиодекодер**. Скрытие этого раздела не шифрует HTTP и не делает bootstrap внутри публичного клиента секретным.

## Проверки

Выполнены локально:

- 19 реальных JVM-сценариев оригинальной математики обложек, включая сетку контраста из 4096 цветов и детерминированные случайные выборки.
- 18 Python-тестов серверного browse-контракта на локальных фикстурах, без обращения к VPS.
- 9 тестов параметров сборочного подключения.
- 30 статических контрактов исходников, включая SHA-256 семи неизменённых общих мобильных файлов.
- Проверка разделителей Kotlin: ошибок не найдено. Это не компилятор.
- 5 FFmpeg/FFprobe smoke-проверок контейнеров WAV, FLAC, MP3, Ogg/Opus, MP4/AAC с расширением `.part`.
- Финальная проверка структуры ZIP, контрольной суммы манифеста и безопасного извлечения.

Добавлены 14 JUnit-тестов для CI: библиотека/backup/неизвестная схема, офлайн-пути, типизированный каталог, повтор и перестановка очереди, восстановление без автопуска, вызов мобильного набора цветовых тестов. Эти Kotlin/JUnit-тесты **не запускались локально**: здесь нет Gradle/Kotlin/Compose-зависимостей. Оригинальная Java-математика отдельно скомпилирована и выполнена через JDK-модуль компилятора.

**Не проверены:** компиляция Kotlin/Compose, Windows app-image, живой сервер, реальное скачивание через VPS, фактическая отрисовка и управление на Windows. Успешная статическая проверка не заменяет эти проверки. CI выполняет `test` перед `createDistributable`; при ошибке тестов/компиляции готовая сборка не выдаётся.
