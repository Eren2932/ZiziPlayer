# ZiziPlayer 6.9.0 (versionCode 18)

Две вещи: 6.8 больше не падает на компиляции, и Jamendo подключается по-настоящему —
ключ вводит пользователь, приложение сразу проверяет его и говорит результат словами.

Новых зависимостей нет. Схема базы не тронута, миграций нет.

---

## 1. Build fix: `LibraryScreen.kt:143 Unresolved reference 'searchScope'`

**Что было.** В 6.8 я объявил

```kotlin
val searchScope by vm.searchScope.collectAsState()
val onlineState by vm.online.collectAsState()
```

рядом со строкой, которая их рисует, — так читается лучше. Но `LibraryHeader` вызывается
выше и получает `netScope = searchScope == SearchScope.NET`, а локальная переменная в Kotlin
не видна до своего объявления. Компилятор прав, я — нет.

**Что стало.** Оба `val` поднялись выше `Column`, до первого использования.
Заодно `collectAsState` → `collectAsStateWithLifecycle`: второй уже импортирован в этом файле,
используется всем остальным экраном и отписывается на `STOPPED` — то есть свёрнутое
приложение перестаёт перерисовывать список результатов.

Это была единственная ошибка компиляции. Аннотации в логе показывали её дважды, потому
что шаг `Fail if build failed` повторяет `exit code 1`.

## 2. Jamendo · client_id — поле в настройках

Новая карточка **«Поиск в сети»** в настройках, ниже «Интернета»:

| Строка | Что делает |
|---|---|
| **Audius** | статус, `вкл` — работает без ключа, всегда |
| **Jamendo · client_id** | тап → диалог с полем, статус в подзаголовке |
| **Как получить ключ** | `devportal.jamendo.com`, бесплатно, одна форма |

Решения, за которые отвечаю:

1. **Отдельная карточка, а не вложение в «Дополнять из интернета».** Тот переключатель
   управляет тегами файлов, которые уже на телефоне. Этот — каталогом, по которому ты ищешь.
   Спрятать ключ за несвязанным тумблером — способ сделать настройку ненаходимой.
2. **Ключ проверяется сразу после сохранения** (`OnlineCatalog.jamendoKeyValid`, `limit=1`,
   это рукопожатие, а не поиск). Три исхода различаются, и это важно: неверный ключ и мёртвая
   сеть оба дают ноль строк Jamendo, и без различия пользователь читает «каталог бедный»,
   когда правда — «вставлено 39 символов вместо 40».
   * `Подключён · …a1b2c3` — принят
   * `Jamendo отклонил ключ — проверь, что скопирован целиком` — ответил и отказал
   * `Ключ сохранён, проверить не удалось — нет сети` — сказать нечего, ключ всё равно сохранён
3. **Показывается только хвост ключа.** Шести символов хватает, чтобы отличить два ключа,
   и при этом целый ключ не попадает на экран, который фотографируют для поддержки.
4. **Пустое поле — валидный ввод.** `JamendoKeyDialog` — отдельный диалог, а не `RenameDialog`:
   тот блокирует кнопку на пустой строке (правильно для названия плейлиста), а здесь очистка
   поля — единственный способ отключить Jamendo. Настройка без отмены — настройка без доверия.
5. **Ключ обрезается на входе** (`SettingsStore.setJamendoClientId`) и чистится от `\n`/`\r`
   прямо в `onValueChange`. Ключ попадает в поле вставкой, а вставка приносит перевод строки
   достаточно часто, чтобы это было дешевле, чем потом объяснять отказ.
6. **Ключ в исходнике не лежит и лежать не будет.** Ключ в публичной репе — это ключ,
   который скрапят, лимитируют, а виноватым назначают приложение.
7. **`searchOnline` читает ключ на каждый поиск**, а не кэширует в поле. Ключ меняется из
   настроек, пока экран жив; поле продолжало бы искать со старым значением до перезапуска процесса.

## 3. Побочный фикс: мигающая ошибка при быстром наборе

`runCatching` перехватывает и `CancellationException`. В 6.8 отмена старого поиска ради нового
означала, что мёртвая корутина доходила до `_online.update` и писала свой баннер.
На практике: печатаешь быстро — поверх приезжающих результатов вспыхивает
«Каталоги не ответили».

Теперь `try / catch (e: CancellationException) { throw e }`, и отмена остаётся отменой.
То же для чтения настроек.

## Чего НЕТ

1. **Компилятором не проверено** — Android SDK нет. Проверено структурно: баланс скобок по
   всем 29 файлам Kotlin, каждый новый символ имеет объявление и использование, каждый
   межпакетный символ — импорт (тем же скриптом, который поймал `searchScope`; на нём же
   видно, что `collectAsState` в проекте больше не встречается нигде).
2. **Живьём Jamendo не опрошен** — исходящий трафик закрыт. Разбор `headers.status` по
   документации v3.0. Ответит иначе — пришли JSON, подгоню за минуту.
3. **Audius по-прежнему без ключа и без настроек** — там нечего настраивать.
4. **7.0 / 7.1 в репе только чейнджлогами.** Фикс критического бага со шторками по-прежнему
   существует лишь текстом.
