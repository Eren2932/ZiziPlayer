## Что показывают лог и исходники

Ошибка возникает в `:app:kspReleaseKotlin`: `JsonDecodingException`, пустой
`JSON input`, далее `SchemaBundle.deserialize` → `Database.exportSchema`.
Это не ответ сервера рекомендаций и не повреждение пользовательской базы на телефоне.

В исходном ZIP вообще нет `app/schemas`. При этом общий параметр
`ksp { arg("room.schemaLocation", "$projectDir/schemas") }` направляет оба
процессора в `app/schemas/app.ziziplayer.data.ZiziDatabase/11.json`.
Действующий workflow запрашивает Debug и Release вместе, с двумя Gradle workers.

Проверены опубликованные исходники **Room 2.7.1**, а не только похожая ошибка:
`Context.kt` использует общий schemaLocation для чтения и записи;
`Database.exportSchema` сначала читает существующий файл, а затем пишет экспорт.
Параллельный процесс может увидеть уже созданный, но ещё пустой файл. Такая гонка
объясняет EOF из присланного лога. Точное межпоточное расписание того запуска не
записано; повторного исполнения исходного Gradle/KSP в этой среде не было.

Предупреждения о debug signing и AGP 8.7.3/compileSdk 36 — отдельные вопросы,
не причина показанного исключения. Массовое обновление toolchain в этот hotfix
не добавлено: оно смешало бы исправление с новой зоной риска.

## Исправление

В корневом Gradle закреплён официальный плагин `androidx.room` **2.7.1**, совпадающий
с уже используемыми `room-runtime`, `room-ktx` и `room-compiler`. Плагин применён
в app; ручной KSP-параметр удалён и заменён на:

````kotlin
room {
    schemaDirectory("$projectDir/schemas")
}
````

В опубликованном плагине выходы разделены по имени processing task:
`build/intermediates/room/schemas/kspDebugKotlin` и `.../kspReleaseKotlin`.
История служит входом; отдельная финализирующая задача `copyRoomSchemas` собирает
экспорты и проверяет совпадение содержимого схем одной версии. Это штатное решение
для нескольких вариантов, а не отключение экспорта или глобальное ограничение
сборки одним worker.

`exportSchema = true`, версия базы **11**, миграции и регистрация миграций сохранены.
Все `app/src/**`, `server/**` и `.github/workflows/build.yml` побайтно совпадают с rc1.
Последние изменения выбора артистов/выдачи музыки сохранены; их описание остаётся
в `ARTIST_ONBOARDING_6841.md`. Сервер, аудиотракт, секреты и desktop current.json
не требуют изменения из-за этого исправления.

## Защита и проверки

`tools/check_room_schema_config.py` проверяет подключение/согласованность плагина,
отсутствие ручных schema-аргументов, включённый экспорт и целостность существующих
JSON схем. Пустой или повреждённый JSON получает понятную диагностику **до KSP**.
Проверка ничего не удаляет и не «чинит» подставным `{}`. Это ограниченная проверка
конфигурации и JSON, не Kotlin DSL-компилятор и не тест SQL-миграций.

23 новых регрессионных теста проверяют саму защиту, повреждённую историю,
контроль текущей версии и файловую модель гонки. Файловая модель использует
настоящие файлы и синхронизированные потоки, **не запускает Room/KSP**.
Новая защита отдельно отклоняет реальные Gradle-файлы исходного rc1 и принимает
исправленные. Оба скрипта подключены к `check_selftest.py`, уже вызываемому
корневым workflow: загрузки одного нового мобильного ZIP достаточно.

Результаты текущего прогона и полные логи: `verification/room-build-6841-rc2/`.
`validation.json` отделяет выполненные проверки от невыполненных.
Исторические PASS внутри других каталогов verification не доказывают сборку rc2.

**В the Computer нет установленного Gradle и Android SDK. Android/Kotlin/Compose
компиляция, APK, эмуляторы и живой сервер здесь не проверены.** Пройденные
локальные Python/Java/source-проверки не заменяют новый зелёный GitHub Actions.

## Как собрать

Загрузить **`ZiziPlayer-v6.84.1-rc2-source.zip` в корень репозитория**, не распаковывая
его поверх zip-based репозитория. Старые архивы можно оставить: действующий
workflow выбирает наибольший versionCode — теперь **180 / 6.84.1-rc2**.
Не оставлять два разных архива с одинаковым code 180. Workflow и секреты менять
не нужно. `current.json` в корне относится к десктопу: не менять его на мобильную версию.

В существующей Android-среде для проверки с отключённым build cache:

````sh
python3 tools/check_selftest.py
gradle --no-daemon --max-workers=2 --no-build-cache --rerun-tasks :app:compileDebugKotlin :app:compileReleaseKotlin :app:testDebugUnitTest
python3 tools/check_room_schema_config.py --require-current
gradle --no-daemon --max-workers=2 :app:testReleaseUnitTest :app:assembleDebug :app:assembleRelease
````

Здесь используются команды установленного Gradle **8.11.1**, как в действующем
CI: в исходной базе нет исполняемого `gradlew`. APK из ветки без релизных секретов
сохраняет прежнее поведение debug-подписи; это не менялось.

После успешного KSP сохранить сгенерированный
`app/schemas/app.ziziplayer.data.ZiziDatabase/11.json` в следующем исходном архиве.
История версий 1–10 отсутствовала в базе и этим исправлением не восстановлена:
нельзя придумывать её или identity hash вручную. Обычный preflight разрешает
первую сборку без истории, а `--require-current` после компиляции уже требует
настоящую текущую схему. Эта последняя команда приведена для ручной проверки;
корневой workflow в данном пакете не изменён и автоматически её не вызывает.

Если локальная рабочая копия уже содержит повреждённый JSON, не очищать историю
вслепую: восстановить проверенную копию либо собирать из нового чистого ZIP.
Не запускать два независимых процесса Gradle в одном рабочем каталоге.
