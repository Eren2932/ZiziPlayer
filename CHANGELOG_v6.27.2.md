# ZiziPlayer 6.27.2 — сборка 6.27.1, поставленная на ноги

**versionCode 53 · versionName 6.27.2 · схема БД 9 (без изменений)**

Версия ровно об одном: 6.27.1 не компилировалась. Ни одной правки поведения, ни одного
изменения интерфейса, ни одной миграции. Всё, что описано в `CHANGELOG_v6.27.1.md`, остаётся
как есть — теперь оно ещё и собирается.

---

## Что сломалось

`:app:compileReleaseKotlin`, четыре ошибки на двух строках:

```
Sheets.kt:1218:47 No value passed for parameter 'onClick'.
Sheets.kt:1218:55 Argument type mismatch: actual type is 'kotlin.Function0<kotlin.Unit>',
                  but 'androidx.compose.ui.Modifier' was expected.
Sheets.kt:1220:47 (то же)
Sheets.kt:1220:55 (то же)
```

Объявление (`ui/components/Common.kt`, без изменений с 6.26.1):

```kotlin
fun PillChip(
    label: String, icon: ImageVector?, active: Boolean, palette: ChipColors,
    onClick: () -> Unit,
    modifier: Modifier = Modifier
)
```

Новые чипы разрезов настроек (п. 10 в 6.27.1) вызвали его по-компоузовски — хвостовой лямбдой:

```kotlin
PillChip("Все", null, active == null, colors) { onPick(null) }
```

**В Kotlin хвостовая лямбда садится на ПОСЛЕДНИЙ параметр, а не на последний функциональный и
не на первый свободный.** Значение по умолчанию тут ничего не значит: лямбда ушла в `modifier`,
`onClick` остался незаполненным. Отсюда обе ошибки на одну строку — «нет onClick» и «Function0
вместо Modifier». До 6.27.1 весь проект передавал `onClick` пятым позиционным аргументом, и мина
лежала непотревоженной десять версий.

## Что исправлено

**1. Порядок параметров `PillChip` приведён к конвенции Compose:** `modifier` — последний
параметр со значением по умолчанию, слот `onClick` — за ним. Теперь хвостовая лямбда попадает
туда, куда её и целят, и следующий такой вызов не сломает сборку.

**2. Все вызовы `PillChip` переведены на именованный `onClick`** (`LibraryScreen.kt` — 4 чипа
фильтра медиатеки, `SearchScreen.kt` — вкладки результатов). Именованный аргумент к порядку
параметров нечувствителен: перестановка в объявлении больше не молчаливо переназначает
аргументы на стороне вызова. `PlayerScreen.kt` уже вызывал именованно — не тронут.
`Sheets.kt` оставлен как есть, хвостовой лямбдой: она наконец законна.

Ошибок компиляции больше нет: Kotlin выдаёт все ошибки фазы за один проход, и в логе 6.27.1 их
было четыре — все четыре про эти две строки. Других расхождений компилятор не видел.

## Чтобы это не повторилось

`tools/check_call_args.py` — третья проверка в тот же ряд, что `check_kotlin_syntax.py` и
`check_static_refs.py`. Сверяет вызовы функций проекта с их объявлениями: куда сядет хвостовая
лямбда, существуют ли именованные аргументы, заполнены ли параметры без значения по умолчанию,
не больше ли позиционных аргументов, чем параметров. Ровно этот класс ошибок обе прежние
проверки пропускали: синтаксис 6.27.1 был безупречен, ссылки — все живые.

Проверка встроена в `.github/workflows/build.yml` шагом «Аргументы вызовов» **перед** Gradle и
намеренно **не роняет сборку** (`|| true`): парсер эвристический, у него есть шум на аргументах
вида `if (a < b)`, и превращать шум в отказ релиза было бы хуже самого шума. На текущем дереве
она печатает три подозрения — все три проверены руками и ложные (`EqSlider` ×2: `onChange`
передан, сбой разбора на `<` в теле аргумента; `content()` в `PlayerScreen.kt:850` — вызов
лямбда-параметра, одноимённого с `PoTokenMinter.content`).

## Что проверено и что нет

**Проверено статикой:** `check_kotlin_syntax.py` — 0 замечаний; `check_static_refs.py` — 0
подозрений; `check_call_args.py` — 0 настоящих. Отдельно сверена рантайм-критика 6.27.1, потому
что компилятор до неё не доходит: `version = 9`, `FavoriteShadowEntity` в списке entities,
`MIGRATION_8_9` зарегистрирована в `ZiziApplication` в цепочке 1→9, SQL таблицы `favorite_shadow`
поле в поле совпадает с сущностью, `ALTER TABLE playlists ADD COLUMN coverUri TEXT` — без
`DEFAULT`, как и котлиновский `coverUri: String? = null` (та самая мина `2_3`/`3_4`/`6_7` не
наступлена).

**Не проверено:** сборка Gradle. В песочнице нет Android SDK и нет сети до `dl.google.com` —
компилятор эту версию не видел. Первый зелёный `assembleRelease` в Actions остаётся обязательным
шагом, и говорить «собирается» до него я не стану.
