## Что исправлено

Обложка больше не получает только целочисленный `firstVisibleItemScrollOffset` в фазе слияния.
Новый `CollectionScrollPrecision` сохраняет дробную часть **фактически потреблённой списком**
прокрутки из `NestedScrollConnection.onPostScroll(consumed.y, ...)`.
Родительское сжатие шапки и непринятые движения не прибавляются второй раз. Прокруткой по-прежнему
управляет единственный LazyColumn; новый класс не потребляет жесты и не запускает анимации.

Перед очередным событием координата сверяется с реальными index/offset списка. При переходе между
элементами, внешней перестановке и восстановлении используется реальное состояние списка, без
угадывания высот строк. Когда hero отсутствует, сохранена безопасная насыщенная координата из 6.69.11.
Дробь не сбрасывается при отпускании пальца. На смене плотности создаётся новый якорь и обновляется
зависимость прозрачности панели. В частично сжатой первой фазе координата списка остаётся нулевой.

Предел согласованности с целочисленным списком — 1,0001 px, а **не мёртвая зона для пальца**.
Он учитывает неизвестный начальный остаток Compose и последующее округление layout (примерно по
0,5 px). Внутри этого предела каждое конечное потреблённое дробное движение применяется сразу.
Накопление выполняется в Double; отрисовка, как и раньше, получает Float.

В маске удалён `Path.combine(PathOperation.Union, ...)`. Вместо булева решателя используется один
путь `NonZero` с двумя одинаково направленными контурами: тело и выступ соединения. Направление
`addRoundRect` задано **Clockwise явно** — стандартное CounterClockwise отменяло бы заполнение
перекрытия. Остались один clip, один экземпляр изображения, одна запись исходного слоя и один
проход затемнения. Форма, кривая раскрытия, размытие и поглощение из 6.69.13 не перенастраивались.
`CameraMorphGeometry.java` сохранён побайтно. Нижняя подложка, аудио, БД и backend не менялись.

Инвентарь CI теперь **36 тестов на API 28 и 38 на API 35**; проверка полноты сохранена.

Логи этого выпуска находятся в `verification/v6.69.14/`. Старые логи в архиве относятся к прежним

## Как применить

Загрузить **ZiziPlayer-v6.69.14.zip** в корень репозитория. Текущий корневой workflow сверён с GitHub
и не менялся; он выбирает полный проект с максимальным versionCode, здесь 139. Не оставлять два
разных ZIP с одинаковым максимальным versionCode. Копировать файлы вручную поверх исходников не нужно.

Дождаться успешного APK job. Отдельно запустить **Build & release ZiziPlayer APK** с
`run_camera_tests = true` и проверить полный результат camera-regression, а не только факт сборки.
APK с прежней подписью ставить поверх установленного приложения, без очистки данных.

На Poco проверить медленный подход к контакту, удержание 3–5 секунд, микродвижения в обе стороны,
отпускание пальца, полное поглощение и возврат. Также проверить телефон, где прежняя версия работала
нормально, и возврат в глубоко прокрученную подборку. Желательно сравнить доступные режимы 60/120 Hz.

Если дрожание сохранится, в уже существующей служебной диагностике «Слияние обложки с камерой»
добавлена кнопка **«Начать запись движений»**. После короткого воспроизведения вернуться туда,
остановить запись и скопировать числа. По умолчанию запись выключена; это кольцевой буфер последних
240 событий только в памяти, без logcat, файлов и сетевой отправки. `raw/itemPx` — целочисленное и
дробное смещение первого видимого элемента; при index=0 это вход hero. `draw px/p/u/joined` — вход и
параметры кадра. Для глубокого списка draw px намеренно насыщен, а не равен itemPx. Время лишь
маркирует события и не участвует в эффекте. Запись не содержит треков или изображений.
