# Установка исходников Desktop 0.3.2 preview

## Что это

`ZiziDesktop-0.3.2-repo-update.zip` — пакет обновления репозитория, **не готовый EXE**. Он содержит новый ZIP исходников, `desktop/current.json`, CI-скрипты, desktop workflow и документацию. Android ZIP, Android workflow и серверные исходники пакет не заменяет.

База — пакет 0.3.1 из этой беседы. Если в репозитории после него уже появились собственные изменения десктопа/CI, сначала сравни файлы: свежую удалённую ветку в этом ходе проверить не удалось.

## Обновление и сборка

1. Сохрани рабочую папку приложения 0.3.1. Лучше вносить исходники новой версией в отдельную ветку репозитория.
2. Распакуй **внешний** ZIP в корень репозитория с сохранением путей. Важны `.github/workflows/desktop.yml`, каталог `ci`, новый `desktop/current.json` и `desktop/releases/ZiziDesktop-0.3.2-preview-source.zip`. Просто загрузить внешний ZIP в GitHub недостаточно.
3. Закоммить и отправь изменения. Действующий desktop workflow запускается вручную через GitHub Actions → **Build Zizi Desktop Windows preview (manual)**. Если workflow уже находится в основной ветке, можно выбрать новую ветку в Run workflow.
4. Сохрани прежний secret `RESOLVER_TOKEN` и конфигурацию `RESOLVER_URL`. Используй **тот же режим `allow_http`**, на котором заработала 0.3.1. Для HTTP нужен этот флаг либо repository variable `DESKTOP_ALLOW_HTTP=true`; для HTTPS разрешение HTTP не нужно. Не публикуй значения токенов в коде, скриншотах или сообщениях.
5. Дождись успешных source-checks, тестов и `createDistributable`. Если Kotlin/Compose не соберётся, скачай `ZiziDesktop-test-reports`: пакет исходников ещё не проходил такую компиляцию в этой среде.
6. Скачай artifact `ZiziDesktop-Windows-x64-0.3.2-preview`, распакуй **всю папку**, а не один EXE. Запусти новую копию отдельно от старой.

FFmpeg остаётся внешним компонентом. Сохранённый путь 0.3.1 используется дальше. Если его требуется изменить: **Настройки → О приложении → Диагностика и аудиодекодер**. FFprobe должен лежать рядом с FFmpeg. Тестовая установка FFmpeg на CI runner не встраивается в пользовательскую сборку.

## Первый запуск и данные

Списки 0.3.1 были сеансовыми и не сохранялись: автоматически восстановить их из старого EXE нельзя. Добавь свои папки/файлы и сохрани нужные сетевые треки в новую медиатеку. С этого этапа библиотека, плейлисты, очередь и настройки хранятся между запусками.

Данные Windows: `%LOCALAPPDATA%/ZiziPlayer`. Открыть папку можно из настроек. Не запускай две копии 0.3.2 одновременно с одним каталогом данных: межпроцессная блокировка пока не реализована. Резервная копия JSON помогает восстановлению, но не заменяет пользовательский backup.

## Проверка на ПК

Проверь сначала локальные треки, затем сеть. Создай плейлист, переставь песни, добавь избранное; закрой и снова открой приложение. Включи/выключи «Цвет из обложки» на яркой и чёрно-белой картинке, переключи несколько песен подряд. Проверь повтор одного трека, повтор очереди, перемешивание, перемотку и паузу.

Поиск имеет вкладки треков, исполнителей, альбомов и плейлистов. Открой исполнителя, проверь именно его фото и подгрузку списка. Если сервер отвечает 404 на новый раздел, не отключай авторизацию: живой сервер может ещё не иметь browse-эндпоинтов, которые присутствуют в мобильных исходниках 6.39.9.

Скачай один трек через меню `…`, дождись завершения; затем проверь проигрывание без сети. Незавершённые загрузки не должны отображаться как скачанные. Удаление офлайн-файла проверяй после выбора другого трека.

Список ещё не перенесённых мобильных функций и подробные ограничения смотри в `docs/desktop/REVIEW_0.3.2.md`. Результат не объявлен полным паритетом или готовым стабильным релизом.
