# ZiziPlayer 6.95.2 / versionCode 235

Полный ZIP исходников мобильной версии, **не APK**. База — публичный
`ZiziPlayer-v6.95.1-source.zip` (6.95.1 / 234). Правки предыдущего запуска сохранены,
проверены и дополнены. Сервер и зависимости не изменены.

## Исправления скачивания и отправки

Статус «Скачано» больше не берётся без проверки из старого состояния `Done`.
При открытии меню и возврате в приложение проверяется читаемость и размер сохранённой
копии. Перед отправкой файла проверка принудительная, без доверия к кэшу
статуса. Исходный TTL воспроизведения 5 секунд сохранён отдельно.

Полная последовательность в коде: скачать во временный файл → проверить длину ответа
(если сервер её объявил) и сигнатуру контейнера → скопировать в постоянное хранилище →
проверить размер и чтение → сохранить индекс → подтвердить успех. HTML, JSON и M3U
больше не объявляются M4A по умолчанию. Определение контейнера делается по началу
завершённого временного файла, а не по первому, потенциально очень короткому сетевому блоку.
Это не полное декодирование звука: для потока без известной длины одна сигнатура
не доказывает, что сервер передал всю композицию.

Цели сохранения: `Music/Zizi` через MediaStore → `Download/Zizi` через MediaStore Downloads →
публичная `Music/Zizi`, если ОС разрешает → папка приложения. Резервная папка приложения
теперь доступна через FileProvider, в том числе внутренняя `files/Music/Zizi`.
Внутреннее сохранение не превращает эту папку в общедоступную: Android может скрывать её
от проводника, но приложение может отправить файл через выданный URI.

Индекс пишется через AtomicFile под общей блокировкой: параллельные загрузки не делят один
временный файл индекса и не перезаписывают более свежую запись старым снимком.
Запись индекса проверяется чтением, ошибки больше не скрываются за успешным уведомлением.
Удаление согласовано с публикацией. Временные файлы имеют уникальные имена; стартовая уборка
не удаляет свежие `.part`. Уборка MediaStore ограничена своими старыми pending-записями
в обеих целевых папках. Если старый индекс не читается, уборка ничего не удаляет,
онлайн-воспроизведение остаётся доступным, а явная операция сообщает об ошибке индекса.

Отправка использует `EXTRA_STREAM`, `ClipData` и временное разрешение чтения.
Если аудиокопии нет, показывается сообщение, а не текст с названием трека.
Это относится и к ещё не скачанному сетевому треку: сначала его нужно скачать.
Пакетная загрузка использует тот же загрузчик; диалог повторно проверяет завершённые
файлы и показывает ошибку проверки вместо ложной готовности.

## Плейлисты и медиатека

По исходникам подтверждена ошибка **контекста меню**: плеер брал последний открытый
плейлист и мог предлагать «Убрать из …» для постороннего трека. Теперь нужны одновременно
правильный источник очереди и реальное членство трека в этом плейлисте.
В меню строки медиатеки также проверяется членство.

Поток состава открытого плейлиста теперь несёт его ID: при быстром переключении
результат предыдущего запроса не отображается как состав нового плейлиста.
«Во все треки», «В избранное», «Скачать на устройство» и «Добавить в плейлист» остаются
разными действиями. Первые три не записывают связь с открытым плейлистом.

В проверенной цепочке импорта автоматическое добавление постороннего сохранённого трека
не найдено. Утверждать, что скриншот доказывает изменение состава плейлиста, нельзя.
Автоматической чистки пользовательских плейлистов в этой версии нет.

## Повторное добавление и «Недавние»

Повторный `+` / нажатие на отметку сохранённого трека обновляет время сохранения;
удаление вынесено в явный пункт «Убрать из всех треков». Для «Всех треков» сортировка
использует время сохранения, а не время первого знакомства с треком.
Избранное получает порядок по времени добавления в избранное, без последующей
пересортировки по возрасту самого трека.

Для уже избранного трека добавлен пункт **«Добавить заново в начало избранного»**.
Заполненное сердечко по-прежнему снимает лайк. Повторное добавление поднимает
существующую запись, **не плодит дубли**, не сбрасывает статистику и не затрагивает
членство в плейлистах. Ранее скрытая запись снова становится видимой.
Сохранённый ручной порядок обновляется только в нужной коллекции — TRACKS или FAVORITES.
При одинаковом времени или переводе часов назад новое сохранение всё равно получает
метку строго выше предыдущих. Сортировки по алфавиту и длительности не заменяются
автоматически режимом «Недавние».

## Данные и ограничения обновления

Room остаётся версии 11: схема, ключи треков и миграции не изменены.
Нет удаления пользовательской базы, пересоздания плейлистов или сброса избранного.

Обновление не может восстановить байты файлов, которых уже нет. Такие треки нужно
скачать заново. Повреждённый старый индекс не перезаписывается пустым автоматически:
ошибка выдаётся явно, сами аудиофайлы не удаляются. Для такой ситуации нужен отдельный
разбор индекса/отчёта, а не удаление приложения.

## Проверки

Локально прошли **160/160 скриптов `tools/test_*.py`**: это смесь исполняемых Java/Python
тестов, SQL-проверок и проверок связей в исходниках, **не 160 тестов Android**.
Новый набор содержит 15 тестов; внутри него выполнены 38 проверок рабочего Java-кода
определения контейнера и полноты загрузки. Запросы времени сохранения взяты прямо
из DAO и исполнены на SQLite. Четыре целевые проверки отдельно запущены против 6.95.1:
все четыре обнаружили старое поведение, как и ожидалось.

Проверки структуры Kotlin, импортов, ссылок, схемы и whitespace прошли.
Эвристическая проверка аргументов по всем source set выдаёт шесть предупреждений,
**дословно совпадающих с базовой 6.95.1**. Это не Kotlin-компиляция.

Добавлены Android-тесты настоящего Room DAO и хранилища/FileProvider:
`LibraryRecency6952Test` (4 сценария) и `OfflineFiles6952Test` (2 сценария).
Они **не запускались**. Android-сборка, MediaStore конкретной прошивки, перезапуск процесса,
реальная сеть и получение аудио мессенджером также **не проверены**.
В the Computer нет Gradle-дистрибутива, Kotlin-компилятора, Android SDK и устройства;
в исходном ZIP нет запускаемого Gradle wrapper/JAR. Сетевые домены не разрешены.

Актуальные логи и машиночитаемый итог: `VALIDATION_6.95.2/RESULTS.json`.
Старые папки verification/VALIDATION — история прежних выпусков, не результат этой проверки.

## Сборка и установка

Загрузить `ZiziPlayer-v6.95.2-source.zip` в корень GitHub-репозитория.
В сохранённой конфигурации workflow архив выбирается по максимальному `versionCode`;
у этого пакета **235**, у 6.95.1 — 234. GitHub и Actions в этой работе не изменялись/не запускались.

Сборка требует обычного Android-окружения проекта (JDK 17, Gradle 8.11.1, SDK 36,
как в workflow). Для обновления поверх установленного приложения нужен прежний ключ
подписи. **Не удалять установленный ZiziPlayer и не очищать данные** ради установки.
Перед испытанием полезно экспортировать важные плейлисты.

Для инструментальных тестов использовать отдельное тестовое приложение/устройство,
не пользовательскую медиатеку: тест хранилища создаёт и удаляет свои временные аудиофайлы.
Команда в подготовленном окружении: `gradle :app:connectedDebugAndroidTest`
с фильтром `-Pandroid.testInstrumentationRunnerArguments.class=app.ziziplayer.data.LibraryRecency6952Test,app.ziziplayer.playback.OfflineFiles6952Test`.

## Приёмка на телефоне после сборки

1. Скачать один ранее не скачанный трек. Проверить показанный путь, размер, воспроизведение
   без сети и получение настоящего вложения в мессенджере.
2. Перезапустить приложение/процесс, повторить офлайн-воспроизведение и отправку.
3. Удалить тестовый скачанный файл внешним проводником. Вернуться в Zizi: не должно
   оставаться «Скачано» или отправки текста под видом файла; повторное скачивание доступно.
4. Скачать несколько треков параллельно и плейлист. Проверить все файлы после перезапуска,
   отмену, повторную попытку, отсутствие ложных 100% при ошибке или нехватке места.
5. Запустить трек A с главной, открыть/импортировать плейлист B без A. В меню A не должно
   быть «Убрать из B»; сохранение A не должно менять состав B.
6. При «Недавние» сохранить A, затем B, затем снова A: A первый, запись одна.
   Повторить с избранным через «Добавить заново…»; сердечко отдельно снимает лайк.
7. Проверить режимы с ручным порядком, локальными треками, быстрым переключением
   плейлистов, Android 8–9 с отказом разрешения и современной ОС с закрытой папкой приложения.
