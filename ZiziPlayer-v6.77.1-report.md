# ZiziPlayer 6.77.1 — меню трека в поиске

**Полный мобильный проект, versionCode 162. ZIP исходников, не APK.**
Основа: `ZiziPlayer-v6.77.0.zip` из публичного репозитория `Eren2932/ZiziPlayer`,
commit `22de70c10e0e1d881f2b6b1dcd8692f0ae526922` (последний мобильный ZIP на момент загрузки).
Серверы, аудиотракт, схема Room, поле поиска и библиотека не изменялись.

## Что исправлено

### Одно открытие, без экрана подготовки

В 6.77.0 `SearchTrackActionsHost` сначала передавал пустой список действий и текст
«Подготавливаем действия…», ожидал Room, затем подменял содержимое кнопками. В исходнике
был один `Dialog`, но два последовательных состояния его содержимого. Дополнительно
строка загрузки вставлялась после чтения индекса скачанных файлов.

Теперь всё меню строится синхронно из уже имеющегося `RemoteTrack`. Открытие не ожидает
и не записывает запись трека в БД. Строка загрузки существует сразу; до завершения
проверки скачанной копии она временно неактивна, но не сдвигает соседние строки.

Подготовка авторитетной записи выполняется только после выбора действия, **до** закрытия
и исполнения. В выбранной строке может появиться небольшой индикатор, но окно и список
не заменяются. Повторные нажатия блокируются. «Назад»/тап вне панели отменяют подготовку;
отложенное действие после закрытия не запускается. При ошибке сообщение находится в
том же прокручиваемом списке, и действие можно повторить. Дочерние окна по-прежнему
живут вне закрываемого меню. Отключена отдельная системная анимация `Dialog`: остаётся
одна анимация шторки. Восстановленная раскрытая панель не раскрывается повторно.

### Видимая область и последняя кнопка

У старой панели внутренний список имел полную высоту раскрытого листа даже тогда,
когда часть листа была сдвинута за нижнюю границу окна. Теперь разделены:

- фиксированная наружная высота — она задаёт стабильные якоря Material;
- внутренняя видимая область — пересечение листа с фактическим окном;
- системные отступы — нижний и боковые `safeDrawing` учитываются один раз.

Высота списка пересчитывается на этапе измерения, без пересоздания окна и без
самописного распознавания жестов. Верхний отступ учитывает status bar/вырез.
У списка есть нижний запас 16 dp. На низком экране или при шрифте от 150% шапка
прокручивается вместе с действиями, а не отнимает всю высоту. Прокрутка сохраняется
при обновлении подписей/состояний действий.

Формула внутренней высоты в пикселях: минимум наружной высоты и оставшегося расстояния
от текущего верхнего края панели до низа безопасного окна. Округление вверх верхнего
края не допускает дополнительного пикселя за нижней границей. Реализация и проверки:
`SearchMenuGeometry.java`, `SearchMenu6771Checks.java`.

Важно: все 12 пунктов не обязаны одновременно помещаться на любом размере экрана.
Последний пункт должен быть полностью доступен после прокрутки, в том числе при
крупном шрифте. Полноэкранное поведение на конкретном телефоне требует Android-приёмки.

### Цвета

Использованы те же `NeutralSurfaceTheme` и `LocalPalette`, что у стандартного меню
плеера: фон **#101010**, текст/иконки/разделитель из общей палитры, tonal elevation 0.
Жёстко заданный серый фон #1F1F1F удалён. Цвет текущей обложки не окрашивает это окно.

## Как применить

Загрузить **`ZiziPlayer-v6.77.1.zip` как ZIP в корень репозитория**. Существующий
`.github/workflows/build.yml` выбирает проект по максимальному `versionCode`;
162 выше прежнего 161. Для обычной сборки APK workflow менять не нужно.
Не создавать второй ZIP с тем же максимальным versionCode.

Для Android-регрессий из распакованного проекта:
`bash tools/run_search_menu_ui_6771.sh`. Этот набор не включается автоматически
старой опцией camera-only. После успешной сборки установить APK с прежней подписью
поверх текущего приложения, без удаления данных, и выполнить чек-лист.

Изменённые файлы и SHA-256: `verification/v6.77.1/changed-files.json`.
Точный diff: `verification/v6.77.1/changes.patch`.
