## Почему упала 6.54.0

Четыре `Unresolved reference 'Text'` в `MainActivity.kt:866–871` вызваны отсутствующим импортом `androidx.compose.material3.Text`. Импорт добавлен.

Ошибка в `HomeScreen.kt:153` возникла из-за `val app = ...`: в выражении `app.ziziplayer.ui.components.AccountAvatar(...)` идентификатор `app` обозначал экземпляр приложения, а не корневой пакет. Добавлен импорт `AccountAvatar`, вызов заменён на неквалифицированный.

Предупреждение AGP 8.7.3 о compileSdk 36 не было причиной указанного падения. AGP/Kotlin/SDK не обновлялись ради этой ошибки. Сообщение о DEBUG-подписи на этапе unit tests также не является причиной Kotlin-ошибок: workflow подставляет релизный ключ позже, перед assembleRelease.

Проверка импортов дополнена `Text` и точной границей имени: полная ссылка на `TextButton` больше не считается ссылкой на `Text`. Проверка запущена против оригинальных 6.54.0: теперь находит пропущенный импорт и возвращает 1. На исправленных исходниках — 0. Это полезный регрессионный барьер, но не замена Kotlin-компилятору.

## Навигация и сохранение ввода

Вместо фиксированного `page.parent` используется реальная история `AuthHistory<AuthStep>`. Например, проверка почты после регистрации возвращает на пароль регистрации, а после входа — на пароль входа. Переход из входа в регистрацию также остаётся в истории. Верхняя стрелка и системный Back используют одну функцию.

История синхронно блокирует вторую команду до завершения текущей анимации, включая второй клик до рекомпозиции. Завершение старой анимации не разблокирует новую: проверяется номер транзакции. UI получает наблюдаемое состояние блокировки. Форма недоступна для действий, пока внешний экран ещё въезжает/уезжает. Back в это время поглощается, а не передаётся нижележащему плееру.

Черновики входа, регистрации и восстановления разделены. Простой переход назад больше не очищает пароль и его повтор; повторный переход вперёд возвращает их. Изменение адреса очищает секреты соответствующего черновика, чтобы случайно не отправить старый пароль для другой личности. Закрытие заполненного корневого шага требует подтверждения.

После успешной отправки регистрации, проверки кода или смены пароля секреты очищаются намеренно. Когда это возможно, очистка отложена до ухода старого экрана, чтобы поля не мигали пустыми на выезде. После успешной проверки/сброса строится свежая история входа без возврата к уже использованному коду. При сетевой ошибке заполнение остаётся для повторной попытки.

**Предел сохранности:** черновики находятся только в RAM текущей композиции. Они не записываются в Bundle, preferences, логи или на диск. Закрытие формы с подтверждением, пересоздание Activity (включая поворот) и завершение процесса могут удалить их; восстановление после этих событий в этот патч не входит. Сохранение здесь гарантируется логикой переходов внутри открытой формы, а не долговременным хранилищем. `FLAG_SECURE` сохранён. Обнуление ссылок на строки не является гарантированным криптографическим затиранием JVM-памяти.

## Переходы и клавиатура

Направление анимации записывается в неизменяемую транзакцию `AuthRoute`, а не читается из общего изменяемого `backwards`. Убрана отдельная анимация размера `SizeTransform`: изменение доступной высоты уже обрабатывают системные IME-insets. Убран отступ `24% высоты экрана`, изменявший положение формы при появлении клавиатуры. Внутренние переходы сохраняют длительность 240 мс. Это устраняет найденные в коде механизмы скачков; FPS, субъективная плавность и точная причина каждого рывка на телефоне без рендера не установлены.

Форма прокручивается в отдельной области. Нижние «Уже есть аккаунт? / Войти» и «Нет аккаунта? / Зарегистрироваться» расположены вне её прокрутки, над IME, с учётом системных панелей и выреза. Ширина контента ограничена 560 dp; боковые поля формы — 20 dp. Высота кнопки ссылки — не меньше 48 dp. На обычной доступной высоте нижняя группа видна полностью. При экстремально малой высоте/крупном шрифте она имеет собственную прокрутку, а не перекрывает поля. Действие «Продолжить» и вспомогательные действия пароля остаются в прокручиваемой форме.

Для регистрации/сброса добавлено настоящее действие IME «Далее»: код → пароль → повтор пароля; финальное «Готово» отправляет форму. При входе «Готово» в пароле выполняет вход.

### Расчёт ограничений

Для обычного пристыкованного IME пусть H — доступная высота окна. После расходуемых Compose-insets высота V приблизительно равна `max(0, H − верхний безопасный отступ − max(нижний системный отступ, нижний вырез, высота IME))`. Нижний системный отступ и IME не складываются повторно. Insets берутся из системы, а не из жёстко заданной высоты клавиатуры.

Пусть N — естественная высота нижней группы с текущим масштабом шрифта. В коде `F = min(N, 0.4 × V)`, `B = V − F`, где F — область нижней группы, B — область формы. Поэтому форма сохраняет не менее 60% доступной высоты, а группы не перекрываются. Если N больше F, содержимое нижней группы прокручивается. Это ограничение компоновки, не результаты измерений Android-рендера.

Обещать одновременную полную видимость всех полей, больших шрифтов и кнопок при произвольно малом остатке экрана физически невозможно. Плавающие/OEM-клавиатуры также требуют отдельной приёмки: их перекрытие не всегда отражается нижним IME-inset.

## Как применить

Загрузить **именно `ZiziPlayer-v6.54.1.zip` целиком** в корень репозитория на main. Распаковывать его в корень GitHub не нужно: существующий workflow сам распакует источник. Предыдущий ZIP можно оставить: 105 больше 104. Не добавлять второй архив с тем же максимальным versionCode 105.

Корневой `.github/workflows/build.yml` побайтово совпадает с обеими копиями внутри комплекта и не требует замены. После push должен стартовать Build & release ZiziPlayer APK. Дождаться успеха Kotlin compile and JVM tests, затем Assemble release. Настройки ACCOUNT_URL, ключи подписи и секреты не менять. VPS для этого исправления обновлять не нужно.

Устанавливать APK с прежней подписью поверх существующего приложения, без удаления приложения и очистки данных. Если подпись отличается, не удалять единственную копию медиатеки ради установки: сначала разобраться с подписью и резервной копией. Приложенный ZIP не содержит готового APK.
