# ZiziPlayer 6.43.0 — визуальная доработка и адресный аудит

**Статус: кандидат исходников, не собранный APK.** Основа — мобильный ZIP 6.42.0 из Eren2932/ZiziPlayer, commit `e436c14e55748197b3ca80a3f291a0bcaa384f8c`. Версия Android повышена до **6.43.0 / versionCode 91**. Сервер, desktop, Room-схемы и аудиотракт не изменены.

## Математика затемнения и загрузки

Нижняя вуаль использует существующий smoothstep. Для нормализованного положения t сначала берётся clamp(t, 0, 1), затем alpha = 0.65 × t² × (3 − 2t). Значения: 0 в начале, 0.325 посередине и 0.65 на плато. Это непрозрачность чёрного слоя, а не alpha всего нижнего интерфейса.

Полоса загрузки показывает **готовность подборки с одинаковым весом треков**, а не долю байтов. Готовые локальные и скачанные файлы учитываются полностью, известный процент текущих загрузок — частично. При неизвестной длине активного скачивания используется неопределённая полоса: окно не выдумывает проценты. Проверка файлов выполняется в IO и не повторяется на каждом обновлении прогресса. Полоса известного прогресса сглаживается за 180 мс. Закрытие диалога не отменяет загрузки; отдельная отмена ограничена треками этой подборки.

## Объективный аудит

В проекте нативный Kotlin/Compose-интерфейс, Media3 для воспроизведения, Room/DataStore для данных и настроек, общий движок офлайн-загрузок и кеш обложек. ZIP также содержит сервер, историческую документацию и отчёты — они не становятся исполняемыми Android-компонентами только из-за нахождения в архиве.

Удалены две практически одинаковые реализации рисования заглушки: теперь одна. Удалены неиспользуемые после этого функции `fallbackSwatches`, `fallbackSwatchesFor`, `fallbackColors`, генерация HSV-палитр и повторный запрос цвета в шапке меню. Исчезла и отдельная анимация декоративного фона этой шапки.

Два старых наблюдателя корневого списка сведены к одному и выключены, когда показан отдельный экран подборки со своим владельцем прокрутки. Исправлено сохранение старой очереди обложек: пустой `submit` теперь очищает `lastTracks` и ссылку на отменённую задачу, поэтому `resume` не поднимает прежний список. Ключ предзагрузки теперь учитывает упорядоченные ID всех треков, а не только количество и первый ID: разные подборки с одинаковыми этими двумя признаками больше не считаются одним списком.

Проверка SHA-256 всех файлов `app/src/main` обнаружила только одну группу полностью одинаковых файлов: стандартный и круглый launcher XML. Это штатные альтернативные ресурсы, а не два работающих плеера; они оставлены. Полное семантическое отсутствие похожего кода этот метод не доказывает. В проверенных участках жизненного цикла PlayerController снимает слушатель и освобождает future, PlaybackService снимает слушатель хранилища и освобождает плеер/сессию; признаков незакрытой регистрации в этих местах не обнаружено.

Зависимость `material-icons-extended` пока не удалена: два настоящих обращения остаются в VaultAuthDialog (отпечаток и стирание). Удалять её, опираясь на старый комментарий «все иконки свои», означало бы сломать сборку. Унаследованные функции `cardTop` и `topContentTint` остаются кандидатами на отдельную очистку; они не вызываются в переработанных зонах, но широкое удаление чужих контрактов не смешивалось с этим UI-патчем.

Основные крупные UI-файлы всё ещё монолитны: Sheets, LibraryScreen и MainViewModel. Размер исходника сам по себе не равен расходу CPU; дальнейшее разделение разумно делать отдельной задачей с Android-сборкой. Пять файлов шрифтов — разные начертания, не побайтовые дубликаты. Исторические отчёты не удалялись ради фиктивного обещания уменьшить APK. Новых зависимостей нет. Оценку экономии размера APK, RAM или FPS без сборки и профилирования не заявляем.

Отдельно замечено: корневой `current.json` публичного репозитория указывает на desktop. Для этой работы мобильная база определялась по Android ZIP и `app/build.gradle.kts`, desktop-манифест не менялся.

## Что проверено

Успешны **31 локальная команда**, в том числе общий preflight с 8 фикстурами проверяющего инструмента, четыре статические проверки, `git diff --check` и все **25 самостоятельных тестовых скриптов**. Существующие контракты обновлены там, где они намеренно требовали старую окраску меню, 58% или прежний номер версии. Новые проверки закрепляют нейтральную заглушку, интеграцию панели, состояния прогресса и исправления предзагрузки.

Java-математика выполнялась непосредственно из production-кода: геометрия, smoothstep, политики загрузок/переходов и новый расчёт прогресса. Журналы и коды завершения находятся в `verification/v6.43.0/`, итог — `results.json`. Новая JVM-обёртка `Polish6430Test.kt` добавлена для будущего Gradle CI, но здесь как Kotlin/JUnit-тест не запускалась.

**Не проверено:** компиляция Kotlin/Compose, Gradle unit tests целиком, сборка APK, скриншоты от Android, реальные скачивания, TalkBack, кадровые задержки и потребление памяти на телефоне. В the Computer отсутствуют Android SDK и Gradle. Статический preflight не заменяет компилятор. Релиз требует существующего GitHub Actions и приёмки на устройстве.

## Передача в репозиторий

Загрузить **`ZiziPlayer-v6.43.0.zip` целиком в корень существующего Eren2932/ZiziPlayer**, не распаковывать его поверх корня и не менять desktop `current.json`. Существующий Android workflow выбирает исходники по наибольшему versionCode; у новой версии он 91. Внутренний `.github/workflows/build.yml` — часть исходного проекта, но GitHub запускает workflow из корня репозитория. Ключи подписи и настройки сервера не менять. После успешной сборки выполнить `DEVICE_CHECKLIST_v6.43.0.md`.
