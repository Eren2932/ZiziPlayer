# ZiziPlayer 6.42.0 — экраны подборок и плавная нижняя вуаль

**Статус: кандидат исходников для сборки и проверки на устройстве. APK не собран в этой сессии.**

База: публичный репозиторий Eren2932/ZiziPlayer, ветка main, архив `ZiziPlayer-v6.41.4.zip`, полученный 13 сентября 2026 года. Это последний Android ZIP в полученном снимке репозитория. Корневой `current.json` относится к Desktop и не использовался для выбора Android-версии. Новая версия: `versionCode = 90`, `versionName = "6.42.0"`. Идентификатор приложения и схема Room не менялись.

## Нижняя зона

В 6.41.4 `bottomChrome()` рисовал один прямоугольник с чёрной альфой 0.50, начиная ровно от верхней границы dock. На оригинальном скриншоте ZiziPlayer у левого края переход между строками 2061 и 2062 px меняет RGB приблизительно с (34,23,17) до (18,11,5). Это наблюдаемая резкая граница подложки, а не дефект формы капсулы.

Теперь один полноширинный градиент начинается прозрачно за 48 dp до dock и достигает чёрной альфы **0.58** на 72% его высоты; ниже сохраняется 0.58. Промежуточные точки получены функцией smoothstep, записанной в production Java и проверенной на JVM. Верхний и нижний концы математической кривой имеют нулевой наклон; шейдер приближает её 25 остановками. Нового скруглённого контейнера, blur, изменения alpha дочерних кнопок и дополнительного bitmap-слоя нет. Максимальное пропускание фона в нижней части — 42%, а не 58%.

Размеры, положение, тень и форма существующей капсулы сохранены. По уменьшенным превью её верх находится примерно на 1322 px против 1330 px у референса; в оригиналах это около 2062 против 2075 px. Это близкое положение, но не заявление о полном совпадении силуэта: у референса другая форма мини-плеера.

## Медиатека

Строка сортировки «Недавние» перенесена из неподвижной шапки в первый элемент LazyColumn **в обоих режимах**, списке и сетке. Заголовок и фильтры остаются неподвижными. Повторная чёрная вуаль на верхнем крае контента в этой точке больше не применяется. Баннер импорта сохраняется после сортировки. Состояние корневого списка хранится вне ветки экрана подборки, поэтому открытие карточки не уничтожает его позицию.

## Самостоятельные экраны подборок

Избранное, все треки, плейлист, папка и локальный исполнитель открывают `LocalCollectionScreen`, а не старый список под заголовком и чипами медиатеки. Это отдельная полноэкранная Compose-поверхность внутри существующей Activity; не Android-диалог и не новая Activity. Системная кнопка Back остаётся в общей навигации приложения.

Один LazyColumn содержит поиск, сортировку, большой заголовок, счётчик, действия и треки. Поверх него располагаются неподвижный toolbar и **единственная** круглая кнопка воспроизведения. Положение кнопки вычисляется из прокрутки с нижней границей; дубликата кнопки при сворачивании нет. Свёрнутый заголовок центрируется по ширине окна. Цвет toolbar постепенно становится непрозрачным. Длинный заголовок измеряется, и ему выделяется дополнительное место.

Цвет связан с типом открытой подборки, а не с текущей песней: избранное #984629, папки #246B68, плейлисты #8C4D32, исполнители #594681, все треки #345B79. База #121212, кнопка — существующий брендовый оранжевый. Это собственная палитра, а не копия синего/зелёного Spotify.

Короткий список тоже может свернуть шапку полностью: вычисляемый хвост содержимого обеспечивает необходимый диапазон прокрутки. Например, для шести треков, viewport 2292 и нижнего padding 350 эталонных единиц требуется 446 дополнительных единиц. Для длинных списков эта добавка равна нулю. Это не второй скроллер и не сдвиг viewport.

Поиск относится только к открытой подборке. Новая подборка не наследует запрос из поиска по карточкам. Back сначала завершает поиск, затем возвращает в родительский раздел. Долгое нажатие, множественный выбор и меню треков сохраняются. Кнопка «Импортировать музыку» открывает существующий импорт; она не обещает автоматически добавить импорт в текущую папку или избранное.

При первом открытии плейлиста сохраняется его ручной порядок. Явный выбор сортировки изменяет представление, не переписывая порядок записей в Room. Повторный вход снова использует ручной порядок. Сортировка остальных подборок использует существующую настройку приложения.

## Измеренная геометрия

Источники: оригинальные JPG 1080 × 2400. `154202` — развёрнутые любимые треки, `154206` — свёрнутые; `153940`/`153945` — библиотека до/после прокрутки. `151612` — исходный ZiziPlayer, `151412` — главная референса. Номера файлов надёжнее порядка превью в чате.

| Величина | Геометрия в эталонных единицах |
|---|---:|
| Ширина | 1080 |
| Статус-бар в примере | 108 |
| Высота toolbar ниже статус-бара | 162 |
| Диаметр Play | 140 |
| Отступ Play справа | 28 |
| Левый край Play | 912 |
| Play сверху, развёрнуто | 821 = 108 + 713 |
| Play сверху, свёрнуто | 203 = 108 + 95 |
| Чёрный треугольник, bbox по исходному JPEG | 42 × 47 |
| Поля списка | 46 |
| Обложка трека | 140 |
| Шаг строки при стандартном шрифте | 184 |

Пороговая маска JPEG даёт зелёный круг от x=913 шириной 139 px: антиалиасинг на краю объясняет разницу с конструктивными 140 px. Для Play добавлен отдельный вектор 140 × 140 с вершинами (54,45), (96,69), (54,92); старые значки мини-плеера не изменены. Для скачивания добавлена круговая стрелка.

Масштаб кода = доступная ширина в dp / 1080. Статус-бар берётся из WindowInsets, а не задаётся числом 108. Это измеренная геометрическая модель, **не результат pixel-diff готового Compose-экрана**. Растеризация текста, fontScale, системные inset, IME и край градиента требуют проверки на телефоне.

## Массовое скачивание

Диалог берёт `collectionTracks` — полное содержимое подборки до фильтрации поиском. В нём показываются локальные/готовые файлы, активные задания и ошибки. Можно скачать недостающие, повторить недокачанные или отменить задания данной подборки. Проверка существующих файлов выполняется на IO один раз при открытии; обновление процентов не вызывает повторное сканирование всей памяти.

Используется прежний `OfflineDownloads`: максимум два одновременных потока, foreground-сервис, временный файл, проверка длины/места и публикация через OfflineStore. Сохранение стремится в Музыка/Zizi; если Android запрещает общий каталог, прежний механизм использует доступный fallback, включая папку приложения. Уже локальные и готовые треки не дублируются. Возможность получить звук зависит от поддержки и доступности источника.

Регистрация задания теперь предшествует запуску. Completion-handler освобождает запись даже при отмене до входа в тело корутины. Отмена сохраняет регистрацию до завершения cleanup, чтобы повторный запуск не писал в тот же временный файл одновременно. Batch-policy не позволяет отменённому старому запросу позднее поставить ещё не обработанных участников обратно в очередь; новый явный запрос разрешён.

**Не добавлено:** сохранение незавершённой очереди после убийства процесса/перезагрузки, докачка с байтового смещения, гарантированный доступ к закрытым/недоступным источникам. После принудительного завершения нужно снова нажать скачивание недостающих; готовые файлы останутся. Сетевой сценарий и Android foreground-сервис в этой сессии не исполнялись.

## Проверки и выпуск

Выполнены четыре статические проверки проекта (скобки/строки Kotlin, импорты, статические ссылки, аргументы вызовов), общий `tools/check_selftest.py`, восемь новых проверок интеграции по исходникам и **30049 assertions исполнения production Java** для геометрии и batch-policy. Прежние проверки звука/переходов также исполняются общим preflight; это не прослушивание аудио и не запуск Media3 на устройстве.

Старые тесты требовали именно versionCode 89, прямоугольник 50% и закреплённую сортировку. Их утверждения обновлены под новый запрос, а не отключены. Начальный прогон выявил эти несовместимые ожидания; после миграции общий preflight прошёл. Полные журналы лежат в `verification/v6.42.0/`.

**Android SDK и Gradle отсутствуют в the Computer. Компиляция Kotlin/Compose, JUnit через Android Gradle Plugin, assembleRelease, установка APK, визуальный pixel-diff и проверка скачивания на телефоне не выполнены.** Успешный preflight не заменяет эти шаги.

Для сборки достаточно положить полный `ZiziPlayer-v6.42.0.zip` в корень репозитория. Существующий корневой workflow выбирает наибольший versionCode и выполняет preflight из архива, затем Android unit tests и assembleRelease. Сам ZIP не нужно распаковывать поверх Desktop; `current.json` менять не нужно. Из этой сессии изменения в GitHub не отправлялись.
