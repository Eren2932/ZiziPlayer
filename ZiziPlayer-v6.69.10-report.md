# ZiziPlayer 6.69.10 — камера, перемычка и возврат цвета

27 сентября 2026 · versionCode **135** · полный ZIP исходников, **не APK**.
Статус: локальные проверки пройдены; Android-сборка, Skia/Compose на эмуляторе
и проверка на реальном телефоне ещё НЕ выполнены. Это кандидат для сборки и проверки.

## Что изменено

В `CameraMorphGeometry.java` скорректированы сближение обложки, пространственный
допуск эффекта, рост капли и раскрытие шейки. Кривые зависят только от текущей
геометрии и прокрутки: нет таймера, задержки по направлению жеста или дополнительной
пружины. При возврате в ту же позицию формулы дают те же координаты и оттенок.
Рождение шейки имеет нулевую ширину; интерполяция её ширины монотонна, C1.
Это не означает постоянную скорость движения пальца или гарантию частоты кадров.

В `CollectionCoverMorph.kt` обложка и продолжение перемычки объединены через
`PathOperation.Union`. Вместо двух взаимодополняющих сглаженных вырезов теперь
один внешний контур. Под отражённой текстурой есть сплошная основа, а затемнение
наносится на объединение один раз. Это устраняет механизм внутреннего шва от
двойного покрытия антиалиасинга. Был ли именно он единственной причиной видимого
дрожания, без повторной записи с телефона утверждать нельзя.

Возвращающаяся обложка уже показывает рисунок, но ещё слегка приглушена — именно
остаточная чернота, а не задержка появления. При разрыве соединения общий оттенок
не переключается. Для контактного затемнения используются расстояния в радиусах
камеры: примерно 15% при u=3.07, 5% при u=3.58 и 0% при u>=4.10.
Глубже в камере обложка темнее, затем плавно включается полное поглощение.
Контактная и финальная чернота объединяются как `1-(1-finalInk)*(1-contactInk)`;
поверх остаётся локальный пространственный градиент шейки.

Скорректирована только оценка узкого OEM-прямоугольника от верхнего края экрана:
он не считается физическим диаметром отверстия. Приближённая визуальная точка
имеет диаметр 60% ширины reservation, нижняя граница сдвинута внутрь на 5% ширины.
Это художественная оценка по данному референсу, НЕ универсальная калибровка камеры.
Точный системный Path и допустимые компактные bounds не уменьшаются.
На другом телефоне с приблизительными bounds совмещение нужно проверить отдельно.

## Что показало видео

Основа: сохранённый `ZiziPlayer-v6.69.9.zip` из Eren2932/ZiziPlayer. SHA-256 исходного
ZIP и обоих видео, а также SHA дерева GitHub — в `verification/v6.69.10/inputs.json`.
Референс: `Screenrecording_20260927_125830.mp4`; старый Zizi:
`Screenrecording_20260927_151639.mp4`. Скриншоты DevZis — референс, не Zizi.

Видео референса 1080×2400 декодировано последовательно с его VFR timestamps.
Обратный ход отдельно измерен в `reverse-measurements.json`. Нижний участок
обложки сравнивался с тем же участком после выхода из зоны затемнения.

| 19.196 с | 3.615 | 5.6% |

Это относительная luma из gamma-encoded RGB сжатого видео, не физическая яркость.
Погрешности вносят кодек, оценка круга, рисунок и размытие. 29 независимых образцов
обратного хода включены в JVM-регрессию с допуском 4 процентных пункта.
Время в таблице описывает конкретный жест, НЕ встроенную задержку анимации.
Скрипт повторения: `python tools/visual/measure_camera_reference_66910.py reference.mp4 reverse.json`
(нужны OpenCV, NumPy, SciPy; видео в ZIP не дублируется).

В нормализованной центральной фикстуре при точном отверстии 37 px первое
соединение теперь происходит при зазоре 56.7 px вместо 48.1 px, ширина обложки
169.8 px вместо 166.5 px. В референсе переход лежит между выборочными кадрами
с зазором 58.6 и 55.6 px, диаметром 174.5 и 167.7 px.
Для приблизительной OEM-камеры новый зазор контакта 58.8 px, диаметр обложки 178.2 px.
Это сопоставление геометрии, НЕ pixel-perfect рендер нового APK.
При изменении размера fallback-точки контакт не обязан наступать раньше в процентах
скролла: сравнивать нужно расстояние и размер, а не только progress.

## Границы изменения и сборка

В production изменены два файла: CameraMorphGeometry.java и CollectionCoverMorph.kt;
плюс app/build.gradle.kts для версии. Аудио, серверы, Room, аккаунты, данные медиатеки,
сетевые настройки, nested-scroll и desktop не изменены.

Загрузить полный `ZiziPlayer-v6.69.10.zip` в корень репозитория привычным способом.
Сохранённый workflow выбирает источник по versionCode; новый код 135 больше 134.
Не оставлять другой ZIP с тем же наибольшим versionCode. Изменять workflow для
этого патча не требуется. Сборку/публикацию в GitHub из этого диалога не запускали.

На the Computer нет Gradle, Android SDK и эмулятора; APK не собран. На API 26–30
RenderEffect по-прежнему отсутствует: геометрия и затемнение обратимы, аппаратное
размытие предусмотрено только с API 31, как и в базе.

После зелёного Android CI проверить на телефоне медленное соединение/разрыв,
короткие смены направления у шейки, полный выход и повторный вход, быстрый fling,
разные изображения (светлое/тёмное/контрастное). Проверить совпадение визуальной
точки с физической камерой, отсутствие шва, остаточного пятна и мерцания оттенка.
Без этого нельзя обещать отсутствие всех визуальных багов или pixel-perfect
совпадение с референсом на GPU устройства.
