# ZiziPlayer 6.65.0 — HTTPS audio test release

VersionCode: **121**. Полный исходный проект на базе последнего 6.64.0-lyrics-timing (120), не откат к 6.63. APK здесь не собран.

## Изменения

Адрес аудиорезолвера по умолчанию — `https://ziziplayer-audio.duckdns.org`.
Gradle обрабатывает не только отсутствие RESOLVER_URL, но и пустую CI-переменную,
старое `147.45.166.244:8080`, `http://147.45.166.244:8080` и HTTP-вариант нового домена.
Сохранённый в DataStore старый корневой адрес переводится на HTTPS при чтении настроек.
Переход работает и для начальных UserSettings, без удаления приложения или очистки данных.
Это нормализация эффективного адреса, не стирание пользовательских настроек.
Другие серверы/порты/префиксы сохранены. Миграция намеренно не переписывает произвольные URL.
Токены, идентификатор установки, библиотека, аккаунт, кэш и выбор «Только Wi-Fi» не сбрасываются.
Проксирование аудио по умолчанию остаётся включённым; явно сохранённый выбор не меняется.

Сохранены изменения текстов из последнего 6.64. Дополнительно исправлено зависание
параллельного координатора при CancellationException дочернего провайдера: отменяется
канал результатов, чтобы ожидающий receive не зависал. Для соответствующего Kotlin/JUnit
теста добавлен предел 5 секунд и проверка исходной причины отмены. Coroutine runtime
тесты в the Computer НЕ выполнены; обязательный шаг GitHub :app:testDebugUnitTest сохранён.

Исправленные предварительные проверки из предыдущего разбора сохранены; ожидания текущей
версии обновлены на 6.65.0/121. Тесты не удалены и не отключены. Добавлены 18 исполняемых
Java-сценариев миграции с повторной проверкой идемпотентности и 5 Python integration checks.

## Что намеренно НЕ изменено

Аудиокодеки, битрейт, тайм-ауты, буфер, политика автоскипа, Media3 и исправление foreground
service в этот выпуск не входят. Автоадаптация качества НЕ реализована.
Это контролируемая проверка нового HTTPS-маршрута, не заявление об устранении всех сбоев МТС.
Серверные исходники аудио/аккаунтов/текстов не изменены; разворачивать их заново не требуется.
TLS-проверка сертификатов не отключена; аккаунты и тексты не переведены на аудиодомен.

## Проверки

23/23 локальных проверочных команды завершились с exit 0. В check_selftest: 434 unittest
cases плюс собственные Java/fixture-проверки. В остальных командах есть повторные проверки,
поэтому не суммировать их как уникальные тесты. Подробные логи: verification/v6.65.0/.
Синтаксические эвристики Kotlin, импорты, квалифицированные ссылки и аргументы — без замечаний.
Android Gradle, Kotlin/JUnit runtime, APK, подпись и телефон в the Computer НЕ проверены:
нет Gradle/Android SDK. Состояние нового HTTPS-сервера сообщено владельцем; живой запрос здесь
не выполнялся. Окончательный критерий сборки — зелёный GitHub Actions и проверка APK на телефоне.

## Как собрать в репозитории с исходниками в ZIP

1. Загрузить ZiziPlayer-v6.65.0.zip в корень Eren2932/ZiziPlayer и закоммитить.
   Архив полный, внутри корень проекта src/. Не класть туда второй ZIP с versionCode 121.
2. В Settings → Secrets and variables → Actions → Variables установить
   RESOLVER_URL=https://ziziplayer-audio.duckdns.org. Старый корневой IP и пустое значение
   также корректно обрабатываются кодом, но актуальная переменная делает конфигурацию ясной.
3. RESOLVER_TOKEN и секреты подписи оставить прежними. Не публиковать их в ZIP или чате.
   ACCOUNT_URL, LYRICS_SERVER_URL, GOOGLE_WEB_CLIENT_ID и DEV_UNLOCK_CODE не менять.
4. Существующий корневой workflow выбирает ZIP по максимальному versionCode, запускает
   preflight, Kotlin/JVM тесты, Android test compilation и assembleRelease.
   Изменять корневой workflow ради этой версии не требуется: новый тест включён в
   tools/check_selftest.py внутри ZIP. Вложенный .github/workflows сам по себе не запускается.
5. После зелёной сборки скачать артефакт ZiziPlayer-APK-v6.65.0.
   Ожидаемое имя APK — ZiziPlayer-v6.65.0.apk. Установить поверх 6.63/6.64 с ТЕМ ЖЕ ключом.
   При несовпадении подписи не удалять приложение: сначала восстановить прежние CI signing secrets.

## Проверка на телефоне

Убедиться: версия 6.65.0; «Только Wi-Fi» выключено; VPN выключен; авто-тексты для сравнения
пока выключены. Один и тот же доступный трек на Wi-Fi и МТС, экран включён, без перемотки и
смены очереди. Сначала серверный кэш прогреть, но различать его и локальный кэш телефона:
повтор из локального кэша не измеряет сеть. Отчёт «Задержки воспроизведения» сохранить.
Проверить на Nginx обращение к /match/deezer, /resolve и /stream; успешный /health не заменяет
проверку тела аудио, Range/206 и перемотки. Не выкладывать Authorization и подписанные URL.
Порт 8080 пока оставить для старых установок. HTTPS не снимает тарифные ограничения оператора.
