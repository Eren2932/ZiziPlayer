# ZiziPlayer 6.13.0-rc1 (versionCode 28)

## Рассинхрон значка воспроизведения — исправлено

Причина найдена в `SearchScreen.kt`: у играющего трека строка рисовала статичный
`Icons.Rounded.PlayArrow`, а мини-плеер в тот же момент показывал `⏸`. Плеер был в порядке —
врал список.

Введено правило и вынесено в один компонент `NowPlayingBadge` (`ui/components/Common.kt`):

* **строка списка показывает состояние** — полоски эквалайзера, живые пока играет, замершие на паузе;
* **кнопка показывает действие** — `⏸` пока играет, `▶` пока на паузе.

Аудит всех четырёх мест, где рисуется маркер:

| Место | Было | Стало |
|---|---|---|
| Поиск, результаты (`ResultTrackRow`) | статичный `▶` при игре, маркер исчезал на паузе | эквалайзер, виден и на паузе |
| Коллекция / плейлист из поиска | тот же `ResultTrackRow` | то же исправление |
| Медиатека (`LibraryScreen`) | эквалайзер — было верно | без изменений |
| Очередь (`Sheets`) | эквалайзер — было верно | без изменений |

Побочный выигрыш: на паузе маркер больше не пропадает, место в списке не теряется.

## Меню трека (троеточие) — перебрано

* Лист открывается **наполовину** (`skipPartiallyExpanded = false`) и разворачивается полностью
  протяжкой. Частое — сразу, редкое и опасное — после жеста.
* Четыре круглые кнопки быстрых действий: Избранное, В плейлист, Скорость, Поделиться.
  Избранное подсвечивается акцентом.
* Списком остались только Таймер сна и «Убрать из плейлиста», ниже разделителя — удаление.
* **Убраны мелкие пояснительные тексты:** «Файл останется на устройстве…» и строка
  `папка · длительность · прослушан N раз`. Формулировки развели так, чтобы пояснения были не нужны:
  «Убрать из Zizi» против «Удалить файл с устройства».
* `partial` — новый параметр `ZiziSheetScaffold`, по умолчанию `false`: остальные листы
  (настройки, очередь, эффекты) ведут себя как раньше.

## Обмен плейлистами — формат

Добавлен `share/PlaylistShare.kt`: чистая логика формата `.zizi` без UI.

* JSON с полем `v` — версионирование с первого дня;
* транспорт-страховка `ZIZI1:<base64(gzip(json))>` для мессенджеров, которые ломают файлы и MIME;
* лимиты: 300 треков, 256 КБ;
* `matches()` — сверка чужих локальных треков по названию и длительности с допуском ±3 с;
* `decode()` принимает сырой JSON, строку `ZIZI1:`, ссылку `zizi://` и текст, внутри которого
  строка просто лежит; на мусоре возвращает `null`, не бросая исключений.

UI и запись/чтение файла (FileProvider, intent-filter, экран предпросмотра импорта) в этот rc
**не входят** — идут следующей посылкой вместе с сервером 1.4.
