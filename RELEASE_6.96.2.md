# ZiziPlayer 6.96.2 / versionCode 238

Полный архив исходников, не APK. База — 6.96.1. Изменения только на сервере плюс тест и версия клиента (код клиента не менялся).

## Причина «Недоступно (404)» на треке N.O (BTS)

В логе плеера: пять раз подряд `MATCH HTTP=404`. Это ответ сервера `/match/deezer`: ни один кандидат не прошёл судью.
`zizi_match.title_tokens` выбрасывал все однобуквенные латинские токены (нужно для «don't» → don + t).
Название «N.O» даёт токены `n`, `o`, оба выбрасывались, запрос становился пустым, и судья отвергал каждого кандидата
с причиной `request has no title words`. Так же ломались любые названия из одних одиночных букв («A.M.», «R U 8»).

## Что изменено

- `server/zizi_match.py`: одиночные буквы отбрасываются, только если в названии есть слово длиннее. «Don't Stop», «I'm Fine»
  ведут себя как раньше. `RULES` 7 → 8: ключ кэша «miss» зависит от этого номера, поэтому закешированный 404 по N.O
  не живёт ещё неделю, а перестаёт читаться сразу после деплоя.
- `server/tools/server_known.json`: хеш `zizi_match.py` из 6.96.0 добавлен в `match_bases`. Без этого `deploy_server.py`
  отказал бы с «unknown server edit», потому что известной базы у развёрнутого файла не было.
- `server/tools/server_bundle_seal.json`: пересобрана штатным `seal_server_bundle.py`.
- `tools/test_match_letters_6961.py` (в CI): регрессия на N.O, «Don't», настоящие записи принимаются, чужие песни,
  cover/instrumental и неверная длительность по-прежнему отвергаются.

## Деплой (обязателен: без него 404 останется)

На сервере, из папки `server` этого архива:

    /opt/zizi/venv/bin/python tools/deploy_server.py --check
    sudo /opt/zizi/venv/bin/python tools/deploy_server.py --apply

Установщик сам гоняет тесты и откатывается, если `/catalog/health` не подтвердит результат.
Если `--check` напишет `unknown server edit: zizi_match.py (sha256 …)`, на сервере лежит файл, которого нет в известных базах:
пришли этот хеш. Здесь я не видел живой сервер и не мог проверить, какая именно версия там развёрнута.

## Проверено и не проверено

Проверено: на реальном `zizi_match` воспроизведён пустой запрос для «N.O» до правки и принятие правильных записей после;
весь набор `tools/test_*.py` и серверные тесты; печать и деплой-тест.
Не проверено: живой YouTube. Я не знаю, есть ли на нём подходящая запись N.O с нужной длительностью: исправлена причина
отказа судьи, а не гарантия, что трек найдётся. Если после деплоя всё ещё 404, нужен лог сервера по этому треку
(в нём будут причины отказа каждого кандидата).
Клиентский Kotlin по-прежнему не компилировался (в Computer нет Android SDK).
