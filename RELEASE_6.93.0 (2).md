# ZiziPlayer 6.93.0 (231): анимации по референсу

Источник: `Screenrecording_20261016_180249.mp4` (1080x2400, 594 кадра, переменная частота: кадр пишется только при смене картинки).
Время бралось из pts. Кадры сжаты в 4 раза, область страницы = без статус-бара, мини-плеера и панели вкладок.

## Что показал разбор

### Экраны верхнего уровня (12 переходов в записи)
| Этап | Замер |
|---|---|
| Старый экран | пропадает за один кадр (<= 32 мс), без затухания и сдвига |
| Только фон | 99-115 мс (в среднем 110) |
| Новый экран | чистая прозрачность; подгонка масштаба/сдвига: s = 1.00, dy = 0, остаток ~1 ед. яркости |
| Кривая | cubic-bezier(0, 0, 0, 1), 264 мс, rms 0.013 (LinearOutSlowIn 0.024, FastOutSlowIn 0.031) |
| Панель вкладок, мини-плеер | стоят, значок вкладки меняется за кадр |

Почему «плавно при любой скорости загрузки»: пауза ~110 мс скрывает сборку нового экрана, а анимируется только
прозрачность слоя. В референсе на Главной тело ленты иногда появляется чуть позже шапки: это загрузка данных, а не анимация,
поэтому у нас шапка и тело проявляются вместе.

### Нижние окна («Сортировка»: 2 открытия, 2 закрытия)
| Что | Замер |
|---|---|
| Сдвиг | cubic-bezier(0, 0, 0.2, 1), открытие 204/199 мс, закрытие 202/194 мс, rms 1.3-2.0 px (на кадре 270x600) |
| Закрытие | та же кривая, не зеркальная: окно сначала быстро, к низу замедляется |
| Затемнение | чёрный, 0.70 (наклон по пикселям 0.298, сдвиг -0.65), линейно ~105 мс |
| Порядок | при открытии затемнение стартует на ~30 мс раньше окна, при закрытии вместе |
| Путь окна «Сортировка» | 850 px из 2400 (35% экрана) |

Откуда ощущение «медленнее, но так и должно быть»: у референса окно стартует сразу на высокой скорости и долго подползает
(LinearOutSlowIn), а наша пружина начинала с нулевой скорости и тянула хвост до порога 0.5 px. Затемнение у референса уже
полное, когда окно ещё доезжает, у нас оно было привязано к положению.

## Что изменено в коде
- `ui/motion/RefMotion.java`: константы и математика (чистая Java). `ui/motion/PanelMotion.kt`: кривая панелей.
- `ui/components/TabFadeHost.kt` + `MainActivity.kt`: переход вкладок.
- `ui/components/TabBar.kt`: мгновенная смена активной вкладки.
- `ui/screens/ZiziSheetEngine.kt`: `show()` / `hide()` идут по часам (`timed`), затемнение `scrimDriven`; жесты и пружины не тронуты.
- `ui/screens/ZiziSheetHost.kt`: затемнение 0.70 через `state.scrimLevel()`.
- `AccountDrawerHost`, `BookOverlayHost`, `AccountAuthScreen`: общая кривая панелей.

## Не проверено
- Kotlin и Java в Computer не компилировались (нет JDK и Gradle): сборка и `RefMotion6930Test` на CI. Числа в тестах сверены Python-портом алгоритма.
- Живой прогон на телефоне: плавность, нагрузка на первом кадре Главной (тяжёлая лента), поведение при быстрых нажатиях на вкладки.
- **Панель аккаунта (по аватарке), страницы входа/приветствия, `BookOverlayHost`: в записи 180249 их нет, поэтому скорость и кривая не измерены.** Сейчас стоит 200 мс LinearOutSlowIn как гипотеза. Нужен ролик референса: открытие панели по аватарке, закрытие, страница входа вперёд/назад.
- Поиск в медиатеке (экран второго уровня): в записи это жёсткая смена со спиннером при загрузке, без анимации. Не менялось.
- Диалоги `AlertDialog`/`Dialog` живут на платформенной анимации, в записи их нет.
- Одно окно «Сортировка» на 2+2 прогона: кривая подогнана, но не проверена на высоком окне (Expanded).
